## 0. 协议文档长度（纠正 rev 1.2 §0.2）

rev 1.2 把每篇触发次数写成 136/8/8/136/2。那个数字来自 Stage A 的合成探针（`L=69`），不是协议文档。

协议文档构造不变：`FILLER_TOK=30` + `CUE_A` + 1 个码 token。
训练机离线 tokenizer（`Qwen/Qwen2.5-0.5B-Instruct`）实测 `CUE_A = " The vault code is"` 为 4 个 token：`[576, 34584, 2038, 374]`。
因此每篇长度 **L = 35**。stride=1 的触发位置是 `t = 1..34`。`write_both` 对目标文档和干扰文档各做一次前视。

| 臂 | stride | 单次前视触发 | 每篇 m |
|---|---|---|---|
| `G_tok` | 1 | 34 | **68** |
| `G_seg4` | 17 | 2（`t=17,34`） | **4** |
| `G_seg4_alt` | 18 | 2（`t=18,34`） | **4** |
| `G_tok_rate` | 1，η=η/17 | 34 | **68** |
| `G_doc` | 68 | 1（只写 `t=34`） | **2** |

smoke#2/#3/#4 的增量读数与上表一致：`n_entries = 34/2/2/34/1`，`n_steps_doc = 68/4/4/68/2`。
`m(G_tok) / m(G_seg4) = 17`，所以 rev 1.2 的 `η/17` 对照仍然成立，**臂表不改**。

由此改正两条注释性预测，**不改正阈值**：

- 容量峰值的解析对照改为 `K* ≈ 256/m`：约 4 / 64 / 64 / 4 / 128 篇。`G_doc / G_tok ≈ 34×`。H21-1b 的阈值仍是 **≥ 8×**。
- 每篇累积 `(ηλ)·m`：`G_tok = 0.34`；`G_seg4 = 0.02`；`G_tok_rate = 0.02`。H21-4 的曲线阈值仍是 mean ≤ 0.05 且 max ≤ 0.10。

Stage A 的 A21-2 继续用 `L=69` 探针，期望写步 136/8/2。那是装置调度检查，不是上表的协议 `m`。

## 1. 实现缺陷（不改判据）

- **D97**：判据汇总块放在 `mean_curve` / `_m_of` 定义之前。smoke#2/#3/#4 的主循环已完成，收尾抛 `UnboundLocalError`。失败日志保留。修法：删除该提前汇总；汇总只留在辅助函数定义之后。
- **D98**：派生脚本的运行期标识仍写 DIR-20（`res["dir"]` 与启动横幅）。结果 JSON 会被标错方向。修法：运行期标识改为 DIR-21。历史派生说明留在文件头，不删。
- 报告项 Rp-1 的实现曾查询 2048/4096，这两个步点不在冻结的 `STEP_GRID` 里，会打出 NaN。改为只报告 `STEP_GRID` 中实际存在的步点。这不是判据文字修改。

正式轮增量命名空间改为 `DIR21r13`，与 r12 的 smoke 增量隔离。r12 smoke 增量保留，只作为协议可执行性记录。
