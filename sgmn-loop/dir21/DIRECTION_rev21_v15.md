# DIR-21 · rev 1.5（冻结：两处实现口径回正）

rev 1.0–1.4 留档不改。**H21-1 / H21-1b / H21-2 / H21-3 / H21-4 的阈值与判据文字不改**，仍以 rev 1.1 §3 为准。

## 0. 前置事实

smoke5（`DIR21r13`）证明脚本能跑完判据并写出有限数。它同时暴露两处**实现口径**问题：
这两处若不修，正式轮会产出一个**结构上不可能被计算**的判据（H21-1）。
按纪律，「判据从未被计算」与「判据算出 FAIL」必须区分 ⇒ ⇒ 两处都在正式轮开跑前修。

## 1. D101：码必须真正全局唯一

`build_docs` 收集了 `used` 却**从不检查**。只有 `code_id == dcode_id` 一道判断。
⇒ ⇒ docstring 与 A2'⑦ 声称的「码全局唯一 ⇒ 训练码与评测码零重叠」在正式规模上**不成立**：
720 篇 × 2 个码 = 1440 次抽取，码池 4000 ⇒ 碰撞概率 ≈ 30%。
⇒ ⇒ 后果：同一个答案词进两次记忆 ⇒ 命中口径被污染 ⇒ 恰好污染本方向要测的粒度效应。
A2'⑦ 用 4+6 篇抽样，挡不住这个规模（10 篇的碰撞概率约 2.5%）。

修法：抽码时判 `code_id in used or dcode_id in used` 则重抽；结尾断言 `len(used) == 2 * need`。
码池 4000 对 1440 的需求绰绰有余，重抽次数在 `guard = 80 * need` 内。

## 2. D102：H21-1 的 NLL 口径回正到 rev 1.1 §2.2 定义的曲线

rev 1.1 §2.2 定义 `R_nll(K)` = **文档 1 已写入条目的平均 NLL**；§2.3 的配对统计也是对这个 nll 而言。
rev 1.2 §0.3 把 H21-1 收窄到「目标条目单条 NLL」，理由是「粗粒度下目标可能没写进去」。
⇒ ⇒ **rev 1.2 同时引入了「目标位置 L−1 必写」**，该前提使 §0.3 的理由失效。

而且 `nll_tgt` **结构上无法区分粒度**：写侧存的签名是 `h_{t-1}`，读侧查询是同一前缀末位的隐状态，
cause 注意力下二者逐位相同 ⇒ 余弦 = 1 ⇒ 目标条目在**每个臂**都被精确寻址 ⇒ 每个臂都能答出 ⇒ 差 ≈ 0。
smoke5 实测 `|Δ| = 0.0048` nats，正是这个结构的体现，**不是**「粒度不重要」的证据。

修法：H21-1 用 rev 1.1 §2.2 的 `R_nll`（该臂写下的条目的平均 NLL）⇒ 判据与卡片冻结定义一致。
`nll_tgt` 变体**预登记**为并列读法（Rp-5），不参与 PASS/FAIL。

### 2.1 预登记的并列读法处理规则（写在开跑前）

- 判据 PASS/FAIL **只**按 `R_nll`（rev 1.1 §2.2）。
- Rp-5 报告 `nll_tgt` 的 Δ、p、逐种子符号。
- 若两个读法结论**一致** ⇒ 结论稳健。
- 若**不一致** ⇒ 按 `R_nll` 裁决，且必须在裁决里写明 Rp-5 的读数与其结构性限制
  （「目标条目恒可寻址 ⇒ 该读数对粒度不敏感」）。

### 2.2 证据边界（追加）

`R_nll` 是**该臂自己写下的条目**的平均。两个臂的条目集合不同（`G_tok` 34 条 vs `G_seg4` 2 条），
⇒ ⇒ 臂间均值差同时包含「条目集合构成（短前缀更难）」效应。
⇒ ⇒ H21-1 的 PASS 只能读作：**采用某一粒度会改变任务层的表现，两种粒度不可互换**；
**不能**读作「写入调度本身改变了同一任务的表现」。
