## 修订 51（★ 指标口径缺陷 · **D46**）：`addr` 把「核槽位号」与「写入顺序号」混为一谈

- **症状**：smoke#5 的 H5 FAIL —— Hebbian 臂的 `addr` 恒为 **0.0000**（所有臂、所有种子）。
- **根因（probe18c 实测）**：`addr` 的实现是 `int(last_cue_idx) == int(d["true_idx"])`，
  其中 `last_cue_idx` 是**核槽位下标**（`core.count % N` 的落位），而 `true_idx` 是**写入顺序号**
  （第几篇写进去的条目）。两者在「核里已有其它条目」时**必然不等**。
  probe18c 实测：`hebb_eta7_cue_train` 的 addr（写入序）= 0.0000，但 addr（**槽空间**）= **0.6667**；
  `verbatim_cue_train` 的 addr（槽空间）= **1.0000**。
  ⇒ ⇒ **地址机制本身是好的**（`verbatim` 臂槽空间命中 1.0），失败的是**指标**。
- **处置**：**新增第三个地址口径** `addr_slot` —— 「签名匹配选中的槽 == **真值条目实际所在槽**」。
  真值槽**由值内容反查**（`core.vals` 中与本次写入的 `V[true_idx]` 余弦最大者）⇒ 与槽位空间自洽。
  ⇒ ⇒ **H5 改用 `addr_slot`**，阈值不变（≥ 0.95）；`addr`（写入序口径）**保留并双口径报告**（纪律 ⑲）。

## 修订 52（★ 协议缺陷 · **D48**）：评测期**核污染**（陈旧条目 + 槽位回绕）

- **症状（probe18c Q2 实测）**：训练臂在评测时 `n_searched=128`、`n_stale=60`；未训练臂 `n_searched=68`、`n_stale=0`。
- **根因**：`eval_arm` 的 `snap0` 取自**训练之后**（`core.count=68`）⇒ 每篇评测再写 68 条 ⇒
  `count=136 > N_ENTRIES=128` ⇒ **槽位回绕**（真值条目落在槽 101，而非 33），
  且**残留 60 条训练期陈旧签名**参与地址匹配。未训练臂 `count=0` ⇒ 无回绕 ⇒ `addr=1.0`
  （这正是 smoke#5 中「W0 addr=0 / E4 addr=1」矛盾的来源）。
- **处置（协议修订）**：**每篇评测前清空槽表（`keys/vals/sigs` 归零、`count=0`），但保留 `W`**
  ⇒ ⇒ 消除陈旧条目与回绕，使**槽位空间与写入顺序空间一致**（真值槽 = `true_idx`），
  并让 `addr`（写入序）与 `addr_slot`（槽空间）**两口径必然相等**（⇒ 这本身是一条 Stage A 断言）。
  ⇒ ⇒ **与 DIR-17 的数值跨轮比较必须注明口径变化**（DIR-17 保留了污染协议，其 `hit` 指标受此影响，见修订 56）。

## 修订 53（★ 协议缺陷 · **D47**）：`W4_hebb_full_trainPv` 的 $P_v$ **梯度恒为 None** ⇒ H4 不可判定

- **症状（probe18c Q3 实测）**：`train_arm(..., train_pv=True)` 后，三层 `m.Pv.grad` **全为 None**
  ⇒ ⇒ `W4` 与主臂**逐位相同**（smoke#5 实测两者 NLL 均 = 11.1565，逐位一致）。
- **根因**：写阶段在 `with torch.no_grad():` 内，且 `v = sg(hs_in[0,t] @ self.Pv)` 中的 `sg()` **已 detach**
  ⇒ ⇒ `P_v` **从未参与反向传播** ⇒ ⇒ **在 Freeze C 下「任务损失更新 `P_v`」不可实现**。
- **处置（判据 H4 的实现性更正）**：
  H4 原命题「可训 $P_v$ 把 `W1` 的收益拉起来」**在 Freeze C 下不可判定** ⇒
  **H4 改写为可判定的形式**：新增 **`W4` 的替代臂 `W4b`**（把「值映射可训」改成**写侧自监督**：
  在写阶段对 $P_v$ 施加**独立的保真度损失** $\mathcal{L}_{\text{write}}=-\cos(Wk_j,v_j)$，
  该损失**只更新 $P_v$、不进入任务损失、也不更新 $W$** ⇒ 这才是 v2.4 §7.2「受保护的联合训练」
  在 Freeze C 下的**正确实现形态**）。若 `W4b` 仍与主臂逐位相同 ⇒ **H4 判定为「不可实现」而非「FAIL」**。
  ⇒ ⇒ **`W4` 原臂保留在臂表中留档**（它是一个已定位的缺陷样本，不是判据臂）。

## 修订 54（★ 装置缺陷 · **D50**）：$\eta$ 的「稳定窗口」与「学习窗口」**不相交**

- **probe18b 实测（单篇 34 次写）**：
  | 量 | 实测 |
  |---|---|
  | $\lVert k\rVert$ | mean **131.4** / max **3451**（**离散度 26×**） |
  | $\lVert v\rVert$ | mean 13.65 |
  | $\lVert Wk-v\rVert$ | mean 296.7 / max 3262 |
  | $\lVert G\rVert$ | mean **3.374e+05** / max **1.126e+07**（首步 1.13e+07） |
  | 稳定上界 $\eta<2/(\lambda+\alpha\lVert k\rVert^2)$ | **1.158e-04**（按均值）/ **1.7e-07**（按最大键范数） |
  | 一步搬动比例 $\eta^\*$ | **2.279e-03** |
- **根因**：§3.1 的数据项范数 $\sim\lVert Wk-v\rVert\lVert k\rVert$，而**键范数离散 26×**
  ⇒ ⇒ **按最大键范数，单点稳定需 $\eta\lesssim1.7\times10^{-7}$；而有效学习需 $\eta\sim10^{-3}$**
  ⇒ ⇒ **两个窗口不相交** ⇒ 「全局 $\eta$」这件事本身在位置级写语义下**无解**。
- **处置（新增臂 + 新判据）**：
  1. **新增臂 `W6_hebb_full_ortho_eta2`**：正交键（$\lVert k\rVert^2\approx5$，**天然均匀** ⇒ 消除 26× 离散）
     + $\eta=10^{-2}$（落在正交键的稳定窗口内）。这是**唯一**能让「稳定窗口 ∩ 学习窗口」非空的配置。
  2. **新增判据 H8（★ 写规则可行性的充分条件）**：`W6` 的写保真度 `fid` 显著大于 0 且**任务收益**显著大于 0
     ⇒ ⇒ PASS = 「v2.4 的写规则**本身**可用，前提是键几何均匀（$P_k$ 的线性键在真实 hidden state 上范数离散 26× 是**装置/协议层**问题，
     不是写规则的问题）」⇒ ⇒ 一条对 Freeze B 的具体条款：**写入键必须做范数归一**。
  3. 主臂 `W3_hebb_full_eta7`（$\eta=10^{-7}$）**保留不变**（修订 55 的「禁止事后挑 η」纪律不变），
     它的角色改为「**线性键 + 保守 $\eta$**」的实测点。

## 修订 56（★ 收益归因的判据化 · **H10/H11/H12**）：smoke#5 的「+2.97 nats」**不是**写规则的功劳

- **probe18c Q4 + probe18d/e 的实测**（同装置、同任务、同一批评测文档）：

  | 臂 | NLL(真码) | NLL(干扰码) | 含义 |
  |---|---|---|---|
  | 主臂 `hebb η=1e-7`（训练） | **11.0017** | 11.6991 | — |
  | **`nowrite`（地址表照写，`W` 从不更新）** | **11.0239** | 11.7477 | **地址正确、内容无关联** |
  | `shuffle`（键值错配） | 11.0951 | — | 内容关联被打乱 |
  | `misaddr`（读邻位键） | 12.3837 | — | 地址也错 |
  | `verbatim`（逐字上界） | **10.4638** | 12.2733 | 上界 |
  | `base` | 14.1687 | 15.6866 | 基座 |

  ⇒ ⇒ **`nowrite` 与主臂逐位同分（差 0.022 nats）** ⇒ **Hebbian 写步对任务收益的贡献 ≈ 0**
  ⇒ ⇒ 主臂相对 base 的 **+3.17 nats** **几乎全部**可由「**完全不更新 `W`**」复现
  ⇒ ⇒ **收益来自「地址机制 + 可训读接口」，不来自写规则**（与 DIR-10 同型结论）。
- **机制侧佐证**：主臂 `cos(y_read, v_true) ≈ 0.0015`、`fid(真值槽) ≈ −0.005`
  ⇒ ⇒ **读出的 `y` 不含目标值** ⇒ ⇒ 写 → 读链在**写侧保真度**处断裂。
- **处置（把归因写进判据）**：smoke#5 的 H2「`W1` 相对 base 有显著收益」**在形式上会 PASS**，
  但**该 PASS 不可解释为「写规则有效」** ⇒ ⇒ **H2 改写**为下表形式（并新增 H10/H11/H12）：

| 判据 | 命题 | 通过条件 |
|---|---|---|
| **H2′**（替代 H2） | **写规则的任务贡献**：主臂相对 `nowrite` 对照有显著收益 | 配对差 > 0.5 nats 且 p < 0.05 且三种子同向 |
| **H10**（新增） | **内容关联存在**：主臂的 `cos(y_read, v_true)` 显著大于 0 | 均值 > 0.05 且配对 t 检验 p < 0.05 |
| **H11**（新增） | **写保真度**：主臂真值槽的 `fid` 显著大于 0（写**有做功**） | 均值 > 0.05 且 p < 0.05 |
| **H12**（新增） | **地址 ≠ 写规则**：主臂 `addr_slot` ≥ 0.95（即使 `H10/H11` FAIL） | ≥ 0.95 |

⇒ ⇒ **H2′ FAIL + H10 FAIL + H11 FAIL ⇒ 结论 = 「v2.4 的实际写规则在本协议下不可用，
其收益与写规则无关」**，且**归因必须写明**「收益来自地址机制 + 可训读接口」。
⇒ ⇒ **H12 独立 PASS ⇒ 地址机制与写规则正交**（这与 DIR-15/16/17 一致）⇒ ⇒ 一条正面结论。

## 修订 58（★ 新增臂 `W8` 与判据 **H13**）：**交换性对照** —— 排除「稀有词先验」这一替代解释

- **动机（probe18d 的教训）**：probe18d 首次用「未写入的稀有词」作对照，得到「内容余量 +1.49 nats」，
  但**那两个对照 token 是池中频次最低者，在 base 上 NLL 比真码更低** ⇒ **与码不可交换** ⇒
  该「内容余量」**不能**直接解释为内容被读出（probe18e 用**同池同分布、均匀抽样的 K=32** 个对照重测）。
- **臂 `W8_hebb_full_ctrl32`**：与主臂同构，唯一差别 = **评测时额外测一批「同池、均匀抽样、
  从未写入」的对照 token 的 NLL**（K=32，对照集**跨臂配对固定**）。
- **H13（★ 收益的内容性）**：主臂的 `Δcode` 显著大于其 `Δctrl`（配对）
  ⇒ ⇒ **收益超出「稀有词先验」** ⇒ ⇒ 内容确实被读出；
  ⇒ ⇒ FAIL ⇒ **收益 = 稀有词先验**（模型只学到「这里该输出一个稀有词」）⇒ ⇒ **主假说不成立**。
- **口径纪律（纪律 ⑳ 的延伸）**：判据量必须**双口径报告**：`Δcode`（真码）与 `Δctrl`（交换性对照）
  **都要报**，且「内容贡献」= 两者之差；**只报 `Δcode` 一律不构成「内容被读出」的证据**。
