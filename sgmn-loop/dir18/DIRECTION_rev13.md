### 0.2 真正的根因：**键尺度标定口径错**（D51）

装置的 `pk_scale` 是**用随机 N(0,1) 向量**标定的（`sgmn_module_hebb.py` 中 `x = torch.randn(20000, d_model)`，
目标是 `E‖k‖² = 5`）。**但真实 hidden state 的范数远大于随机向量**：

| 量 | 装置标定值（随机向量） | 实测值（真实 hidden state） |
|---|---|---|
| $E\|k\|^2$ | 5 | **1.7e4**（mean） |
| $\max\|k\|^2$ | 5 | **1.19e7**（max） |
| 键范数离散度 | — | **26×**（mean 131 / max 3451） |

⇒ ⇒ **超标约 60×** ⇒ ⇒ 由解析式
$$\eta < \frac{2}{\lambda + \alpha\|k\|^2}$$
（稳定上界）与 $\eta^\ast \approx 1/(\alpha\|k\|^2)$（一步收敛）**同时**成立所需的窗口
⇒ ⇒ 在**装置原标定下不相交**（稳定需 $\eta \lesssim 1.7\times10^{-7}$，学习需 $\eta\approx10^{-4}\!-\!10^{-3}$）
⇒ ⇒ ⇒ **此前观察到的「写规则不可用」是「键尺度口径缺陷」与「η 网格过小」共同造成的假象。**

### 0.3 修正手段（**不是**改写规则，而是**改键的尺度**）

| 手段 | 定义 | 效果 |
|---|---|---|
| **`renorm`** | 线性键 $k = P_k h$ 保持**方向**不变，逐写归一化到 $\|k\|^2 = 5$ | 保留 v2.4 的键语义（投影自 hidden state），只修尺度 ⇒ ⇒ **最小改动** |
| **`ortho`** | 键取自每层一份 $896\times896$ 的**随机正交基**，按写入序号取列，标定 $\|k\|^2=5$ | 键**完全去相关** ⇒ ⇒ 隔离 DIR-13 已知障碍「键共线（cos 0.987–0.995）」 |

⇒ ⇒ 两者都让 **$\|k\|^2$ 恒为 5** ⇒ ⇒ 解析窗口重新相交：
$\eta < 2/(\lambda+5)\approx0.396$（稳定）且 $\eta^\ast\approx1/5=0.2$（一步收敛）
⇒ ⇒ **η 由解析式导出，不是事后挑**（纪律：禁止事后挑 η）。

### 0.6.1 ⇒ 三条结论

1. **★ D48（「评测期清空槽表」）是错的，必须回退。**
   清空槽表把寻址命中率从 **0.8833 打到 0.3722**（n_train=200, n_eval=60）⇒ **反而破坏寻址**。

   它们与**训练后**的模型（$W_o,\gamma$ 已更新）对齐（与 DIR-17 的 **D-24** 同源：
   §6.1 的读写前向耦合使**训练前**记下的签名与**训练后**的前缀表示错位）。
   ⇒ ⇒ **陈旧残留与槽位回绕不是寻址的敌人，反而是「寻址能工作」的条件**。
   ⇒ ⇒ ⇒ **「干净」的评测协议在有训练的臂上是不合法的** ⇒ ⇒ D48 **失败留档**（不追认）。

2. **★ DIR-17 的 0.8722 被逐位复现**（`dirty17` @ n_train=200, n_eval=60 ⇒ **0.8833**）
   ⇒ ⇒ **DIR-18 沿用 DIR-17 原协议** ⇒ ⇒ 跨轮数字**可比**（纪律 ⑲/⑳ 的口径要求得到满足）。

3. **★ D46 的「写入序」口径在 DIR-17 协议下必然 ≈ 0**（实测 **0.0000**）：
   回绕使真值槽 = `(写入前 count + true_idx) % N` ≠ `true_idx`
   ⇒ ⇒ 这是**协议的正确读数**，不是指标缺陷 ⇒ ⇒
   **判据一律改用「槽空间」口径**，且槽号必须**精确映射**（见下）。

### 0.6.3 ★ 由此新增的纪律 ㉚

**协议修订（尤其「把状态清干净」类修订）不得只看「指标是否更干净」，必须先验证「机制是否仍能工作」。**
- 典型症状：某个「清理」步骤（清空缓存 / 清空表 / 归零状态）让**指标口径**变好看（两口径相等、无残留），
  却让**机制本身**退化（寻址命中率腰斩）。
- ⇒ ⇒ 任何协议修订必须**同时**报告「口径指标」与「机制量」（本轮：`addr` 两口径 + `hit`/`addr_slot`），
  并**对照修订前后的机制量**。
- ⇒ ⇒ 「更干净」**不是**「更正确」；**口径一致性与机制可工作性是两个独立的验收维度**。
- ⇒ ⇒ 探针应做**逐变量分离**（同一核状态上只改一个变量），否则结论会被混淆变量污染。
- （来源：DIR-18 D55 / probe18h）

### 1.2 ★ 读取路径（沿用 rev 1.0，不变）

1. 用**上下文签名** $h_{t-1}$（DIR-15/16 的内容寻址）匹配出条目槽 $j$；
2. 取该槽的**键** $k_j$ 作查询 $q = k_j$；
3. 读出 $y = \mathrm{sg}(W)\,q$（§2.2 线性读，作用在 Hebbian 核上）。

⇒ ⇒ **机制量**：写保真度 $\cos(Wk_j, v_j)$（`fid`）与 **读出-真值余弦** $\cos(y_{\text{read}}, v_{\text{true}})$（`cos_y_vtrue`）。

| **H3** | **★ 写规则是瓶颈**：`W0_verbatim` 显著优于主臂 | 配对差 > **+1.0** nats 且 p < 0.05 且三种子同向 |
| **H4′** | **★ 值映射是瓶颈**：`pvw`（写侧自监督）显著优于主臂 | 配对差 > **+0.5** nats 且 p < 0.05 且三种子同向 |

| **H8** | **★ 键尺度归一 ⇒ 写规则有内容收益**：`W6b`（renorm，η=1e-1）的 `fid_true` > 0.05 **且** 相对 base 收益 > 0.5 nats | 二者同时成立 |
| **H8b** | **★ 正交键 ⇒ 写规则有内容收益**：`W5b`（ortho，η=1e-1）的 `fid_true` > 0.05 **且** 相对 base 收益 > 0.5 nats | 二者同时成立 |
| **H8c** | **★ 归一化优于装置原尺度**：`W6b`（renorm）显著优于 `W3`（linear，η=1e-7） | 配对差 > 0 且 p < 0.05 且三种子同向 |
| **H9** | **★ 跨方向复核 D-24**：主臂的地址准确率 < γ 锁定臂（训练 γ 破坏寻址） | 主臂 < γ 锁定臂 |
| **H10** | **★ 内容关联存在**：主臂 $\cos(y_{\text{read}}, v_{\text{true}})$ 显著 > 0 | 均值 > 0.05 且 p < 0.05 |
| **H11** | **写保真度（真值槽）**（同 H6 的复述，保留编号以对齐卡片） | 均值 > 0.05 且 p < 0.05 |
| **H12** | **地址独立于写规则**：即使 H10/H11 FAIL，主臂 `addr_slot` 仍 ≥ 0.95 | ≥ 0.95 |
| **H13** | **★ 收益的内容性**：主臂的 $\Delta_{\text{code}}$ 显著大于 $\Delta_{\text{ctrl}}$（**交换性对照**） | 超额 > **+0.5** nats 且 p < 0.05 |
| **H13b** | **★ 归一化写规则的内容性**：`W6b`（renorm）的超额 > 0.5 nats | 超额 > 0.5 且 p < 0.05 |
| **H13c** | **★ 正交键写规则的内容性**：`W5b`（ortho）的超额 > 0.5 nats | 超额 > 0.5 且 p < 0.05 |

> **H13 的定义**（逐文档配对，★ 探针 probe18e 的直接教训）：
> $$\Delta_{\text{code}} = \mathrm{NLL}_{\text{base}}(\text{code}) - \mathrm{NLL}_{\text{arm}}(\text{code}),\qquad
> \Delta_{\text{ctrl}} = \mathrm{NLL}_{\text{base}}(\text{ctrl}) - \mathrm{NLL}_{\text{arm}}(\text{ctrl})$$
> $$\text{超额} = \Delta_{\text{code}} - \Delta_{\text{ctrl}}$$
> ⇒ **正** = 该臂比「稀有词先验」**额外地**更懂真码。
> **对照 token 必须**：同 `code_pool`、**均匀抽样**（码本身是 `rng.choice(code_pool)`）、**从未写入**、**跨臂固定**。
> ⚠️ **不得**取池中最稀有者（probe18d 的教训：那样在 base 上 NLL 更低 ⇒ **不可交换** ⇒ 把 base 先验差异误读成内容）。

### 2.3 证伪条件（预注册）

- **H8 FAIL**（`renorm` 的 `fid_true` ≤ 0.05 或任务收益 ≤ 0.5 nats）⇒
  ⇒ **键尺度归一不足以让写规则在任务层可用** ⇒ ⇒ 瓶颈在写规则本身（与键几何无关）⇒ ⇒ §3.1/§3.2 须改写。
- **H8 PASS 且 H13 FAIL** ⇒ **写保真度存在，但任务收益不是内容驱动的**（稀有词先验）⇒ ⇒
  ⇒ 「写 → 读出」链在**读出映射**处断裂（记忆内容没有变成输出）⇒ ⇒ 与 DIR-16 的 H7 FAIL 同型。
- **H13 PASS** ⇒ ⇒ ★ **v2.4 的写规则 + 键尺度归一 ⇒ 首次在任务层产出「内容驱动的」收益** ⇒ ⇒ 计入 SUCCEEDED。

- `fid` 与 `fid_true`（选中槽 / 真值槽）**两口径同时报告**。
