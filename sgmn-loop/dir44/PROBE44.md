## §3 run-3（`probe44c.py`，种子 `23300+`，n=12）—— **干预试探（失败，留档）**

- 干预：把 `O_1` 的 **`c` 通道**冻结为 0 ⇒ 期望降损只能走寻址 ⇒ `ρ>0`。
- 读数：`base` vs `cfrozen` 的 `ρ(K=60)` 是 **−0.009 vs −0.167** ⇒ **更负** ⇒ **无效**。
- 副产物：`direct` 臂 `cos_end ≥ 0.999`（判据**非空**、可达）。

★★ **为什么无效**（run-3 + run-1 + run-2 合并）：
**`c` 通道只是** `O_1` **的旁路**；真正的**根源**是 **`c` 能直接推出任务的目标值** —— 即使 `c` 不进 `O_1`，
**目标值仍是 `c` 的函数** ⇒ 读头**仍**能从**读结果** `y`（`y = W·q`）**反推出** `c` 的信息 ⇒ **旁路依旧**。
⇒ ⇒ **冻结 `O_1` 的 `c` 通道、或「可分性更强的基座」，都改变不了这一根本事实**。

## §4 run-4（`probe44d.py`，种子 `23400+`，n=12）—— **真正的修复（值来源解耦）**

★★ **修复假设 H44**：**把『值』的来源与** `c` **解耦**。
装置里**任务的目标值**是 `gs[t-1] = tanh(c(t-1)·Pv1)` ⇒ **目标值是** `c` **的确定性函数** ⇒
读头**只需**逼近目标值（**不必寻址**）⇒ ⇒ `ρ≈0`。
⇒ ⇒ **修复**：让**值**来自**`c` 无法推出的外部码本**（按**奇偶**索引）⇒ 读头**必须**用 `y=Wq` 取回**正确的值** ⇒ ⇒ 降损**只能**靠寻址 ⇒ ⇒ `ρ` 应当显著 > 0。

| 量 | **device**（值=装置 `h_pre`） | **codebook**（值=离线码本） |
|---|---|---|
| `ρ(初值)` | +0.065 | +0.093 |
| `ρ(K=60)` | +0.047 | **+0.367** |
| `ρ(250)` | **−0.272** | **+0.293** |
| `ρ(250)` 的 sd | 0.406 | 0.479 |
| `L(初值)` | 33.16 | 33.73 |
| `L(250)` | **0.058** | **13.76** |

★ **读数成立**：
- `device`：`ρ` 随训练**负向漂移**（−0.27）。
- `codebook`：`ρ` **正向**、稳定（+0.29…+0.37），sd 0.48–0.53。
- `direct` 臂 `cos_end ≥ 0.992`（判据**非空**）。
- ★ 副产物：**码本臂下** `L` **训不下来**（13.76 vs device 0.058）⇒ **头部找不到 → 需要寻址**。

## §5 ⇒ 对下一张卡（DIR-44）的**约束**（★ 这些不是判据，只是**开卡前必须先算**的依据）

1. **干预 = 值来源解耦**（把『值』换成 `c` 无法推出的码本）。**不是**「可分性更强的基座」，
   **不是**「冻结 `O_1` 的 `c` 通道」（run-3 已判**无效**）。
2. **ρ 的 sd ≈ 0.5**（codebook 臂、n=12）⇒ `se = 0.5/√400 = 0.025` ⇒ **n=400 时 `3se ≈ 0.075`**；
   探针的 `mean(ρ)` ≈ +0.3 ⇒ **远超** `3se` ⇒ **功效足够**（**无需加大 n**）。
3. **判据非空**：`direct` 臂 `cos ≥ 0.99` ⇒ 装置的**对齐目标**本身可达。
4. **风险**：码本臂下 `L` 训不下来 ⇒ 若正式轮**只用** `learned` 臂降损，**可能**只能证明「任务梯度
   指向寻址」而**不能**证明「读控制器能学成」⇒ **设计时必须**两者都要。

# ★★ §4-CORR（**append-only 更正**：§4 的「修复成功」是**错的**，读数留档但不据此开卡）

`§4` 的 `ρ(250)=+0.293`（codebook 臂）**不能**作为开卡依据。本轮**实测/读码**确认两处构造缺陷：

## 缺陷 **DEF-44-1**（**已实测**：`dir44/check_defect44.py`）

`T42.train_reader42` 内部调用 `trace42`（`dir42`），**不读** `probe44.V_MODE`
⇒ ⇒ 两臂**训后参数逐位相同**：`g1/Wo1/bo1/Wq1/bq1` 的 `max|Δ| = 0.000e+00`。
⇒ ⇒ `§4` 的 `codebook` 臂实际是「**device 损失训出来的控制器、在码本损失下测 ρ**」⇒ **混了两个协议**。
**订正**：任何码本臂的训练**必须**用码本损失（`trace44` + `train_reader44`），**不得**复用 `train_reader42`。

## 缺陷 **DEF-44-2**（**读码即可确认**）

装置目标是 `gs[t-1] = tanh(hs[t-1]·Pv1)` ⇒ 它**恒等于**该步写入的值
⇒ ⇒ **把『值』换成码本** ⇒ 记忆里存的**不再是目标** ⇒ 记忆**变得无用**（不是变得必要）
⇒ `§4` 的 `L(250)=13.76`（vs device `0.058`）正是这个 ⇒ ⇒ 「降损只能靠寻址」**不成立**。

## 缺陷 **DEF-44-3**（`probe44f` 的测量层）

`g_addr_of` 里 `which` 只影响被丢弃的 `cur/prev` 字典，实际目标仍用 `cc` 算 ⇒ `ρ_prev ≡ ρ_cur`
（四个格**逐位相同**）⇒ ⇒ **§9 的 `ρ_prev` 读数无效**，只有 `ρ_cur` 一列可信。

## §11 结论：**DIR-44 的候选干预在开卡前被否决**（`WITHDRAWN-BEFORE-CARD`）

1. **候选干预「值来源解耦」被否**：`DEF-44-2`（目标仍等于装置值）⇒ 记忆变**无用**；`DEF-44-1`（训练未用干预）⇒ 探针读数**混协议**。
2. **两个替代装置 revision 都被测过且都不产生显著 `ρ`**：内容持续度（§8）、查询坐标对齐（§9）。
3. ⇒ ⇒ **不开 DIR-44 的卡**（冻结一张已知有构造缺陷的卡是违纪的）⇒ 记 **`WITHDRAWN-BEFORE-CARD`**：
   ★ **不计入** `SUCCEEDED`（仍 **32/32**）、**不产生**证据行、**不产生** VERDICT。
4. ★ **下一方向的依据（本轮拿到的新事实，不是猜测）**：`‖g_task‖` 崩塌 261–1433 倍 ⇒
   主判据在 `STEPS=250` 取的是空梯度 ⇒ ⇒ 真正该问的是「**在梯度仍然非零的阶段**，方向是否指向寻址？」
   ⇒ 这直接对应框架 §7.2「集成接口验收」的「**读取参数的非零有限梯度**」⇒ ⇒ 下一方向 = **梯度仍非零时的方向性**。
