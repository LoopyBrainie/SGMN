## §1 rev 1.0 → rev 1.1 的更正（★ 3 条缺陷，**全部由自测在跑正式轮之前抓到**）

### `DEF-118-20` —— rev 1.0 §4 的手算 `E_random` **算错了**

rev 1.0 写：「`E_random = (2²+1²+2²)/3 = 9/3 = 3.0`」。**错。**

`Σ_v m_v²` 是**按不同值**求和，而那个 toy 的值是 `v0, v1, v0`
⇒ **值重数只有 `m_{v0}=2`、`m_{v1}=1`**
⇒ `Σm² = 2² + 1² = `**`5`**，`E_random = 5/3 ≈ `**`1.6667`**（不是 3.0）。

我把**每项的 `|S_i|`**（2,1,2）当成了**每值的重数**（2,1）来求和 —— 前者多算了一遍重复值。
★ 两条自洽核对（都写进了自测，均 PASS）：
- 恒等式 **`Σ_i |S_i| = Σ_v m_v·m_v = Σ_v m_v²`** ⇒ `2+1+2 = 5 = 4+1` ✓
- **判据本身没错、装置也没错**：真装置 16 值 × 2、`N=32` ⇒ `Σm² = 16×4 = 64` ⇒ `E_random = 64/32 = `**`2.0`** ✓
  ⇒ 本错误**只污染 rev 1.0 §4 的举例**，**未**影响任何判据、且真装置读数 `2.0` 与 rev 1.0 一致。

### `DEF-118-21` —— rev 1.0 §4 的 toy **维度选错**：`d_k < n` 时 oracle **原理上**不精确

rev 1.0 的 toy 取 `K` 为 `3×2`（`d_k=2`）、`n=3`。实测 `oracle` 残差 = **`0.3125`**（远大于 `G5-3` 的 `1e-6`），
而这不是数值噪声：`W_or K^T = V^T` 要求 `V^T·pinv(K^T)·K^T = V^T`，
后者只在 **`K^T` 列满秩**（即 **`d_k ≥ n`**）时成立；`d_k < n` 时 `pinv(K^T)K^T` 是**投影而非恒等**。

⇒ ★★ **由此得到一条对 `G5-3` 的正确理解**：它**不只是**数值容差检查，
　 **同时是一条结构前提检查 —— 装置必须处于 `d_k ≥ n` 的过定区**。
　 真装置 `d_k = 896 ≥ 32` ✓（实测残差 `3.9e-07 ~ 5.7e-07`）。
　 rev 1.1 的 toy 改取 **`d_k = n = 3`**，并把「`d_k < n` ⇒ 残差必然大」写进自测第 ⑩ 条**反向验证**。

### `DEF-118-22` —— 自测把 toy 张量放在 CPU，而 `n_hit` 内部硬编码 `device=DEV`(cuda)

首跑 5 条报 `RuntimeError: Expected all tensors to be on the same device`。
★ **为什么危险**：**崩溃与断言失败同样退出码 1** —— 若不分开看 `[FAIL]` 行数，
　 很容易把「5 条崩溃」误记成「5 条断言红」（`DEF-118-17` 的同一教训）。
修法：toy 一律建在 `D98.DEV` 并取 `float64`（残差可判到 `1e-9`，不受 float32 噪声污染）。

★ 两者分工明确。★ 并且本轮读数恰好**经验地支持**了 `P118-2` 的决定：原生键下 `intact` 恒 `2/32`（贴零期望 ⇒ 无法区分"没内容"与"共线掩蔽"），
