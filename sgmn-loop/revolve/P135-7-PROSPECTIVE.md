## §2 装置与方法（为什么**没有**新建 `revolve/DIR-131`）

任务原文是「取下一张新卡」。★ 我**故意没有**建 `revolve/DIR-131`，理由是可验证的：

- 下一空号确实是 **131**（`revolve/DIR-*` 最大 **130**）；
- 但把一张卡放进 `revolve/DIR-*` 会**进入卡片人口** ⇒ `canonical_nums()` 由 **105 → 106**，
  所有冻结读数（`RA_new` **70/79**、`n_clause` **55**、各 `--probe-*`、`--selftest` 159、基线 39 项）
  **全部漂移** ⇒ 等于在无授权的情况下改动已发布读数。
- ★ 而四条读数**都只依赖于条款文本本身**：`R-A` 判「该行在哪个段内」、`R-B/C/D` 判「该条款的字符串」。
  ⇒ **用条款级候选**求这四条，与「放进一张卡再求」在判据上**等价**，且**不碰人口**。

★★ **这个替换的代价（必须写明）**：单条款 ≠ 完整卡片 ——
完整卡可能在别处也引了 `D-n`（`R-B` 的 `any()` 只看**本条**，不看卡内他处）、
段号与段名在真实卡里未必随我意、且真实卡的 `_de_emph` 上下文更长。★ 故本文的
「做到」是**存在性证明**（能写出满足四条的条款），**不是**「任何一张卡都能顺手满足」。

★★ 另：本轮交付物落在 `revolve/P135-7/` —— 这正是 `P135-21` 刚证实的 **MANIFEST 未记录区（G1）**。
★ 即**本文自己的文件不会被逐文件 md5 记录**。这不是本轮的缺陷，是上一轮已登记的缺口；记在此以免误读。

## §4 ★★★ ② 正向句：`0/55` 的真正机制（本轮最重要的发现）

### §4-1 装置里有**两张**「禁止」词表，它们不等价

| 表 | 内容 | 用途 |
|---|---|---|
| `MISREAD_PROHIB` | `不得` `禁止` `不许` `严禁` `不能` `不可` | **检出**条款（`_MISREAD_FRAME`） |
| `_U4_NEG` | `不得` `不可` `不能` `不构成` `不回答` `不是` `未` `非` `无` | **归类**句型（`_u4_form`） |

实测逐个求交：

| 禁止语 | ∈ `_U4_NEG`？ | 后果 |
|---|---|---|
| `不得` | ★ **是** | 用它 ⇒ 句型**必为 NEG/BOTH** |
| `不能` | ★ **是** | 同上 |
| `不可` | ★ **是** | 同上 |
| `禁止` | **否** | 可为 **POS-only** |
| `不许` | **否** | 可为 **POS-only** |
| `严禁` | **否** | 可为 **POS-only** |

★★★ **`POS-only` 不是结构性不可达，而是被「不得/不可/不能」这三个人最常用的词挡住了。**

### §4-2 现库 `0/55` 的机制：`55/55` 全用了「不得」

| 普查项 | 读数 |
|---|---|
| `n_clause` | **55** |
| 含 `不得` | ★★ **55 / 55**（**无一条**不含） |
| 含 `不能` | 1 / 55 |
| 含 `不可` | 7 / 55 |
| 含 `禁止` / `不许` / `严禁` | ★ **0 / 55 · 0 / 55 · 0 / 55** |
| 12 条 `BOTH` 的 `POS` 命中串 | `只在`(1) `本卡只`(6) `本卡不`(2) `只测`(2) `只回答`(1) |
| 12 条 `BOTH` 的 `NEG` 命中 | 全部含 `不得`（3 条另含 `无`） |

⇒ ★★★ **`R-D`（严格 `POS`）= `0/55` 完全由用词决定**：既然 55 条**每条**都写「不得」，
而「不得」∈ `_U4_NEG`，那 `POS-only` **在数学上不可能**出现。**这与「作者写不出正向句」无关。**

### §4-3 前瞻实测：`POS` + 四条齐备**确实写得出来**

```text
## §6 边界
- **严禁**把 `dose=0.29` 的池化读数外推为「恒等映射」（依「D-161」）；本卡只测该单一尺度。
```

| 读数 | 值 |
|---|---|
| 检出（`_misread_hits`） | ★ ✓ |
| 句型（`_u4_form`） | ★★ **`POS`**（`_U4_NEG` 命中 **`[]`**，即一个禁词都没有） |
| `R-A` | ✓ |
| `R-B` | ✓（「D-161」） |
| `R-C` | ✓（`dose=0.29`） |
| `R-D` | ★★ **✓（严格口径）** |

★ **代价（诚实记）**：这条句子读起来比自然禁令**别扭** —— `严禁…外推为` 是为避开 `_U4_NEG`
而选的动词搭配，且末尾必须挂一个 `本卡只测…` 才拿到 `POS`。⇒ **做到，但不是「免费」做到。**

## §7 ★★★ 前瞻性测试暴露的两个**装置缺陷**（旧库数不出来）

### §7-1 缺陷 A：`严禁`/`禁止`/`不许` 写的真禁令被判成 **`NONE`**

```text
## §6 边界
- **严禁**把 `dose=0.29` 的池化读数外推为「恒等映射」（依「D-161」）。
```
⇒ 检出 ✓，但句型 **`NONE`**（无 `_U4_NEG` 命中、也无 `_U4_POS` 命中）。

★★★ **即：`_u4_form` 的「NEG」类漏掉了 6 个合法禁止语中的 3 个。**
「句型 = NEG」并不等于「这是禁令型」——用 `严禁` 写的标准禁令会被记成 `NONE`，
`R-D` 的两个口径（严格 `POS`、宽 `POS|BOTH`）**都不收它** ⇒ 这类条款在 `R-D` 上**彻底失声**。

### §7-2 缺陷 B：`_U4_NEG` 里的 `未/非/无` 污染句型判定

C11 与 C12 **只差引语内容**：

| 版本 | 引语 | 句型 |
|---|---|---|
| C11 | 「恒等**映**射」 | ★ **`POS`** |
| C12 | 「记忆**无**用」 | ★ **`BOTH`** |

⇒ ★★ **仅仅因为被禁的误读里含一个「无」字，句型就从 `POS` 翻成 `BOTH`。**
「句型」本应是**条款的语法形式**，却被**引语内容**改写 —— 这是判据的射程错误，不是作者的错。

### §7-3 ★★ 两个缺陷都**不影响现库**（反事实实测，null result）

| 反事实 | 结果 |
|---|---|
| 把 `禁止`/`不许`/`严禁` 加进 `_U4_NEG` | ★ 现库 **0 条**条款句型改变（因 `55/55` 用「不得」） |
| 把 `未`/`非`/`无` 从 `_U4_NEG` 拿掉 | ★ 现库 **0 条**条款句型改变（同上） |

★★★ **这正是前瞻性验证的价值**：两个缺陷在**现有 55 条上完全不可见**
（任何重数、任何探针都测不出来，因为 55 条都含「不得」），
**只有写新条款才会撞上**。⇒ 任务书「前瞻性」的立意被本轮实测**证实**。

### §7-4 但这带来一个**两难**（须交 `K27` 制定者裁决，本文不裁）

- 若**把** `严禁/禁止/不许` 补进 `_U4_NEG`（修缺陷 A） ⇒ `POS-only` 从此**恒为 0**
  （任何被检出的条款都必含禁词 ⇒ 必为 NEG/BOTH）⇒ ②「正向句」这条读数**失去变量性**。
- 若**不补**（保留现状） ⇒ 用 `严禁` 写的条款被判 `NONE`，`R-D` 对它**失声**。

⇒ ★★ **`_U4_NEG` 不能同时充当「句型分类器」和「禁止语全集」。**
这两个用途需要**拆成两张表**（本文只指出，不实施 —— 改它会动已发布读数）。

## §8 对 `K27` 的可判定建议（只建议，不裁决）

1. ★★★ **`R-D` 不要报严格的 `POS`（`0/55`）** —— 它不是「写不出正向句」，而是「现库全用『不得』」。
   报 `POS` 必须**同时**报「`55/55` 含不得」这一机制，否则读者必然误读成能力缺陷。
2. ★★ 若 `K27` 要保 `POS` 这条读数**可动**，就**不能**把 `严禁/禁止/不许` 补进 `_U4_NEG`；
   那就必须接受「`严禁` 条款记 `NONE`」并另设一条「`NONE` 且含禁词 ⇒ 判为禁令型」的**补充读法**。
3. ★★ **合取（四件齐备）可选**：实测**写得出来**（C6/C11），但**无历史先例**（`0/55`）。
   ⇒ 若立合取，须声明它是**前瞻生效**，并接受「基线为起跑线而非及格率」。
4. ★ **`R-C`/`R-B` 都是代理**：前者收非数值等式，后者只看「有无出处引用」。
   立条款时**不要**把这两条读成「阈值已冻结」「禁令写得准」。
5. ★ **`R-A` 不构成负担**：写好段标题即可，**不必**为它改卡结构。
