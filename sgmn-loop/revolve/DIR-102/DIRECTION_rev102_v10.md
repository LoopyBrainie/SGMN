## §0 为什么是这一问（**且为什么它不是 `D-131` 的重复**）

### 0.1 `§2.2` 把 $\mathcal O_l$ 的可用信息**封闭**为两个实参

原文（`framework/SGMN_v2.4_架构设计.md` §2.2）：

$$
q_{l,t}=\mathcal Q_l(c_{l,t};\phi_l^q),\qquad
y_{l,t}=\operatorname{sg}(W_{l,t})q_{l,t},\qquad
\boxed{m_{l,t}=\mathcal O_l(c_{l,t},y_{l,t};\phi_l^o)},\qquad h^+_{l,t}=h_{l,t}+\gamma_l m_{l,t}
$$

⇒ $\mathcal O_l$ 的**全部**可用信息 = `(c_{l,t}, y_{l,t})`，**再无第三项**。且原文明确 **「$\mathcal Q_l,\mathcal O_l$ 的内部结构不指定」**。

### 0.2 两个实参的路径**都已被本 loop 逐一测过**

| 路径 | 代表证据 | 读数 |
|---|---|---|
| **`y` 路线**（`m = Wo·y`） | **`D-131`** | 秩扫描 `r∈{1,2,4,8,16,27,32,896}`×2 seed ⇒ 判据点 `r=32` **0.8125/0.8750**；全网格最大 **0.9688** `<0.99` ⇒ `A-NOT-SHARED` |
| **`c` 路线**（`q = Wq·c`） | **`D-130`** | 判别臂 `wq_oracle_id` 把查询解成**精确解** `cos_id_he = 1.000000`（三层×两 seed 全同）⇒ 而 `acc_held` **仍 0.0000** ⇒ `A-WQ-NOT-ENOUGH` |

⇒ **「再开一轮 `O_l` 的读出实验」不会产生非重复性证据**：`(c,y)` 两个实参都测尽了。

### 0.3 但 `§7.2-2` 问的不是「哪条路线」，而是「**参数共享**」——一个**数量**

`D-131` 测的是「**共享函数** `y→m` 的**秩**」；`D-130` 测的是「**查询**能否解准」。
两个都**没有**回答：**要让 32 个事实全对，最少需要几组不同的读出参数？**

- `D-131` 的答案族是 `{Wo = UVᵀ : rank ≤ r}` —— **必须是 `y` 的线性函数**。
- 本轮问的族是 `{ table[code] : code ∈ {1..K} }` —— **对 `y` 完全无约束的任意向量**。

⇒ 两族**不相交**（后者含前者在 `r=896` 且 `y` 线性可逆时的一个子集，但不是同一个参数化），
⇒ 关键差别：`D-131` 问「**一个共享的 `y` 的函数**能承载多少」，本轮问「**压缩下限**是多少」= **无论怎么索引，至少需要多少自由度**。
★ 后者是更强的陈述：若连「按固定规则分配、每码一个任意向量」都需要 `K=32`，则**任何**共享都无压缩余地。

### 0.4 ★ 开卡前已推翻的一条任务行候选（`DEF-102-01`）

任务行把候选 (a) 写成「逐事实自由 `m_i`（`D-109` 已证 `acc_held=1.000`）」并要求裁定其架构合法性。
**该表述基于误读，已在开卡前推翻**：

- `acc_held=1.000` 的 `free` 臂**不是** `D-109`，而是 **`D-112`/`D-113`/DIR-91** 的 `optimise_free`；
- **代码级证据**（`dir91/probe91_woform.py:236-276`）：`optimise_free` 逐事实建 `tgt`（来自 `c[1]` = **该题正确答项**）并 `cross_entropy(pick, tgt)` 反传 ⇒ `m_i` 是**用答案优化出来的**；
  且它循环 `for fi in keys`，`keys` **含留出事实** ⇒ 留出事实也拿到了**各自的答案定制**向量。
- ⇒ **`free` 用了测试时不可得的信息**（DIR-91 `VERDICT.md:732` 原文已写明「上界诊断、非可实现」）⇒ **它不是一条可实现路径**，无需裁定"合法性"。

⇒ **候选 (a) 作废**（不是"合法但昂贵"，而是"不可实现"）。本卡因此不问自由 `m_i`，而问**压缩下限** `K_min`。

## §1 主假说与判据（**冻结**）

### 1.1 主假说

> **`H102`**：达到 `acc_all32 ≥ 0.99` 所需的**不同读出参数组数** `K_min` **等于事实数 32**
> ⇒ **压缩比 = 1.0，零共享**；读出侧**结构性**必须逐事实分配自由度。

### 1.2 否证条款

> 若存在 **`K ≤ 8`** 使 `acc_all32(K) ≥ 0.99`，则 `H102` **否证**
> （= 真正的共享存在；`D-131` 的否定结果**只**对"线性于 `y` 的复合"成立，不适用于 $\mathcal O_l$ 的一般形式）。

### 1.3 判据（**唯一，冻结**）

| 标签 | 条件 | 判决 |
|---|---|---|
| **`C102-NOSHARE`** | `acc_all32(32) ≥ 0.99` **且** `acc_all32(16) < 0.90` | `H102` **成立** ⇒ `K_min ∈ (16,32]` ⇒ **零共享**；`§7.2-7` 读出侧记 **`已足够`**；`SUCCEEDED` **+1** |
| **`C102-SHARED`** | 存在 `K ≤ 8` 使 `acc_all32(K) ≥ 0.99` | `H102` **否证** ⇒ 共享存在；`SUCCEEDED` **不增**；读出侧**重新开放** |
| **`C102-PARTIAL`** | `acc_all32(32) ≥ 0.99` 且 `0.90 ≤ acc_all32(16) < 0.99` | 只报告 `K_min` 曲线，**不判** PASS/FAIL，**不豁免** |
| **`C102-BLOCKED`** | `acc_all32(32) < 0.99` | **判据未计算**（装置连"每码一个自由向量"都到不了容量）⇒ `BLOCKED`；**不得**记 FAIL |

### 1.4 阈值为何落在这里（**刻意远离已知值**）

已知锚点（全部实测）：chance **0.25**（4 选 1）· `D-131` 全网格最大 **0.9688** · `A101-1`/`free` 上限 **1.0000** · `D-100` 地板 **0.1250**。

- `0.99` 距 chance **0.74**、距 `D-131` 全网格最大 `0.9688` 仅 **0.0212** ⇒ ★ **刻意贴近 `D-131` 的最好格**：本轮问「**能不能达到 `D-131` 线性族够不到的那 0.0312**」，故必须比 0.9688 高。
  ★ **这是本轮判据最脆弱处，如实记录**：`0.99` 与 `0.9688` 只差 0.0212，**存在把数值抖动判成"共享存在"的风险**。
  缓解（**预注册**）：`acc_all32(32)` 必须**逐位复现 `1.0000`**（`A102-1`）—— 若装置在 `K=32` 上不能逐位给出 `A101-1` 的 1.0000，则 `0.9688` 与 `1.0000` 之间的任何读数**都不可解读**，一律 `C102-BLOCKED`。
- `0.90`（`C102-NOSHARE` 的 `K=16` 侧）距 `D-131` 的 `r=32` 读数 **0.8125/0.8750** 有 **0.0875/0.025** 余量；距 `0.99` 有 **0.09**。★ 如实记录：对 seed 7777 的 0.8750 余量仅 **0.025**，**偏紧**。
- `K ≤ 8` 才判"共享"：8 组参数服务 32 事实 = 压缩 **4×**，这是"有意义的共享"的最低门槛；**不**用 `K ≤ 16`（= 2× 压缩，与逐事实差别太小、区分不了）。

## §2 测量对象（**含手算算例**）

### 2.1 码本装置

- **码分配规则（冻结、与答案无关）**：把 32 个事实按 `build_facts` 的**固定下标** `i∈[0,31)` 分配
  ```
  code_i = i mod K
  ```
  ⇒ 每个码分到 `⌈32/K⌉` 或 `⌊32/K⌋` 个事实（`K∈{1,2,4,8,16,32}` 均整除，各 `32/K` 个）。
- **读出参数**：`table ∈ R^{K×d_v}`，`d_v = 896`；注入 `m_i = table[code_i]`。
- **优化**：只优化 `table`（`32/K × 896` 个参数），**其余全部冻结**、`no_write=True`、**不写 `W`**。
  损失 = 32 个事实的 4 选 1 交叉熵**求和**（一次反传覆盖全部事实，与 `optimise_free` 的"逐事实"不同 —— ★ 这是**唯一**的实现差别，必须如实记录）。
- **主读数** `acc_all32(K)`：同一 `K` 下对全部 32 个事实的 4 选 1 准确率（题集 `Random(555)`，`A101-1` 同口径）。

### 2.2 为什么 `K=32` 就是 `A101-1` 的 `free` 臂（**内建守卫**）

`K=32 ⇒ code_i = i mod 32 = i` ⇒ 每个事实独享一行 ⇒ `m_i` 任意 ⇒ 与 `optimise_free` 的**解集相同**。
⇒ **`acc_all32(32)` 必须 = `1.0000`**（`A101-1` 实测值）。
★ 差别仅在于"逐事实分别优化" vs "32 行联合优化"（§2.1 末）⇒ 若两者不等，**先查实现**，不得改判据。

### 2.3 手算算例（`A102-6`，**直接调被测函数**）

取 `K=2`、事实 0 与事实 2（`code_0 = 0 mod 2 = 0`、`code_2 = 2 mod 2 = 0`，**同码**）与事实 1（`code_1 = 1`）：
- 断言 `code_0 == code_2 == 0`、`code_1 == 1`；
- 断言 `m_0 is m_2`（同一张量对象 / 逐位相等）；
- 断言 `m_0 ≠ m_1`；
- `K=1` 时断言 `code_i == 0` 对**全部** 32 个 `i` 成立（`m_i` 全同）。
⇒ 手算给出**确定**结果，不依赖任何训练。

## §4 自变量与网格（**冻结**）

- **唯一自变量**：`K` = 读出码本的不同参数组数。
- **网格**：`K ∈ {1, 2, 4, 8, 16, 32}`（6 点，含两端：`K=1` 全共享、`K=32` 逐事实）。
  ★ `K=32` 兼作 `A102-1` 守卫；`K=1` 兼作 `A102-2` 下界守卫。
- **种子**：`{20261028, 7777}`（与 `D-131` 同两个，可逐格对照）。
- **不扫**：`d_v`、事实数、值池、`η`、挂载层（`MOUNT=[8,12,16]` 照抄）。
- **步数**：`LR` 与 `steps` 照抄 `D-131` 的 `READ_LR=1e-3` / `READ_STEPS=600`（`K=1` 只有 896 个参数、`K=32` 有 28672 个 ⇒ 同一步数下不同 `K` 的有效学习量不同）。
  ★ **如实预注册此偏差**：`K` 与参数量成正比 ⇒ 步数相同会使小 `K` 更"充分"训练。这是**对 `H102` 不利**的方向（让共享更容易成功），故若仍得到 `C102-NOSHARE`，结论**更强**；若得到 `C102-SHARED`，**必须**加测步数敏感性（`steps∈{600,2400}`）才能接纳。

## §5 边界（**预先声明，不得外推**）

1. **`acc_all32` 是容量，不是泛化**（`D-131` §3 边界 2 同款）：训练用全部 32 事实；**不得**表述为"留出"或"泛化"。
2. 本轮**只**回答「$\mathcal O_l$ 需要多少组参数」，**不**回答「真实 LLM 上的任务收益」；`§7.2-7` **整行**是否 `已足够` 仍需按矩阵逐项对照。
3. `K_min` 是**本装置、本值池（27 值/32 事实）、`d_v=896`** 下的量；**不得**外推到不同值池/事实数/维度。
4. **码分配 `i mod K` 是任意但冻结的规则**；换规则（如按值分组）可能改变 `K_min`。**不得**把本轮 `K_min` 当作与分配无关的下界。
   ★ 反制：`i mod K` **与答案值无关**（`build_facts` 先造 key 再 `rng.shuffle(vals)`）⇒ 不引入答案信息；这一点必须如实写进 VERDICT。
5. `K=32 = free` 的等价是**解集等价**，不是"逐事实分别优化"的数值等价（§2.1 末）⇒ `A102-1` 要求**逐位** `1.0000`，不等即查实现。
6. **不得**用 `π` 判内容（`DEF-98-04`）；**不得**把 `cos` 类诊断量当判据（`DEF-100-04`）。
7. **不得**据此说"7b 已解决"：读出侧之外，写侧内容（`D-128`）与 `W` 中介（`D-124`）已有结论，但**任务收益**仍是 `§7.2-7` 的核心问句。
8. **不得**由 `C102-NOSHARE` 推出「SGMN 读接口不可实现」：被限定的只是 **$\mathcal O_l$ 的参数效率**，不是读接口存在性。

| ① `m ≡ 0`（完全不注入） | **0.03125** |
| ② `m = 随机常数`（32 事实同一向量，sd=1/2/3） | **0.0312 / 0.0312 / 0.0312** |
| ③ `m = 逐事实随机`（sd=1/2/3） | **0.0312 / 0.1250 / 0.0938** |

⇒ 未拟合的注入 ≈ chance（0.031–0.125）⇒ **注入是决定性的**，装置**没有**在"不看 `m`"的情况下答题。
⇒ 因此 `K=1` 的 **1.0000 是优化真的找到的解**，不是装置泄漏。

### 10.3 ★★★ 机制：`K` **不等于**独立自由度（本卡的**自变量混淆**，`DEF-102-02`）

`MOUNT = [8, 12, 16]`，而 `§2.2` 定义 `c_{l,t} = sg(h_{l-1,t})` —— **`h` 含低层注入**。
⇒ 层 8 注入的同一个常向量 `m₈` 会经**冻结基座的非线性前向**流到层 12 的 `c`、再流到层 16 的 `c`
⇒ 被后两层**重新读取**，从而产生**依赖于输入的**（因而是因事实而异的）效果。

⇒ **一个共享向量 ≠ 一个自由度**：三层挂载 + 冻结非线性基座把一个常向量「放大且差异化」了。
⇒ 本卡 §1 的主假说把 `K`（码本行数）当作"读出参数的自由度数目"，**该等同是错的** ——
这是**卡片层面**的错误，不是装置错误，故按用户规则**必须新开 revision**，不得改 rev 1.0 的任何文字（本节为追加）。

### 10.4 rev 1.1 的更正方向（**不改任何已冻结阈值**，只更正自变量与守卫）

1. **自变量重定义**：`K`（码本行数）→ **`K_eff`（独立注入向量的个数，且在"无跨层再入"条件下测量）**。
   实现路径：构造 **`MOUNT=[8]` 单层挂载**的栈（`MOUNT` 是 `R2_task91` 的模块常量，

   同时**保留** `MOUNT=[8,12,16]` 的 `K=1 = 1.0000` 作为**跨层再入的阳性证据**（不是失败）。

### 11.2 ★★★ 决定性诊断（`dir102/diag102_channel.py`）：注入的**两个通道缺一不可**

`dir101/R1_task101._read_r101:88-94`：注入 `m` 是 `(B,L,d_model)`、**在所有位置**返回并加进残差，
而 `_m_override` 的 `m[idx] = mo` **只改 `idx = arange(B)*Ln + (Ln-2)`，每题一个位置**。
⇒ 本诊断按位置过滤注入，在**同一训练好的 `tab`** 下比四种模式（`--mount triple`，`K=1`，seed 20261028）：

| 模式 | 含义 | `acc_all32` |
|---|---|---|
| `all` | 现状（全位置注入 + 读出位覆盖 `tab[·]`） | **1.0000** |
| `readout_only` | **只**在 `Ln-2` 保留，其余清零 | **0.3125** |
| `nonreadout_only` | 除 `Ln-2` 外全保留，读出位清零 | **0.0625** |
| `none` | 全位置清零 | **0.0938** |

⇒ **单通道都不行**（0.3125 / 0.0625），**合起来才 1.0000** ⇒ 两通道**真实协同**，不是"某一路泄漏"。

### 11.3 ★★★ 机制：读出位的 `K` 个向量是**引导（cue）**，不是**载荷（payload）**

- 载荷 = 其余位置的 $m=\mathcal W_o y$（真实检索值，逐位置、因事实而异）；
- 读出位那一个 `tab[·]` = **与事实无关的引导向量**，功能是让基座**读得出**已被检索到的内容。

⇒ 因为引导天然与事实无关，**一个向量就够** ⇒ `K=1` 与 `K=32` 同为 1.0000。
⇒ 本卡把「码本行数 `K`」当作"**记忆**参数的自由度数目"是**第二个、独立的混淆**：
  `K` 量的是**引导向量**的可压缩度，不是记忆的可压缩度。
⇒ 这解释了 §10.2 的全部读数：随机常数给 0.0312（引导方向错）、`m≡0` 给 0.0312（无引导），
  而**拟合过的常数**给 1.0000（引导对了）；与"常数装不下 32 个答案"并不矛盾 —— 常数**不需要**装答案。

### 11.4 ★ 对 `§7.2-2`「参数共享」的**正面答案**（本卡的真收益）

`§7.2-2` 问「$\mathcal Q_l,\mathcal O_l$ 的**参数共享**能共多少」。本节的答案是：

> **读出位那部分注入参数可以共享到极限 `K=1`** —— 因为它的功能是**引导**而非承载内容；
> 承载内容的检索通路（$\mathcal W\,y$，逐位置）**不需要**按事实分配新参数。

这是一个**可带走的架构结论**，且它不依赖本卡原来的（有混淆的）`K_min` 判据。
