## §1 ★★★ 与 `P135-12` 的关键不同：**必须修官方 flag**，不能只加并列探针

`P135-12` 的做法是「旧函数一字未动，新增 `--probe-u4-fixed`」。**本任务不照抄**，理由是：

| | `P135-12`（`--probe-u4`） | 本任务（三个姊妹探针） |
|---|---|---|
| 官方 flag 的读数 | **已归档成文件**（`revolve/P134-14/probe-u4.txt`） | **进了决定与台账**（`145 / 79 / 55`…） |
| 只加并列版会怎样 | 归档件仍可复现 ⇒ 可接受 | **官方 flag 继续打印错数**，旁边多一个「正确版」⇒ **缺陷被回避而非修掉** |

⇒ ★★★ 本任务的正确形态 = **官方 flag 修 + 旧实现冻结为可调用路径（方案 (a)）**：

```
--probe-u4-full      → 修正口径（mode=pop）
--probe-u4-full-legacy → 旧口径，与归档输出逐字节一致
（recount / axis 同）
```

★ 任务书原文那句「若只新增并列版，旧归档件将无法从当前代码复现」字面上说反了
（只增不改，旧 flag 仍可复现）；它真正担心的是**官方 flag 带着错数继续当门面**。已按后者执行。

## §3 ★★★★★ 本轮最重要的发现：**三个探针的 legacy 语义并不相同**

任务书假设三个探针同构。**实测不是**：

| 探针 | 原始副本规则 | 原始 revision 范围 |
|---|---|---|
| `_u4_family_rows`（→`--probe-u4-recount`） | `Ctx.card`（要求 `_v`） | **现行卡一张** |
| `probe_u4_full` | `Ctx.card`（要求 `_v`） | **现行卡一张** |
| `probe_u4_axis` | ★ `DIRECTION_rev{n}*` glob | ★★ **全部匹配副本**（`DIR-21` 有 **9** 个） |

### 我踩的坑（如实记录）

第一版我把三者**统一**成 `_u4_card_text(n, 'legacy')`（＝现行卡一张）。结果：

```
--probe-u4-axis-legacy  【③ 其余带轴值条款】 期望 149 → 实得 100     ✗
```

原因：`_u4_card_text(n,'legacy')` 只返回 `[ctx.card]`（1 个文件），而原函数 glob 到
**272** 个文件（`legacy` 口径下只有 **103** 个）⇒ `DIR-21` 从 9 个副本塌成 1 个。

⇒ ★★★ **「统一化」本身制造了新缺陷** —— 修复前必须逐探针**实测**其原始语义，不得按对称性推断。
★ 修法：给 axis 单独两个口径 `'axis-legacy'`（glob 全副本，冻结用）/ `'axis-fixed'`
（任意名，**revision 范围不动**）。

**机检**：`-REC-15` 钉死 `axis-legacy` = **272** 个文件 ≠ `legacy` = **103** 个 ⇒
任何人再把两者统一，夹具立刻报红。

本轮两侧验证时实测到两处不一致。**均已查清，都不是本轮改动引起的**：

### §16-1 `--probe-u4-{axis,axis-legacy}`：**本来就不可两侧逐字节比对**

该探针会打印 `len(ROOT.glob("dir*/out/*.json"))`，而**本地镜像不完整持有** `dir*/out/`
（探针自己早就写着「实测 499 vs trainer 808」）。实测差异**仅两行**：

| 行 | 本地 | trainer |
|---|---|---|
| 口径② `readings.json` 不是装置表 | `15/499（3.0%）` | `19/808（2.4%）` |
| 【①】读数文件存量 | **499** 个 / **15** | **808** 个 / **19** |

★ **所有实际读数两侧完全一致**：装置轴声明型 **10 张卡 / 10 条** · 其余带轴值 **149 条**
（扫参 **9** / 单值条件 **12** / 方程记号 **128**）· 合计 **159** 条。
⇒ 这是该探针**自带出处**的设计（它明写「同一句结论在两侧的百分比不同，但都极低 ⇒
结论不变、数字不得离源引用」）。**不得**把 md5 不等读成「代码不一致」。

### §16-2 `-REC-15` 第一版钉了**跨侧不稳定的总数**（已改，如实记录）

第一版钉 `axis-legacy = 272 个文件`。训练机实测 **270** ⇒ 夹具红。
**根因**：`revolve/DIR-64/` 的 `DIRECTION_rev64_v10.md` / `_v11.md` **本地有、训练机缺**；
两者**自首次归档提交 `e41b508`（Cycle 230）起就存在**，而训练机**不是 git 仓库**（rsync 镜像），
`push52.sh` 是**按名推送**、从不全量同步 ⇒ 这两张卡**从未被推上去**。
⇒ 这是**既存的镜像漂移**，只是本轮的夹具（精确数文件）才把它照出来。

**两处处置**：
1. ★ **把两张卡推上训练机**（它们是权威 git 跟踪件）⇒ `DIR-64` 现 4 张，两侧一致。
2. ★★ **改夹具**：不再钉全局 **272**，改钉**具体卡的语义差**
   —— `DIR-21`：`axis-legacy` **9** vs `legacy` **1**；`DIR-24`：**3** vs **1**。
   实测两侧**逐位相同**。⇒ ★ 这正是 `P135-12` 那条教训（**钉耦合而非钉数值**）的再次应用：
   绝对文件总数依赖「本地镜像是否完整」，而**语义差**（全副本 vs 现行卡）是**代码属性**。
