# DIRECTION rev 1.1 —— DIR-101：注入接口 `y → m` 是否为**共享函数**？（§7.2-7b，`D-130` 之后唯一剩下的环节）

**冻结时刻**：开卡即冻结。**§2/§3 的阈值与判决表在任何实验读数之前写定，此后一字不改**；要改只能新开 revision，旧版全部留档。

## §1 背景与**被本卡推翻的一条任务行假设**（`DEF-101-01`，开卡前读代码得出）

任务行（`task.md` 顶条）给的路线是：「取 `free` 臂的 32 个 per-fact `m_i`，拟合 `y_i → m_i` 的共享线性解」。
**该路线不可用**，两条独立理由：

1. **`m_i` 非唯一**。`optimise_free`（`dir91/probe91_woform.py:236`）只做**逐事实**的单向量优化、`acc=1.000` 的解集**极大**（896 维里只需满足 4 选 1 的间隔）。它返回的是解集里**任意一个点**。
   ⇒ 两个**同一答案值**的事实拿到的 `m_i` 可以毫不相干；对这样一组 `{m_i}` 做「能否被共享 `G` 拟合」的检验，**失败不可解读**（可能只是抽样点选得差）。
2. ★★ **`y → m` 本来就是共享线性映射**，不需要"另找"。读路径（`sgmn_module.py:71-80`）逐字为
   `c = sg(h)` → `q = Wq c` → `y = sg(W) q` → **`m = Wo y`** → `injection = m`，
   而 `Wo ∈ R^{d_model × d_v} = R^{896×896}` 是**一个**矩阵，**跨事实共享**。
   ⇒ 「是否为共享函数」问的**不是**存在性（架构里已然是），而是它的**复杂度**：**秩多少才够用**。

**⇒ 本卡改问秩**（方向不变，仍是「注入接口 `y→m` 是否为共享函数」；只换测量对象）。
★★ 这一改同时把 `D-130` 的纪律 ③（上限臂必须无歧义）落实到位：秩扫描**不涉及任何**拟合得到的 `m_i`，`G` 是被**搜索**出来的，不是对任意解集做回归。

## §2 主假说、否证条款、判据阈值（**冻结**）

### 2.1 主假说
> **`H101`**：共享线性注入接口 `m = G y`（即架构的 `Wo`）在**秩 `r ≤ 32`** 时即可在**全部 32 个事实**上达到 `acc = 1.000`。

即：所需注入不是"每事实一个任意方向"，而是一个**低秩共享函数**；`r_min`（达到 `acc ≥ 0.99` 的最小秩）落在 `[1, 32]` 内。

### 2.2 否证条款
> 若 **`acc_all32(r) < 0.90` 对一切 `r ≤ 32` 成立**（含 `r = 32`），则 `H101` **否证**。

### 2.3 判据（唯一，冻结；阈值刻意远离机会水平与地板）
- **`C101-CAP`**：`acc_all32(32) ≥ 0.99` ⇒ 存在秩 ≤ 32 的共享接口。
- **`C101-FAIL`**：`acc_all32(32) < 0.90` ⇒ 否证。
- `[0.90, 0.99)` 之间 = **`PARTIAL`**（只报告，不判 PASS/FAIL，不豁免）。

★ 阈值依据：机会水平 **0.25**（4 选 1）、基座地板 `acc_held(W=0)` = **0.1250**（`D-129`/`DEF-99-05`）。
`0.99` 距两者 ≥ **0.74**，`0.90` 距机会 ≥ **0.65** ⇒ **不与任何已知机会值/地板撞值**（`DEF-99-05`）。
★ **`0.99` 不是 `1.00`**：装置有 seed 抖动（`D-129` 格间 0.7500–0.9375），要求逐位 1.0 会把数值抖动判成否证。

### 2.4 判决表（冻结）
| 读数 | 判决 |
|---|---|
| `acc_all32(32) ≥ 0.99` **且** `r_min ≤ 32` | **`A-SHARED-LOWRANK`**（`H101` 成立，`SUCCEEDED` +1） |
| `acc_all32(32) < 0.90` | **`A-NOT-SHARED`**（`H101` 否证；⇒ 注入接口需 per-fact 自由度，**结构性**，可终结读出侧线） |
| 其余（`[0.90,0.99)`） | **`A-PARTIAL`**（不计入，报告 `r_min` 曲线） |
| 任一守卫 `A101-*` 失败 | **`BLOCKED`**（不许出判据读数；不得放宽守卫） |

### 2.5 ★ 两侧闭合（**预注册**，避免又一次「改写缺口」）
- 若 **`A-SHARED-LOWRANK` 且 `r_min ≤ 32`** ⇒ 障碍**不在注入接口的表达力**，而是**样本数**：`r_min` 个自由度需要 ≥ `r_min` 个独立事实才可辨识（`D-111` 已测 16 样本 < 所需）⇒ **§7.2-7b 的可达性判为：需要 ≈`r_min` 个事实**，该行为**可推进**、**不得**记 `已足够`。
- 若 **`A-NOT-SHARED`** ⇒ 注入接口**必须**按事实分配自由度（`896` 维/事实）⇒ 16 样本**原理上**无法确定 ⇒ 读出侧线**结构性不可达** ⇒ §7.2-7b 的**读出侧**分支记 `已足够`（并写明**只**终结读出侧，**不含**写侧/内容侧）。

## §3 测量对象（**含手算算例**，`A101-9` 须复现）

- **装置**：`white` 键臂（`D-129`/`D-130` 的 `KEY_ARM="white"`；键**互相正交**、`maxcos = 0.0000`），600 块写入，
  32 事实（**27 个不同答案值**，5 个值重复用到两次 —— 由 `VALUE_POOL` 27 词、`vals=[pool[i%27] for i in range(32)]` 决定）。
- **量**：`Wo` 因子化为 `Wo = U Vᵀ`，`U,V ∈ R^{896×r}`（`use_factorized` 同 `W` 的既有约定）。
  **独立变量 = `r`**；`Wq`、`W`、`gamma` 一律按原样（`W` 真写、读侧 `no_write`）。
- **训练**：任务损失 = 4 选 1 候选 CE（`train_read_task` 同一条），**训练集 = 全部 32 个事实**（★ 与 `D-111` 的 16 不同：本轮问**容量**，不问留出）。
- **主读数**：`acc_all32(r) =` 按题计（同题 `N_DRAWS=3` 次全对才算命中，`acc_by_question` 同一条）。
- **`r_min`** = `min{r : acc_all32(r) ≥ 0.99}`；若不存在则 `None`。
- **秩网格（冻结）**：`r ∈ {1, 2, 4, 8, 16, 27, 32, 896}`。
  ★ 含 `27` = **不同答案值数**（预测点）；含 `32` = 事实数（判据点）；含 `896` = 满秩（上限/守卫点）。

### 3.1 手算算例（`A101-9`，**直接调被测函数**，不另写推导）
取 `r = 2`、`d_model = d_v = 2` 的玩具实例：`U = [[1,0],[0,1]]`、`V = [[1,0],[0,1]]` ⇒ `Wo = I`；
`y = [[3,4]]` ⇒ `m = Wo y = [3,4]`，`‖m‖ = 5`。
断言：`‖Wo@yᵀ − [3,4]‖ = 0`、`‖m‖ = 5`、`rank(Wo) = 2`。

## §5 边界（**预先声明，不得外推**）

1. `white` 键是**上界臂**（`D-128`：用 oracle `K`）⇒ 本卡只回答「**给定已存好的内容**，注入接口需要多少复杂度」，**不得**说已找到 7b 的可实现路径。
2. 训练在**全部 32** 个事实上 ⇒ 本轮测**容量**，**不测**留出泛化；`acc_all32` **不得**表述为"泛化"。
3. `Wo = U Vᵀ` 秩约束下的最优可能受优化器影响 ⇒ 判决只对**该优化器 + 该步数**（`READ_STEPS=600`、`READ_LR=1e-3`）成立；`A101-2` 的闭式臂提供**与优化器无关**的下界对照。
4. `r_min` 是**本装置、本值池（27 值/32 事实）**下的量；**不得**外推到不同值池/事实数（`r_min` 预测与 `27` 相关，换值池须重测）。
5. **不得**用 `π` 判内容（`DEF-98-04`）；**不得**把 `cos` 类诊断量当判据（`DEF-100-04`）。
6. `A-NOT-SHARED` 只终结**读出侧**分支，**不含**写侧与内容侧结论。
7. **不得**把 `A-SHARED-LOWRANK` 记成"7b 已解决"：它只说明**表达力够**，`D-111` 的样本数结论仍在。

## §8 ★ rev 1.1（**Stage A 之后、正式轮之前**；时机如实披露）

**§2 主假说、否证条款、判据阈值（`0.99` / `0.90`）、判决表：一字未改。**
只改**一条守卫的性质**，并**新增**一条不混淆的守卫。

### `DEF-101-07`（★ 本卡自身的不一致，必须记档）
`A101-2`（rev 1.0）要求：用 `free` 臂的 `m_i` 与 `y_i` 拟闭式 `G = M Yᵀ(YYᵀ+λI)⁻¹`，装成 `Wo` 后 `acc_all32 ≥ 0.99`。
**实测 FAIL**：`acc_all32 = 0.0625`、拟合相对残差 **1.46e-01**。
**但这不是装置缺陷** —— 它是本卡 §1 **同一个缺陷**的重演：`optimise_free` 返回的是解集里**任意一个点**，
对这样一组 `{m_i}` 做回归，**成功与失败都不可解读**。§1 已据此**否决**了任务行路线，`A101-2` 却又把它立成**阻断式守卫** ⇒ **自相矛盾**。
★ 处置（不改判据）：**`A101-2` 降级为 report-only**（只记录，不参与硬门），理由如上，**不掩盖**其失败读数。

### 新增 `A101-6`（**真正不混淆**的接口守卫）
问「`y` 是否**携带**足够信息来决定 `m`」—— 这是**装置性质**，与解集取值无关：
- `r_y = rank({y_i}_{i=1..32})`（`y_i` 按列）⇒ 共享线性接口的秩**不可能**超过 `r_y`；
- `cos(y_i, y_j)` 在「**同答案值**」对与「**不同答案值**」对上的对比 ⇒ `y` 能否分辨事实。
**断言**：`r_y ≥ 8`（须 ≥8）。若 `r_y < 8`，`y` 根本不足以区分 32 个事实 ⇒ 秩扫描测的是别的东西 ⇒ `BLOCKED`。
★ 并把 `r_y` 与 `r_min`、`27`（不同答案值数）并列报告 —— 它不仅作守卫，**本身就是「是否为共享函数」的直接证据**。
