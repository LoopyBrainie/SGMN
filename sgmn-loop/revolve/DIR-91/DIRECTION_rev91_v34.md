## §1 为什么这个问此前从未被回答

此前每一轮的**隐含前提**都是：写侧池化信号 `c = mean_t sg(h_t)` 带着「是哪个值」。
`D-103` 说存储正常、`D-104` 说寻址到顶也只到 `0.125/0.188`、`D-106`/`D-108` 说取值算子、
`D-111` 说秩/参数个数不是瓶颈、`D-113` 说目标形状可达 —— **但没有一轮直接测过这个前提**。

若该前提**不成立**（池化已毁掉事实身份），则 `rec = 0.0000`、`M2.acc_train = 0.1250/0.1875`、
`cos(q,k) ≈ 0`、键近乎退化**全部由同一原因解释**，且是**结构性**的。

**★ 关键结构事实**：`SGMNStack(model, MOUNT, d, d, R, …)`（`R2_task91.py:106`）以
`d = hidden_size = 896` 传入 `d_k = d_v = 896` ⇒ `Pk`、`Pv` 都是 **896×896 满秩方阵**，
`mk` 用 `randn/sqrt(d)` ⇒ 条件数良好。因此：
- 若 `H` 带值身份 ⇒ `K`、`V` **必然**也带（仅差一个良态线性映射）；
- 反之若 `K`/`V` 不带而 `H` 带 ⇒ **指向病态条件数**，须报 `cond`（本卡 `A97-10` 分支）。

⇒ 这把「投影宽度/信息瓶颈」排除掉了，剩下的判决是**信息在不在写侧**。

## §3 测量对象（须对一个具体算例验过）

`write()`（`sgmn_module.py:78`）的实际写规则：

```
hf = hs_in.reshape(-1, d);  pf = hf
k  = (sg(pf @ Pk).mean(dim=0)) * pk_scale        # (d_k,)
v  =  sg(hf @ Pv).mean(dim=0)                     # (d_v,)
```

`key_matrices()`（`R2_task91.py:332`）用 `st._hs_in[li]` 复原同一对象：
`pf = st._hs_in[li].reshape(-1, d)`，再 `(pf @ Pk).mean(0) * pk_scale`、`(pf @ Pv).mean(0)`。

本卡的 `H_i := (st._hs_in[li].reshape(-1, d)).mean(dim=0)` —— **与 `k`/`v` 用同一个 `pf.mean`**。
★ 因此 **`A97-03`** 断言 `(H @ Pk) * pk_scale == K`（来自 `key_matrices`）**逐位相同**，
`A97-04` 同理 `H @ Pv == V`。这不是形式主义：`DEF-96-08` 的失败正是「手搓的 v 不是装置写的 v」。

**工作算例（`A97-00` 的一部分）**：手工取第 0 条事实、第 8 层，
用 `st._hs_in[8]` 直接算 `hf.mean(0)` 得 `H_0`，再与批量算出的 `H[8][0]` 比 `max|Δ|` 须 `== 0`——
证明「逐事实一 chunk」的索引（`ci = owner.index(fi) + 1`）没有错位一个块。

## `DEF-97-01`（★ 本轮最严重）· 工作算例里的野 forward 在 `no_write=False` 下**写了**

`v34` §4 的 `A97-00` 工作算例块里，第一行 `model(input_ids=...)` 落在
`no_write` 恢复为 `False` 之后（`capture()` 内部已把 `no_write` 还原）
⇒ **该次 forward 真的执行了写入** ⇒ 之后 `A97-05` 读到 `max|ΔW| = 1.9e-03`。
★ **这正是不该放过的那种失败**：若我按"门太严"把它放过，正式轮的 `H/K/V`
就取自一个**已被写入**的状态，`WS_*` 结论全部作废。⇒ **`A97-03/04/05` 三条守卫成功拦截了一次静默污染。**

**修复**：工作算例改为**先设 `no_write=True` 再 forward**，且 `Wsnap` 在**所有 capture 之前**取、
`A97-05` 在所有 capture **之后**核；并新增 `A97-05b` 断言 `write_calls` 全程 `== 0`。

## `DEF-97-02` · `A97-03/04` 用 `== 0` 要求**换了算序**的浮点积逐位相同（不可达）

`write()` 是 `((pf @ Pk).mean(0)) * pk_scale`（**先乘后均**），我原来拿
`(pf.mean(0)) @ Pk`（**先均后乘**）比 ⇒ 数学恒等、**浮点不等**，实测相对差 `3.14e-08`。
⇒ 这是 `DEF-95-01` 的镜像：**那次门过严抓到我，这次门过严造成假失败**。
**修复（更强，而非放宽）**：拆成两条
- **`A97-03a`（严格 `==0`，承重）**：用**同一算序**复算 `Kmine = ((pf @ Pk).mean(0)) * pk_scale`，
  断言 `Kmine == K` **逐位相同**。★ 这条才是真正证明"我的 `pf`（及其逐事实块索引）就是装置的对象"的断言。
- **`A97-03b`（相对门）**：`‖(H@Pk)·s − K‖/‖K‖ ≤ 1e-6`（仅为"`H = pf.mean(0)` 与 `K` 自洽"的旁证）。
- `A97-04` 同理拆成 `A97-04a`（`==0`，同算序）/ `A97-04b`（相对 `≤1e-6`）。

## `DEF-97-03` · `A97-07` 的 `≤1e-10` 在 float32 下不可达

`H` 是 float32、量级 `O(10²)`，32 条求均后残差实测 `8.34e-07`。
**修复**：改为**相对**门 `‖mean_i H_c‖∞ / ‖H‖∞ ≤ 1e-5`，并**同时**在 float64 里复算一次断言 `≤1e-10`
（float64 复算能真正验"减均值"这一步写对了）。

## `DEF-97-04` · 引错模块（`ridge_closed` / `N_CLS` / `split16` / `W`）
