## §0 更正的事由（`DEF-96-07`：**幅度未标定** ⇒ 把"注入太小"误判成"目标不可达"）

rev 3.2 的 `A96-11` 直接注入 `m_i := normalize(E_unembed[token(v_i)])`，即**单位范数**向量。
但同一台装置的读出向量 `‖y‖` 实测 **均值 ≈ 12.6（最小 12.64）**，而 `m = Wo y` 与 `‖y‖` 成比例，
`m` 又被**加到隐状态**上 —— 而 Qwen 在 `MOUNT=[8,12,16]` 层的隐状态范数远大于 1
⇒ **一个范数为 1 的加性扰动在数值上可忽略**。
⇒ `acc = 0.2188`、`margin = −0.782` **与"什么都没注入"不可区分**。
⇒ rev 3.2 §2 由它推出的"`m` 是隐状态扰动、不是 logit 偏置 ⇒ 从输出嵌入推导 `Wo` 不可达"
**是把量级伪影合理化成了一个机制故事**。**该机制叙述作废。**

### 实测：oracle 的**幅度扫描**（`/tmp/oracle_scale.py` → `dir91/out/probe91_oracle_scale.json`）

| 3.0 | `0.3750 / 0.6250` | `0.5625 / 0.5000` |
| **10.0** | **`1.0000 / 1.0000`** | `0.9375 / **1.0000**` |

⇒ **"从输出嵌入推导的共享目标"经该读出通路是可达的**，rev 3.2 的 `TARGET_UNREACHABLE` **被推翻**。

## §1 修正后的主假说

**H1′（本版）**：读出位所需的 `m` **可以与一个现成的、无需训练的语义量对齐** ——
即"让答案 token 的输出嵌入方向（按隐状态量级缩放）出现在读出位"足以让正确候选胜出。

**推翻条款**：若在 `α` 扫描中 oracle 的 `acc_held` **始终** `≤ G_low`（两 seed），则 H1′ 被推翻。
**实测：`α ≥ 10` 时两 seed 均 `acc_held = 1.000` ⇒ H1′ 未被推翻。**

★ 本版**不**声称"`Wo` 不需要训练"（oracle 用**真值答案**，测试时不可得，是**上界诊断**）；
它只证明**该目标形状可达**，从而**不能**用它来论证"共享目标无用"。

## §2 冻结判据（**本版新增，此后不得改**）

| 常量 | 值 | 含义 |
|---|---|---|
| `ORACLE_ALPHA` | **`{0, 1, 3, 10, 30, 100, 300, 1000}`**（冻结网格） | ★ 幅度扫描网格；**不得**只报单点 |
| `ORACLE_REACH` | **`G_gen = 0.50`**（沿用） | oracle 在**任一** `α` 上两 seed 均 `acc_held ≥ 0.50` ⇒ 目标**可达** |
| `MAG_RATIO` | **`‖h_read‖ / ‖m‖`**（逐层报） | ★ 幅度标定用：`α` 必须与隐状态量级同阶才有意义 |

**判决（本版）**

| 条件 | 判决 |
|---|---|
| 存在 `α` 使两 seed `acc_held ≥ G_gen` | **`TARGET_REACHABLE`**（**实测成立**：`α ≥ 10`） |
| 全部 `α` 两 seed 均 `≤ G_low` | `TARGET_UNREACHABLE`（**未发生**） |
| 介于其间 | `TARGET_PARTIAL` |

★ **`α = 0` 基线必须与每个 `α` 一起报** —— 否则无法区分"注入有效"与"注入无影响"（`DEF-96-07`）。
★ 读数**必须**报 `margin`（`Δlogit` 的连续代理），**不得**只报 `acc`（4 选 1 的粒度是 `0.0625`，
太小，`margin` 才是分辨"方向对但幅度不足"的量）。

## §3 `rec = 0.0000` 是否受本缺陷影响？—— **不受**

`rec` 是**解码器**读数（用 `ridge_scores` 从 `y` 预测值类），**完全不经过注入通路**，故与 `α` 无关。
但按 `CORR-17` 规则 ①，`rec` 的**标签管线**（`value_classes`、capture 位置、排序）**尚未在真实数据上验证**
—— `A96-01`/`A96-04` 只验了**合成标签**。⇒ **本版新增 `A96-12`**：

**`A96-12`（正对照 —— ★ 已**降为仅报告**，见 `DEF-96-08`）**

★ **更正（`DEF-96-08`，实测于 Stage A）**：我原先要求 `M1b(v) == CAP_LOO = 10/32`，
**该期望值错**：`0.312` 是 **`D_vtpos` 实验臂**（值 token 位池化）的读数；
本 probe 用**未改动的原生装置**（`A_mean` 块均值池化），`D-108` 实测该臂 `M2loo ≈ 0.042`（**近 chance**）。
实测 `M1b(v) = 0.03125 = 1/32`（用 `R2.key_matrices`）⇒ **近 chance，与 `D-108` 一致，装置正常**。
⇒ `A96-12` **仅报告、不作门**。**标签管线已由 `A96-01`（合成可读 = 上限精确）＋ `A96-04`
（投毒 0、打乱 0.0417）验证**，无需 `A96-12` 承担。

原设想的正对照（保留描述供复核）：：用**同一把解码器**（`ridge_scores` + `top1` + 同一 `cls` 标签 + 同一 LOO 构造）
去解码**存储的值向量 `v_i`**（`Pv · hs_in`，即 `D-106`/`D-108` 用过的那条通路）。
- 若 `M1b(v)` **打满 `CAP_LOO = 10/32`** ⇒ **标签管线在真实数据上被验证**，则 `rec(y) = 0` 可归因于 `y` 本身；
- 若 `M1b(v)` 也 `= 0` ⇒ **管线有系统性错配**，`rec(y)=0` **不可解释**，须先修管线。

★ **明确说明**：`D-106`/`D-108` 报的 `LOO = 0.312` **正是本卡的 `CAP_LOO = 10/32`**
⇒ 那两轮在 `v_i` 上也是**打满上限**（cap-saturated），不是"部分可读"。
★ 边界措辞同步收紧为：**"不被本卡这把岭回归/LOO 解码器、在该读出处、于原生 `q` 下线性解码"** ——
**不得**写成"`y` 不携带信息"（叠加干扰是等效的替代解释，未测）。

## §5 边界（继承 v30/v31/v32 全部有效条款；追加/收紧）

1. **oracle 是上界诊断**（用真值答案 `cls_i`，测试时不可得）⇒ **非可实现**；
   **不得**把 `TARGET_REACHABLE` 读成"装置已能做任务"或"`Wo` 无需训练"。
2. **`α` 只能与隐状态量级同阶才有意义**；本卡用 `α ∈ {0…1000}` 扫描，**不得**只用单点。
3. `rec = 0` **不得**外推为"值身份不在记忆里"（`D-108` 的 `rel(Wk,v)`、`D-106`/`D-108` 的
   `v→类 LOO = CAP_LOO`）；正确措辞见 §3。
4. `A96-12` 只用 `v_i` 一条通路验证**标签管线**；**不**证明 `y` 与 `v` 同源。
5. 其余全部继承。
