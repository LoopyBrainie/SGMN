## §0 为什么要改（`DEF-96-01`，**开卡期缺陷，实测暴露**）

rev 3.0 冻结 `M1a`（27 类、用 `y_train` 16 条拟合、判别 `y_held` 16 条），并规定
"`M1a ≥ CEIL_HIGH = 0.50` ⇒ 有身份"。**该门在数学上不可达**：

- 训练集 `tr = 0…15` 的答案值类是 `{0,1,…,15}`；留出集 `he = 16…31` 的值类是
  `{16,…,26} ∪ {0,1,2,3,4}`（因 `N_FACTS=32 > |VALUE_POOL|=27`，值类循环）。
- 其中 **11 条**（`i=16…26`）的值类是 `{16…26}`，**在训练集中从未出现**
  ⇒ 任何 16 条样本拟合出的分类器**对这些类没有权重**，**不可能判对**。
-  ⇒ `M1a` 的**结构上限** = `n_seen_class_held / n_held = 5/16 = 0.3125`。
-  ⇒ `CEIL_HIGH = 0.50 > 0.3125` ⇒ **`M1a ≥ CEIL_HIGH` 永不成立** ⇒
  冻结判决表里 `SAMPLE_LIMIT` 那一支**永不可能被选中**，而 `M1a ≤ CEIL_LOW = 0.25`
  却**很可能**成立 ⇒ 会把一切判成 `Y_NO_IDENTITY`。**这是门的位置错了，不是被测对象坏了。**

★ Stage A 实测证据：`A96-01` 用"值身份完全线性可读"的**合成** `Y`（`Y[i]=α·B[cls_i]+noise`），
`M1a` 只得 **`top1 = 0.0625`**（= 1/16）—— 若量测对象或解码器坏了，这个数字不会恰好是 `1/16`；
它恰是"`he` 里 11 条不可判 + 5 条可判但也没判对"的形状。⇒ **`M1a` 不是身份探针，是抽样上限探针。**

★ **注意 `5/16 = 0.3125` 与 `D-106` 的结构天花板 `10/32 = 0.3125` 数值相同** —— 这是巧合，
但两者含义不同：`D-106` 是"值 token 位可辨的上限"，`5/16` 是"训练集没覆盖该类"。**不得混引。**

★ 另有 `DEF-96-02`：`torch.round(T, 5)` 在新版 torch 不接受位置参数 ⇒
改为 `torch.round(T * 1e5) / 1e5`（A96-02 崩溃，非被测对象问题）。

## §1 主假说（**与 rev 3.0 完全一致，未改**）

**H1**：`D-111` 剩下的瓶颈是**样本量** —— `y = sg(W) q` **携带**答案身份，
只是 16 条样本不足以定位共享映射 `M`（`Wo`）。

**推翻条款**：若 **`y` 中不存在可从 32 条线性读出的答案身份**（下方 `M1b ≤ M1B_LOW`），
则任何样本量、任何目标构造都不可能救 ⇒ **H1 被推翻**，判决 `Y_NO_IDENTITY`。

## §2 修正后的 `M1`（**冻结**）与数值门

**把"信息是否存在"与"16 条样本能否提取"分成两个读数**，这是本版的核心修正：

| 读数 | 构造 | 类覆盖 | 机会水平 | 用途 |
|---|---|---|---|---|
| **`M1b`** ★**主判据** | **全 32 条 leave-one-out**：对每条 `i`，用其余 **31** 条拟合 27 类岭回归，判 `y_i` | **全 27 类**（31 条必覆盖） | `1/27 = 0.037` | **信息是否在 `y` 里**（机制门） |
| `M1a` | `y_train`(16) 拟合 → 判 `y_held`(16) | 仅 `{0…15}` | `5/16 = 0.3125`（**结构上限**，非 1/27） | 16 条样本制度下**实际**拿到多少（**仅报告**，比 cap） |

★ `M1b` 用 31 条拟合，**比 16 条制度多** —— 这不是缺陷，**正是设计**：
`M1b` 问的是「**信息在不在 `y` 里**」，`M1a` 问的是「**16 条能不能提出来**」。两者之差即样本量的代价。

**新增/沿用的冻结门**

| 常量 | 值 | 含义 |
|---|---|---|
| `M1B_LOW` | **0.15** | ★ 新：`M1b` 的"**无**线性身份"门（≈ 4× 机会 `0.037`） |
| `M1B_HIGH` | **0.3125** | ★ 新：`M1b` 的"**有**身份"门（= `D-106`/`D-108` 在 `v_i` 上实测的结构天花板） |
| `CEIL_D106` | 0.3125 | 参照（数值同 `M1B_HIGH`，含义不同：那是 `v_i` 上的，本条是 `y` 上的门槛） |
| `CAP_M1A` | **0.3125** | `M1a` 的**结构上限** `5/16`（报告用，**不得**当门） |
| `G_gen` / `G_low` / `G_delta` / `CHANCE` | **0.50 / 0.25 / 0.125 / 0.25** | **沿用 rev 3.0，一字未改** |

**判决表（冻结，替换 rev 3.0 的同名表）**

| 条件 | 判决 | 含义 |
|---|---|---|
| **`M1b ≤ M1B_LOW`** | **`Y_NO_IDENTITY`** | `y` 里**没有**可线性读出的答案身份 ⇒ H1 推翻，样本量与目标构造**都不是**出路 |
| `M1b ≥ M1B_HIGH` 且 `M2.acc_held < G_low` 且 `M4.acc_held < G_low` | **`SAMPLE_LIMIT`**（确认） | 身份**在** `y` 里，但共享映射在 16 条样本下提不出来 ⇒ H1 **未被推翻** |
| `M2.acc_held ≥ G_gen` | **`TARGET_STRUCTURE`** | 共享目标救得回来 ⇒ 瓶颈是**目标构造** |
| `M4.acc_held ≥ G_gen` | **`WQ_CONFOUND`** | `Wq` 联合训练是元凶 |
| `M1B_LOW < M1b < M1B_HIGH` 且无臂达标 | **`Y_PARTIAL`** | 部分身份；判"16 条不足以利用部分身份" |

★ **两 seed 必须同支**；不同支记 `AMBIGUOUS`，如实报两 seed 读数，**不得**取平均。
★ `M1a` **仅报告**，且**必须**与其结构上限 `CAP_M1A` 并列印出；**不得**用绝对 0.50 判它。
★ `M3` **仍仅报告**（`n_seen = 5`，粒度 `0.2`），**不得**作任何判决的门（`CORR-10` 精神）。

## §3 修正后的 worked example（`A96-01`，**冻结**）

`A96-01` 改为**对 `M1b`（全类覆盖）做双向验证**，因为 `M1a` 在合成情形下也受 `5/16` 上限约束、
**不能**用来证明解码器"能判对"：

- **(a) 合成可读**：`Y[i] = B[cls_i] + 0.01·ξ`（`B` 为 27 个 896 维随机基）⇒ **`M1b ≥ 0.999`**。
- **(b) 纯噪声**：`Y = 随机`⇒ **`M1b ≤ 0.15`**（`1/27 = 0.037`，容许岭回归过拟合余量）。
- **(c) 双向都对**才 PASS ⇒ 证明 `M1b` 能区分"有身份/无身份"，不会恒 1 也不会恒 0。

★ 并**追加**（报告项，不作门）：同一合成可读情形下 `M1a` 的实测值，预期 ≈ `CAP_M1A = 0.3125`；
若实测恰好落在此值附近，则该数字**再次确认** `M1a` 是结构上限探针（`DEF-96-01` 的独立复验）。

## §5 边界（**继承 rev 3.0 §5 全部，并追加**）

1. `M1b` 判的是「**线性**可读」；**不得**外推为"`y` 完全不含信息"（非线性可读未测）。
2. `M1b` 用 31 条拟合 ⇒ 它**不**代表 16 条制度下的可实现性能；**不得**把 `M1b ≥ M1B_HIGH`
   读成"16 条就够"。**两者之差正是待测的样本量代价。**
3. `M1a` **不是**身份探针（受 `5/16` 结构上限约束，`DEF-96-01`）；**不得**用它的绝对值下判决。
4. rev 3.0 §5 的其余 9 条**全部原样有效**。

## §6 不做的事（**继承 rev 3.0 §6，一字未改**）

不做事实池扩容 / `n_train` 扫描（存储负荷共变 + `W` 逐位守卫不可满足）；
不做 `y` 的非线性可读性（另开卡）。
