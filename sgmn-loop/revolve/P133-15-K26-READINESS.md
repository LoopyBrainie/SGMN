# `P133-15` · `K26` 的可用形式：把「禁止集的可执行性」落成**可抄读数**

- **性质**：**清单治理 / 工具**（`Cycle 259`，`P133-11` 派生）。**无新方向、无新证据行、无新判决。**
- **产物**：`.ops/scripts/check_cards.py` 的 **`--probe-k26`**（+ 16 条可证伪自测夹具 `-K26-1`…`-K26-16`）；本文件。
- **工具 md5**：`032cc31c23a4…`（★ 工具变了 ⇒ `.ops/COMPLIANCE-BASELINE.md` 头部须刷新，见 §7）
- **`K26` 是 `②留痕`** ⇒ 本探针**不判 `PASS/FAIL`、不进 `REGISTRY`**，只把**事实**摆出来供开卡人声明。

## §1 为什么需要它（动机不是「补个功能」）

`K26`（`P133-11`/决定二百四十七）现在是**散文纪律**，与 `K25` 当年**同病**：
`K25`（「守卫**够不够**」）要到 `P133-8` 才补上 `--probe-guard-coverage`，在此之前它
只是一句话。**一条只能靠人记住的纪律 = 一条会被违反的纪律**（本库 `DEF-128-03` 的教训：
「结构计数必须由代码数」）。

`K26` 比 `K25` **更**需要工具：它要求「**至少两道**、**形态互不相同**」—— 而「形态不同」
恰恰是**肉眼最难判**的（`P133-8` 实测：字面网命中 **2/6**、漏 **4/6**；再加一张词表是
**同一形态的重复**，看起来像「两套判据」其实是**一道网**）。

## §2 探针把 `K26` 的三步逐条落成什么

| `K26` 的步骤 | 探针给出什么 | **谁**判定 |
|---|---|---|
| **① 能不能枚举** | 该条禁止语句的**机制标记 → 形态候选**（`E-LIT`／`E-COMP`／`U1-AGG`／`U1-SRC`／`U1-CLS`／`U3`） | **人**（★ 候选，不是判定 —— `K26` 是 `②留痕`） |
| **② 已配几道网、形态** | **四个布尔值**：字面`(实)`／字面`(声)`／形式无关`(实)`／形式无关`(声)` + **证据串** | **机械事实**（`(实)`）＋ 人读完 `(声)` |
| **③ 是否已明示「不可枚举」** | 强信号命中 + **触发行** + 是否有**理由** | **人**（触发行交人复核） |

★★★ **本探针的核心区分：`(实)` ≠ `(声)`。**

| 读数 | 机械定义 | 为什么必须分开 |
|---|---|---|
| **字面网`(实)`** | 卡片 `precheck*.py`/`mech*.py`（**只这两个族**，见 §3.2）里存在**模块级**字符串序列常量（`list/tuple/set`，**≥3 项且全为字符串**） | 那是**真的** token 表 |
| **字面网`(声)`** | 卡片文本里 **`S\d+` 守卫名** 与「禁用词／白名单／词表」**同现** | 只是**说法** |
| **形式无关网`(实)`** | 卡片 py 里存在**载体类**（`Agg`/`Carrier`/`Tagged`/`Redacted`…）**或**`*audit*`/`provenance` 函数 | 能让被禁量**不可打印** |
| **形式无关网`(声)`** | 卡片文本里「**形式无关**」与「**源头／不可打印／不算出／只报布尔／身份载体**」**同现** | 只是**说法** |

★ **汇总只认 `(实)`**。这是 `P133-8` 的教训在 `K26` 上的**同构复用**：
「有守卫 ≠ 守卫够」⇒「**说**有两道网 ≠ 两道网在」。夹具 `-K26-9` 专测这一点：
**只会声明、零实测 ⇒ 必须判 `ZERO`**（若状态机读了 `(声)`，该夹具必红）。

★ **阈值为什么是 3**：1–2 项的序列在本库几乎都是**分支参数**（`("a","b")`），
而 `DIR-130` 的真词表是 `["聚合","中间","合并","累加","sum","mean"]` 这个量级；
夹具 `-K26-2`（2 项 ⇒ 0）、`-K26-3`（3 项但非字符串 ⇒ 0）钉住了这条线。
★ **为什么只认模块级**：局部 list 是**中间量**，不是**判据**；判据词表必须由卡片在
**开卡时冻结**（`K16` 判读的理由）⇒ 夹具 `-K26-4`。

## §3 ★★★ 本轮实测踩到的**两类误报**（都改了，都留档）

### 3.1 第一类：`③` 把「测量不可判定」误读成「禁止集不可枚举」

初版把「判不了／**不可判定**／欠定义」也算 `③` 的强信号，跑出来 **4 张卡**被判成
「已明示不可枚举（合法出口）」：`DIR-38`、`DIR-39`、`DIR-40`、`DIR-104`。

逐张读**触发行**发现**全是误报** —— 它们的原句是

> `- ★ 不可判定：若 …`

讲的是**测量**不可判定，**不是禁止集不可枚举**。★ 若照此计入，`③` 就成了一条
**只要写「判不了」就能走的后门**，而 `K26` 步骤 3 的本意是**承担举证责任**。

**修法**：`③` 的**强信号只认带「枚举／穷举／逐一列举」的措辞**
（`不可枚举|无法枚举|不能枚举|枚举不了|无法穷举|不能穷举|无法逐一列举|不能逐一列举|无法逐项列举`）；
「判不了／不可判定／欠定义／无法界定／说不清」降为**弱信号** ——
**只提示、不翻转状态**，并打印为「★弱信号（**不**算 ③ 的合法出口，仅提示人工复核）」。
夹具 `-K26-15`／`-K26-16` 钉住。★ 修后 `③` = **0 张**，弱信号 **5 张**
（`DIR-38`／`39`／`40`／`55`／`104`）。

### 3.2 第二类：`②` 把**一次性 probe 脚本**里的清单当成**守卫**

初版扫的是 `dir{n}/*.py` **全部**，跑出来 **4 张**卡「两道网齐备」：
`DIR-111`／`112`／`113`／`130`。核对文件后发现 **`DIR-111`/`112`/`113` 根本没有
`precheck*.py` 或 `mech*.py`**（`ls` 空）—— 它们的「网」来自 `dir111/`、`dir112/`
里的**一次性探查脚本**。

★ **那不算守卫**：一次性 probe 跑完就不再执行，卡片的纪律**不依赖**它。
若照此计入，等于承认「**写过一个脚本看过一眼** = 配了网」—— 正是 `K26` 想防的
**假 `PASS`** 的同物种错误。

**修法**：扫描面收窄到**冻结交付物** —— 正则 `^(precheck|mech)[A-Za-z0-9_]*\.py$`，
与 §2 的机械定义**逐字一致**（文档原本就写的是「卡片 `precheck*.py`/`mech*.py`」，
是**实现**偏离了定义，不是定义有问题）。

★ **附带修好的一处不稳定**：初版因扫全部 `*.py`，读数取决于**工作区里恰好有哪些
probe 脚本** ⇒ 本地镜像与 trainer 文件集不同 ⇒ 两侧输出**无法逐字节比对**
（实测：67010 B vs 68139 B，125 行差异全是 `ast.parse` 的 `SyntaxWarning` 噪声与
行号漂移）。收窄后两侧**逐字节一致**；同时在 AST 助手内 `warnings.simplefilter("ignore",
SyntaxWarning)` —— 卡片 py 里 `\l` 这类 escape 不该污染探针输出（`stderr = 0 B`）。

★ 修后读数：**`②两道网` 由 4 张降为 1 张（只剩 `DIR-130`）**，`只有一道` 30 → **6**，
`零道` 35 → **62**。★★ **前一组数字是错的，不得再引用。**

## §5 边界（`K26` 与本探针各自**不做**什么）

1. **不进 `REGISTRY`** ⇒ `REGISTRY` 仍 **13** 条、清单 `①自动化` 仍 **13** 条、
   `--all` 判决**一字未动**（`PASS 384 · FAIL 271 · N/A 684`、实发 **1339**）。
2. **不替卡片发明白名单** —— 那只能由卡片**开卡时**冻结（`K16` 判读明令）。
3. **不改任何冻结卡**、不写任何 `out/`、不重跑任何 formal。
4. **不判「能不能枚举」** —— 它只给**形态候选**；`K26` 的判定归人（`②留痕` 的本义）。
5. **不把 `(声)` 当证据** —— 汇总只认 `(实)`；`(声)` 只为「声明与事实是否一致」服务。
6. **不覆盖 `K26` 的「两道网**各自**须有独立自测见证」**（`K26` 正文要求，沿用 `K25` 的 (b)）
   —— 本探针只看**网在不在**，**不看**见证质量；那是逐卡人工的事。
