## §9 Stage A 首轮实测：2 项 FAIL，逐条归因

首轮 Stage A（`out/stageA.log`）结果：**`A109-0/5a/5b/5c/1b/2/3/6/7/8` PASS，`A109-1`/`A109-4` FAIL**。

### 9.1 `DEF-109-02`（★ 实质缺陷，`DEF-95-01` 重蹈）—— 训练后**未重封** `no_write`

**现象**：`A109-1` FAIL。`T-BOTH(γ=0.005)` 的 `acc_item` 三 seed 全为 **`0.3333`**（= 16/48），
而 `DIR-104` 的 `INJ(γ=0.005)` 为 `0.0208 / 0.0417 / 0.1042`；
`T-Q` 与 `T-O` **也**都恰好 `0.3333`（而它们的 `gain16` 只有 `4.5` / `4.0`，与 `T-BOTH` 的 `537`–`679` 差两个数量级）⇒
**不是增益导致的，是任何训练都会撞到同一个退化点**。同时 `κ(L16) = nan`（`ρ_q/ρ_o/gain` 皆有限）。

**归因（决定性读数）**：`final_loss` 与 `DIR-104` **十位小数全同** ——
`0.8687` vs `0.8686546159751015` · `0.6451` vs `0.6451094183677639` · `0.8501` vs `0.8500934218091425`
⇒ **训练逐位相同，差异全在评测侧。**

**根因**：`dir104/R1_task104.py:142-144` 的 `train_read_frozen` 末尾执行
```python
for m in st.mems.values():
    m.no_write = False
set_grad_gamma(st, True)
```
而 `dir104/R1_task104.py:349-350` 在评测前**显式重封**：
```python
for m in st.mems.values():
    m.no_write = True
```
**`R1_task109.py` 的训练臂从 `train_read_sel` 直接进 `measure_state`/`score_matrix`，漏了这一步重封。**
⇒ 评测期间**写入规则真的跑**：`W = Wfull` 被改写、`prev_hs` 开始被设、`eta=3e-5` 的写入在 16 题×4 候选的前向上累积
⇒ 激活溢出到 `inf` ⇒ logits `inf/nan` ⇒ `argmin` 全部落在同一下标 ⇒ 恒错/恒对固定子集 ⇒ `16/48 = 0.3333`；
`κ = mean(‖m‖γ)/mean(‖h‖) = inf/inf = nan`。

**★ 为什么 `A109-2` 反而 PASS**：`T-NONE` **不训练**，所以 `no_write` 从未被解开
（`make_stack(no_write=True)` 一路保持）⇒ 这正是「**只有训练臂被污染**」的指纹。
★ `A109-2` 用 `RAWINJ` 复现因而**永远抓不到这个缺陷** —— 它能锁装置，但锁不住「训练后状态」。

**修复**：`run_cell` 在训练后**无条件重封**并断言：
```python
for m in st.mems.values(): m.no_write = True
assert all(m.no_write for m in st.mems.values()), "评测前必须重封 no_write"
```

**新增守卫 `A109-9`（本修订加入）**：**评测期写入次数恒为 0** ——
记录评测前后 `m.write_calls` 之差，要求 `eval_writes == 0`（四臂全查）。
★ 这条是**直接**针对 `DEF-109-02` 的回归守卫：只要再漏重封，它立刻 FAIL，
而 `A109-1` 只会在**恰好**改变判决时才发现。

### 9.2 `DEF-109-01`（我的守卫写错）—— `gamma` 用 float64 比较

`A109-4` 原写 `abs(gamma - g) > 0`，而 `g=0.005` 是 Python float64、`gamma` 是 **float32**：
`float32(0.005) = 0.004999999888241291` ⇒ **恒 FAIL**（不是真违例）。
**修复**：改为 `abs(gamma - float(torch.tensor(g, dtype=torch.float32))) > 1e-9`。
★ 同型风险（`DEF-108-02` 的教训）：**容差按 float64 写却跑在 float32 上**，本项目已犯过一次。

### 9.3 顺带补强：`diverged` 的检查对象不全

`dir104` 的 `diverged` 只查 `D90.W_of(m)`（**记忆矩阵**），而读出训练**只动 `W_q`/`W_o`** ⇒
参数炸到 `inf` 时 `diverged` 仍为 `False`（本轮实测 `diverged=False` 而 `κ=nan`）。
**修复**：`run_cell` 增记 `finite_params = isfinite(Wq).all() ∧ isfinite(Wo).all()`，并由 `A109-4` 阻断。
