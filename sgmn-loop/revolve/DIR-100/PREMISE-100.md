## §1 ★ 代码核对先发现一条**推导缺陷**（`DEF-100-01`，非实验所得）

`task.md` 顶条把候选机制写成「`Wq ∝ Pk`」，并假设「**读在答案位置、键由前一 token 算**」⇒ 只需找一个 **token 偏移 `δ*`**。
**逐行核对本装置代码后，这个前提在本装置里不存在**：

| 事实 | 出处 | 后果 |
|---|---|---|
| **写侧键 = 事实 chunk 全部位置 `hs_in @ Pk` 的 `mean`** | `probe91_kpool.py:89` `k_rule("mean", …)` = `pk_raw.mean(dim=0) * kp_scale`；`pk_raw = pf @ Pk`、`pf = hs_in.reshape(-1,d)`（`dir99/R1_task99.py:176-196` `capture_keys`） | 键由**事实文本**（`chunks[owner.index(fi)+1]`）算出，且是**整段池化**，不是"前一 token" |
| **读侧判据位置 = 问题 prompt 的最后一个 token** | `dir91/R2_task91.py:313` `lg[idx, P-1, …]`，`P = len(prompt_ids)` | 查询由**问题文本**（`f["prompt_ids"]`）算出 |
| **两者是不同序列** | `build_facts` 的 `prompt` vs `build_chunks` 的事实段 | ⇒ `q` 与 `k` 来自**两段不同文本** |

⇒ **结论（推导，非实测）**：`Wq ∝ Pk` 在这台装置上**按构造就不可能对齐** ——
`Pk·c_{prompt末}` 与 `mean(Pk·h_{事实段})` 是两个不同序列的池化量，中间**没有任何 `δ` 可调**。
⇒ 「扫 `δ ∈ {−2..+2}` 找 `δ*`」**在本装置无对象**（`task.md` 原文预设的是"同序列内的位置错位"）。
⇒ **不得**照搬 `Wq=Pk`（`task.md` 已预留此分支：「若任何 `δ` 都不给高对齐 ⇒ 候选机制不成立，须改为…」）。

★ **修正后的前提问题**（本轮真正要问的）：
> **事实键 `k_i` 能否从「问题 prompt 末位」的读出向量 `c_i` **线性解码**，且**跨事实泛化**？**

这个问题**不依赖**任何"位置对应"假设，且它恰好把 `D-129` 的两种可能**分开**：
- 若**能**泛化 ⇒ 线性解**存在**，`Wq` 训练没找到它 ⇒ `acc_held≡0` 是**辨识性/优化**问题（`D-129` §四-5 的假设成立）。
- 若**不能**泛化 ⇒ **不存在**任何线性 `Wq` 能在未训练事实给出正确查询 ⇒ `acc_held≡0` 是**表示性**不可达 ⇒ 读侧线可判结构性关闭。

## §2 前提核测什么（三个量，全部**无训练**、纯几何 + 最小二乘）

对每层 `li`、每事实 `i ∈ 0..31`：

- `k_i` = `capture_keys` 给出的池化键（`(d_k,)`，与真写用的是同一个量）—— 逐字复用 `dir99/R1_task99.py::capture_keys`。
- `c_i` = 前向 `f["prompt_ids"]` 后，`st._hs_in[li]` 在**最后位置 `P-1`** 的读出向量 `(d,)` —— 与 `train_read_task` 的判据位置严格同一位置。

三个读数：

1. **`cos_in`（天花板 / 有效性）**：`M` 用**全部 32** 事实最小二乘拟合，再在**同样 32** 上算 `cos(M c_i, k_i)` 均值。
   ⇒ 「问题末位是否**装了**事实键」的**上界**。若这个都低，问题里就没有该信息，一切讨论无意义。
2. **`cos_tr`（拟合质量）**：`M` 只用 **16 个训练事实**拟合，在**这 16 个**上算 `cos` 均值。
3. **`cos_he`（★ 主读数）**：同一个 `M`（只见过 16 个）在**另 16 个**（`he`）上算 `cos` 均值。

`M` 取**最小范数最小二乘**：`A = Cᵀ(CCᵀ + λI)⁻¹K`（`C`=16×896、`CCᵀ`=16×16，λ=1e-6），
对照 `A_pk = pk_scale·Pkᵀ`（即候选机制本身）。

★ 另记一条**参考**（不进判定）：读同一事实 chunk 的末位 `c` 与 `k_i` 的 `cos`，
用来显示"键与自己的文本是自洽的"（预期高），从而说明 §1 的跨序列问题**不是**键本身坏。

## §3 ★★ 预注册判定规则（**跑之前**写定）

按层取 `mean`，逐层判，再取**多数**（3 层中 ≥2 层同向）。

| 判定 | 条件 | 含义与后续 |
|---|---|---|
| **`INVALID`** | `cos_in < 0.90` | 问题末位**根本没装**事实键 ⇒ 前提**不可测**，不解释 `cos_he`；记 `DEF`，改装置（问题 prompt 必须携带可解码的事实标识） |
| **`P100-A` 线性可泛化** | `cos_tr ≥ 0.90` **且** `cos_he ≥ 0.50` | 线性解**存在** ⇒ `acc_held≡0` 属**优化/辨识性** ⇒ `DIR-100` 正式轮测「把 `Wq` 直接**解**为 `M`（或以其初始化）」的 `wq_solved` 臂 |
| **`P100-B` 线性不可泛化** | `cos_tr ≥ 0.90` **且** `cos_he ≤ 0.20` | **不存在**能泛化的线性 `Wq` ⇒ `acc_held≡0` 属**表示性** ⇒ `Wq∝Pk` 候选**否证**；读侧线判**结构性关闭**，`§7.2-7b` 记 `已足够`（须在正式轮补一条可实现机制的对照臂后生效） |
| **`P100-C` 灰区** | `cos_tr ≥ 0.90` **且** `0.20 < cos_he < 0.50` | 部分可泛化 ⇒ 记录；正式轮改为**定量**判据（信息在但不足 4 选 1 的决策余量），阈值由 §3 表**另开 rev** 冻结 |
| **`P100-D` 拟合失败** | `cos_tr < 0.90` 而 `cos_in ≥ 0.90` | 16 点不足以定出该映射（自由度/条件数）⇒ 前提**仍不可测**；改用 `he` 上的**留一法**（每个事实用其余 31 个拟合）重测 |

★ **纪律**：
- 本表阈值（`0.90 / 0.50 / 0.20`）**跑之前冻结**，见 git/文件时间戳；事后不得改。
- 探针**不产生** `SUCCEEDED`，**不写证据行**（它是卡片的前置条件，不是轮次）。
- 判 `P100-A` 时，`DIR-100` 正式轮的**主判据**仍须预注册为 `Δ_ho`（**与 `W⁰` 的差**，`DEF-99-01`），
  且必须带**对着上限状态训练**的 `w_oracle` 型臂（`DEF-99-04`），阈值**不得**与基座地板 `acc_held(W=0)=0.1250` 撞值（`DEF-99-05`）。
