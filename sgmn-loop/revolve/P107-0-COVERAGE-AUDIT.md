## §1 覆盖度的机械核算（不是估计）

`dir91/R2_task91.py`：

```python
vals = [VALUE_POOL[i % len(VALUE_POOL)] for i in range(N_FACTS)]   # len(POOL)=27, N_FACTS=32
rng.shuffle(vals)                                                  # rng 已被键生成消耗
facts = [{"key": k, "val": v} for k, v in zip(keys, vals)]
```

`rng = random.Random(9091)`，且**键生成在前**（拒绝重抽，消耗 rng 状态），
故必须逐字复现键生成才能复现 shuffle。在 `trainer` 上实算：

| 量 | 实测 |
|---|---|
| 32 个事实的唯一值数 | **27** / 32（`i%27` ⇒ 前 5 个值各出现两次） |
| `tr = facts[0:16]` 的不同值数 | **13** |
| `he = facts[16:32]` 中**答案值已在 `tr` 出现** | **1 / 16 = 0.0625** |
| `he` 中答案值**从未出现**的值 | 14 个：`amber bronze copper coral crimson iron ivory jade panda peach pearl rose silver yak` |

★ 与 `DEF-96-09` 当年**独立实测**的「`M3`: `seen-value=1`、`unseen=15`」**逐位吻合**
⇒ 两条互不依赖的路径给出同一个 `1/16`。

### `DIR-106` 的四种 `n_train`（`tr=facts[0:n]`）

| `n_train` | `he` | 覆盖 | 池化（4 个 split） |
|---|---|---|---|
| 16 | 16 | **1/16 = 0.0625** | 0.1562 |
| 20 | 12 | 1/12 = 0.0833 | 0.2500 |
| 24 | 8 | 1/8 = 0.1250 | 0.2917 |
| 28 | 4 | **2/4 = 0.5000** | 0.3125 |

⇒ 与 `D-136` 报的池化上界**完全一致** ⇒ `DIR-106` 确实吃了同一个坏划分。

### §3.1 `D-133` / `D-135` —— **清白，且它们自己写明了**

两行的边界原文已各自声明测的是**容量**不是泛化：
`D-133`「训练用全部 32 事实 ⇒ 测**容量**、非泛化」；`D-135`「**泛化**（`acc_held`，
16 训/16 留出）本卡**不测**」。⇒ 审计**确认无需任何动作**。

### §3.2 `D-129` —— 判决**正确**，且现在理由更硬

`D-129` 用**上限臂** `w_oracle`（oracle 内容）拿到 `acc_held = 0.0000 < 冻结阈值 0.125`，
据此记 **`UNREACHABLE`**（第三态、不记 PASS/FAIL）—— **这是本项目的正确做法**，
`D-136` 的 `INCONCLUSIVE-ARM-INVALID` 与它同类。

现在可以给出它当时没写出的**定量理由**：覆盖度 **0.0625** ⇒ `acc_held` 上界
≈ `0.0625`（+ 少量猜中泄漏）**本身就低于它自己冻结的阈值 `0.125`**
⇒ `UNREACHABLE` 不只是"上限臂撞了"，而是**度量天花板在阈值之下**。

⇒ **判决保留、不需修正**；★ 但 `D-129` 的**机制归因**「瓶颈是 `Wq` 只训 16 事实」
**不成立**：覆盖度 0.0625 下 15/16 的留出题**任何** `Wq` 都答不出来。

### §3.3 `D-130` —— ★ 判据与归因都要降级

`D-130` 的否证是合取：`Δ_ho = −0.03125 < 0.0625` **∧** `acc_held = 0.0000 < 0.25`。
两个量都建立在**同一条被钉住的度量**上：

- `acc_held` 上界 ≈ 0.0625 **≪ 它自己冻结的阈值 `0.25`** ⇒ **`acc_held < 0.25` 这一支是 CEIL 死臂**；
- `Δ_ho` 是 `acc_held(写) − acc_held(W⁰)`，两项同被钉在 0 附近 ⇒ **差值也钉住**。

⇒ **`H100` 的否证不能作为「查询之后必有缺口」的证据**，应降级为第三态
（与 `DEF-106-13`、`DEF-93R-01`、`A91-11b` 同族）。
★ `D-130` **仍然有效**的部分：`cos_id_he = 1.000000`（查询在 `W` 键空间**精确**）
且 `acc_train` `wq_solved` 0.9375 > `wq_train` 0.7500 ⇒ **查询修好后在训练事实上确实生效**。
⇒ 结论只能收窄为：**「查询在训练事实上可解且生效」**，
**不能**说「查询不是留出集的瓶颈」。

★★ **新增缺陷 `DEF-130-01`（与 `DEF-106-13` 同类，第 4 次同族事故）**：
判据量在冻结前未做结构上界核算，导致阈值（0.25 / 0.125）坐在度量的天花板之上。

### §3.4 `D-125` —— 同源，作为 `D-129/130` 的基线

`D-125` 是这条链的基线（「`acc_held ≡ 0`，`W=0` 得 0.1250」）。同划分、同生成器
⇒ 同覆盖度 0.0625。★ 注意 `W=0` 的 `0.1250 = 2/16` **高于** 0.0625 ⇒ 这部分是
**猜中泄漏**（4 候选 × 3 抽全对，纯猜约 `(1/4)³`，16 题期望 ~0.25 题，观测 2 题属正常波动）
⇒ **`acc_held ≲ 覆盖度` 是 `≲` 不是 `≤`**，与 `D-136` 的 47/48 一致。
