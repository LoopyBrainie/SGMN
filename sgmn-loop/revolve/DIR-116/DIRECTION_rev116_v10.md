## §0 开卡前的前提核查（**它改了题，先记**）

`P115-1` 原文：「把 `ORACLE` 修成真 oracle —— 沿**输出方向**注入（取 `lm_head` 对正确 token 的那一行当 `m`）」。

**开卡前实测**（`dir116/probe116_premise.py` → `dir116/out/premise116.json`，只读、不训练、不改装置）：

| 项 | 读数 |
|---|---|
| `config.tie_word_embeddings` | **True** |
| `lm_head.weight.data_ptr() == embed.weight.data_ptr()` | **True** |
| `torch.equal(lm_head.weight, embed.weight)` | **True** |
| `cos(emb[t], lm_head[t])`（16 个值 token） | **1.0**（min 0.99999994） |
| `‖emb[t]‖₂` / `‖lm_head[t]‖₂`（均值） | **0.425116** / **0.425116** |
| `hidden_size` / `n_layers` / `MOUNT` | 896 / 24 / `[8, 12, 16]` |
| `‖h‖` @ L8 / L12 / L16 / L17 输出 | **14.334** / **15.391** / **25.378** / **30.452** |
| `logit_absmax`（末位） | **16.667**（max 17.251） |
| `‖m‖`（未训练，L8/L12/L16） | 14.291 / 15.591 / 19.275 |
| `‖γ·m‖/‖h‖`（未训练，`γ=1e-3`） | **1.032e-3 / 9.913e-4 / 9.875e-4** |

⇒ ★★★ **两条结论，都是否证性的**：

1. **`P115-1` 的修补是空的。** `lm_head.weight` 与 `input_embeddings.weight` 是**同一张量**
   ⇒ 「取 `lm_head` 那一行」与 `install_ceil` 已在做的 `emb[t]` **逐位相同** ⇒ 照原文开卡，本卡不可能产出任何新读数。
2. **`DEF-115-06` 的诊断错了。** 它说「输入嵌入 ≠ 输出方向」，实测二者 `cos = 1.0`。
   ⇒ `DIR-115` 的 ORACLE 臂**方向是对的**；`acc` 恒等于先验 17/48、且对 `mult` 完全不敏感，真因是**幅度**：
   因为行绑定，`logit_t = ⟨h, emb[t]⟩` ⇒ 注入 `γ·mult·emb[t]` 只把该 logit 推
   `γ·mult·‖emb[t]‖² = 1e-3 × 1 × 0.425² ≈ **1.8e-4**`，而 `logit_absmax ≈ 16.7`
   ⇒ 相对量 `≈ 1.1e-5`，**不可见**。`mult` 从 0.25 到 4 只把 1.8e-4 变成 7e-4，仍不可见 ⇒ 三点全同。

⇒ **因此本卡改问一个更强、也更有判别力的问题**（不是换题，是把 `P115-1` 的真意抽出来）：

> **真 oracle 要多大才"咬得动"？通道到底能不能传递答案？**

★ **同时更正 `D-146` 的一处解释（不追认，`D-146` 原文不改）**：`D-146` §2.6 说
「同量级的注入**可以**做到无害（`emb[correct]` 完全中性）… 而学到的 `m` 在**同一量级上**是有害的 ⇒ 缺陷在学到的方向里」。
★★ 该推理**混淆了 h-空间与 logit-空间的幅度**：学到的 `m` 与 oracle 的 `‖γ·m‖/‖h‖` 都是 `≈1e-3`，
但学到的 `m` 是**宽带**扰动（896 维全参与，`‖δ logits‖ ≈ γ‖m‖·‖W‖₂ ≈ 0.02`），
oracle 是**窄带**（只动一个 logit，`γ‖w_t‖² ≈ 1.8e-4`）⇒ **在 logit 空间差约 100×**。
⇒ `D-146` 的「同量级 ⇒ 无害」**不成立**；本卡用跨 5 个数量级的 `mult` 网格把这条补回来。

## §1 主假设与否证条款

**测量对象**：`SPLIT` 划分（`class_seen_frac_held = 1.0000`）、`d=600` 训练格上的
**留出集** 48 项（16 值 × 2 事实 × 48 候选/项，单 token 候选），基座先验 `ACC0 = 17/48`
（`D-146` 实测；本卡 `A116-2` 现场复算断言）。

**自变量**：`ORACLE` 臂的注入倍率 `mult`（`install_ceil` 的 `ceil_mult`）。
有效注入 = 每个 `MOUNT` 层各加 `γ_tr · mult · emb[t]`。
**网格（9 点，跨 5 个数量级）**：
`MULT = (1, 10, 100, 300, 1000, 3000, 10000, 30000, 100000)`。
★ 该网格**括住了预测的转变点**：由 §0 的算式，`Δlogit_t = n_mount·γ·mult·‖emb‖²`，
取 `‖emb‖²=0.1807`、`γ=1e-3`、`n_mount≈3` ⇒ `Δlogit_t ≈ 5.4e-4 · mult`。
令其与典型 logit 间隙（`logit_absmax≈16.7`，间隙量级 `O(1)`）可比 ⇒ 预期转变在 `mult ~ 1e3–1e4`。
★ `mult=1` **就是 `D-146` 的 ORACLE 臂**（锚点，必须逐位复现 `17/48`）。

### §1.1 `H116`（主假设）
**存在网格内的 `mult`，使真 oracle 的留出准确率 ≥ 36/48（= 75%，先验的 2.12×）** ——
即「**通道能传递答案；若学不到，缺陷在学到的那一侧，而不是通道的幅度极限**」。

### §1.2 否证条款 `F116`（三者**互斥且穷尽**，按序求值）
1. **`C116-CHANNEL-CANNOT-DELIVER`**（**`H116` 被否证**）：对**全部** 9 个 `mult`，`acc ≤ 18/48`
   （= `ACC0 + 1/48` 容差）⇒ **把注入放大到 `‖γ·mult·m‖/‖h‖ ≈ 3.0`（h 的 3 倍）仍不能传递答案**
   ⇒ **通道本身无法传递答案**（架构级强否证）。
2. `C116-INCONCLUSIVE-BAND`（**不确定**）：存在 `mult` 使 `19/48 ≤ acc ≤ 35/48`，且无一点 `≥36/48`。
   ★ 该带**不是**判据通过；须报带内 `mult` 与曲线形状。
3. **`C116-CHANNEL-DELIVERS`**（**`H116` 证实**）：存在 `mult` 使 `acc ≥ 36/48` ⇒ 计入 `SUCCEEDED`。

★ **判据的严格性来源**：① 网格跨 5 个数量级，覆盖 `‖γ·m‖/‖h‖` 从 `3e-5` 到 `3.0`；
② 否证条款要求**全部 9 点**都 ≤18/48，任一点越过即不能判"不能传递"；
③ `F116` 的「带宽」与「升高」两侧都在判据里，**不存在"只看有没有涨"的空洞**。

## §2 MVP 标准（**settles the question 的最小产物**）

**MVP = 一张 9 行 × 1 列的 `mult → acc` 表 + 一条 `Δlogit` 的解析—实测对照 + 一个 logit-bias 天花板。**

1. **主表**：`ORACLE` 臂在 9 个 `mult` 上的 `acc`（项/48），并与 `mult=1` 锚点（`17/48`）逐位比对。
2. **解析—实测对照（worked example，§3）**：在小 `mult` 处实测「注入正确 token 后该 logit 的增幅 `Δlogit_t`」，
   与 §0 的闭式 `n_mount·γ·mult·‖emb[t]‖²` 比对 ⇒ **验证"方向对、只是太小"这条前提本身**。
3. **天花板守卫**：`LOGBIAS` 臂（直接对正确 token 的 logit 加 `β`）在 `β ∈ {0.5, 2, 10}` 上必须达到 **48/48**
   ⇒ 证明评测器**对"正确的 oracle"有反应**；若连这个都到不了，问题在评测器而不在通道。
4. **训练/种子无关性守卫**（本卡省掉重训的**合法依据**，见 §4）。

**最小化理由**：`install_ceil` 覆写 `m.read` ⇒ **整个读路径被替换**，`Wq/Wo/W` 不参与
⇒ 该臂对**训练与种子都是恒等的**。故本卡**不重训**（除 1 格作对照），
但**不假设**这一点 —— 用 `A116-3` **实测断言**（若不成立则退回 3 seed × 重训）。

## §3 测量对象与**具体算例**（开跑前必须对上一个）

**算例（`mult=1`，`L16`，`SPLIT` 第 0 项的 16 值 token 之一）**：

- `‖emb[t]‖² = 0.425116² = 0.180724`
- 单层单点注入增量：`γ·mult·‖emb[t]‖² = 1e-3 × 1 × 0.180724 = **1.807e-4**`
- `n_mount = 3` ⇒ 一阶估计 `Δlogit_t ≈ 3 × 1.807e-4 = **5.42e-4**`
- 参照：`logit_absmax = 16.667` ⇒ 相对量 `3.3e-5`
- ⇒ **预测**：`mult=1` 的 `acc` 与"无注入"**逐项相同**（`D-146` 实测 `0.3541666 = 17/48`，**相符**）
- ⇒ **预测的转变点**：`Δlogit_t` 需 `O(1)` ⇒ `mult ~ 1e3–1e4`
- ⇒ **预测的大 `mult` 失效点**：注入达 `‖h‖` 的 3 倍（`mult~1e5`）后 RMSNorm 会重标定
  ⇒ 大端**可能**出现"再涨后崩"，本卡**报告全曲线**，不预设单调。

★ 算例的**可证伪性**：若实测 `Δlogit_t` 为**负**或与 `5.42e-4` 差出 10× 以上
⇒ 「方向对」这条前提**不成立**，`A116-5` 必须报红并**阻断正式轮**。

## §5 判据求值顺序（逐条求值，**不短路**）

1. `plan` 缺格 / 读数不全 ⇒ `C116-INCOMPLETE`（**不得**记 PASS/FAIL）。
2. 任一 `A116-*` 阻断失败 ⇒ `C116-GUARD-FAIL`。
3. `LOGBIAS` 未达 `48/48` ⇒ `C116-HARNESS-CEILING-FAIL`（评测器无效，**不判通道**）。
4. 存在 `mult` 使 `acc ≥ 36/48` ⇒ **`C116-CHANNEL-DELIVERS`**（`H116` **证实**，`SUCCEEDED +1`）。
5. 全部 9 点 `acc ≤ 18/48` ⇒ **`C116-CHANNEL-CANNOT-DELIVER`**（`H116` **否证**，不计分）。
6. 否则（有 `19–35/48` 且无 `≥36/48`）⇒ `C116-INCONCLUSIVE-BAND`（报带内 `mult`，不判证实/否证）。

## §7 证据边界（**不可**外推）

1. ★★ **本卡修正 `DEF-115-06`**（方向错 → **幅度小**）与 `D-146` §2.6 的"同量级"表述（h-空间 ≠ logit-空间）。
   `D-146` 原文**不改**（append-only）；更正落在本卡、`D-147`、`decisions/`、`ENV-NOTES`（追加）。
2. **`W` 固定、无写入**（`train_read_frozen`）⇒ 不得说「关联记忆强度/容量/遗忘」。
3. **单点 primitive、16 值 × 2 事实、单 token 候选、48 项** ⇒ 不得外推别的池规模。
4. **`γ` 从未被训练**（`D-146` 实测取值集 `{0.001000000047}`）⇒ 本卡的 `mult` 是**评测期覆写**，
   不得推断 v2.4 §4 的学习型 γ 会选错值。
5. ★★ **`mult` 是"任意放大"，不是 v2.4 的可用配置**：`mult ≫ 1` 意味着注入量级远超训练时的量级。
   本卡测的是**通道的能力上限**（"能否传递"），**不是**"SGMN 在正常增益下能否有用"。
   若 `C116-CHANNEL-DELIVERS` 成立，只能得出「通道不是瓶颈」，**不得**读成「调大 γ 就能解决」。
6. **`LOGBIAS` 臂绕过通道**（直接改 logits）⇒ 只作评测器天花板，**不得**当通道能力的证据。
7. **不改** `§7.2-7b` 的 `不足` 状态本身（本卡只补"能力上限"这一维）。
8. 不下复合律（`P114-1`）、不动 Freeze A–E。
