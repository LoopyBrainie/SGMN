## §11 修订原因：`q0` 的总体写错了，是**手算例把它抓出来的**

rev 1.0 §2 把 `J120-5` 的参照写成：

```
q0 = mean(1/|U_i|)     （rev 1.0 的隐含总体：n_seen ≥ 1 的所有项，即"有机会逃逸"的项）
```

而 `q = E_esc_ok / escape` **条件在"真的逃逸了"上**。两个统计量的**条件事件不同**：

- `q` 的分母 = **实际逃逸**的项（`escape`，实测 42 项）；
- rev 1.0 的 `q0` 若在**有机会逃逸**的项（`n_has_seen` = 414 项）上取均值 ⇒ 分子分母condition 不一致
  ⇒ `q ≥ 2·q0` 这个比较**会把总体搞错**，而且偏向**低估** `q0`（因为未逃逸的项里 `|U_i|` 的分布不同）。

★ **是手算例抓到的**：rev 1.0 §3 我手算的 `q0 = (1/2 + 1/3 + 1/1)/3 = 0.6111`（在 `{i0,i2,i3}` 上取均值），
但该例里**只有 `i2` 真的逃逸** ⇒ 按 `q` 的同条件总体，`q0` 只能取 `i2` 的 `1/|U|=1/3`。
两者对不上 ⇒ 说明**卡片散文与正确口径不一致**。这正是 round standard 要求"手算例必须被断言"的理由：
　**如果手算例只写在文档里而不被 assert，这个错会一路带进正式跑。**

### §11-1 更正后的定义（**冻结，取代 rev 1.0 §2 的 `q0` 那一行**）

```
q0 = mean over { i : escape_i } of ( 1 / |U_i| ),   |U_i| = 4 − n_seen_i
```

即：**与 `q` 完全同总体**（只看真的逃逸了的项），`|U_i|` = 该项里未见候选的个数（含正确项）。
逐字对应代码 `mech120.q0_of()`（它遍历 `part["escape_mask"]`）。

★ **语义**：条件在"逃逸"上 ⇒ 模型已放弃所有见过的干扰项，只在 `|U_i|` 个未见候选里"盲选"时命中正确项的概率。
`q` 显著高于 `q0` ⇒ 逃逸后的选择**不是盲选**，而带有值身份级的偏好（这正是 `J120-5` 要测的）。
