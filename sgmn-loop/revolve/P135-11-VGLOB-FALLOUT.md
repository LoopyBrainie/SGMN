## §1 ★★★ 精确机制：不是「glob 缺陷」，是**分子分母用了不同的人口**

`P135-10` 把根因称为「`_v` 文件名 glob」。**这个说法不够准确** —— 读完 `--probe-u4` 源码后要更正为：

```python
nums, skip = canonical_nums()          # ★ 分母：105（P1 总体，含 19/20）
...
print(f"...规范目录 {len(nums)} 个")     # 打印 105
for n in nums:
    ctx = Ctx(n)
    if not ctx.card:                   # ★★★ 就是这一行
        continue                       #   19/20 无 `_v` 现行卡 ⇒ 静默跳过
    cands = sorted(... ctx.cdir.glob(f"DIRECTION_rev{n}*.md") ...)
```

实测：`canonical_nums()` = **105**，但 `[n for n in nums if not Ctx(n).card]` = **`[19, 20]`**
⇒ **实际被扫描 = 103**，而**打印的分母仍是 105**。

⇒ ★★★ **分母取 A 集合（105）、分子取 B 集合（103）** —— 这才是缺陷的准确形状。
★ 所以「97/105」的真相是：**在 103 张里找到了 97 张（缺 6 张）**，
`103 − 97 = 6` **恰好等于**它打印的缺失清单长度 ⇒ **那个清单是对的，只是分母多报了 2**。

### §1-1 ★★ 还有第二层：`DIRECTION_rev{n}` 把**目录号**当**版本号**

glob 用 `DIRECTION_rev{n}*.md`，其中 `{n}` 是**目录号**。但对 `DIR-19`、`DIR-20` 这**不成立**：

| 目录 | 卡片文件 | 文件名里的数字是 | `DIRECTION_rev{n}` 能否匹配 |
|---|---|---|---|
| `DIR-19` | `DIRECTION_rev15.md` | **版本 15** | ✗（`rev19*` 不存在） |
| `DIR-20` | `DIRECTION_rev11..16.md` | **版本 11–16** | ✗（`rev20*` 不存在） |
| `DIR-23` | `DIRECTION_rev23*.md` | 版本（与目录号巧合相等） | ✓ |

⇒ ★★ **两层缺陷同源**：都假设「卡片文件名 = `DIRECTION_rev{目录号}_v{版本}.md`」。

★★★ **只删掉 `if not ctx.card: continue` 修不好，而且会更糟**（实测，glob 未换）：

| 只删 `continue` | 容器可定位 | 缺失 | 广义 | 任何此类段都没有 |
|---|---:|---:|---:|---:|
| 结果 | **97**（不变） | **8**（`19,20,23,46,47,48,49,87`） | **101**（不变） | 4（不变） |

⇒ ★★★ **这才是最危险的一格**：`97 + 8 = 105`，**看起来完全自洽** —— 一个只看
「容器 + 缺失 = 分母」的审计会**通过**。但 `DIR-20` 明明六个副本全有「★ 证据边界」段，
它被**误报成缺失**；而 `DIR-19` 是**真缺**。
⇒ ★★ 也就是说：**修第一层会把「分母多报 2」换成一个「假自洽」**，比原缺陷更难发现
（原来的 `97 + 6 = 103 ≠ 105` 至少还露着马脚）。
⇒ ★★★ **正确修法只能是 `_u4_card_files(d)`（任意名）** —— 即 `P135-10` 新增的那个 helper；
两层必须一起修。

## §3 ★★★ 对 `P135-10` §12 的**自我更正**（上一轮我的错）

### 错在哪

`P135-10` §12 复算条款普查时，我写的是：

```python
cc._u4_sections(t, cc._U4_SEC_ALT)      # ★ 广义五词
```

但 `--probe-u4` 用的是 **strict**（默认 `kws=('边界',)`）：

```python
for ti, lines in _u4_sections(t):        # ★ 默认 strict
```

⇒ ★★★ **口径错了一级**。四格全算，立刻见分晓：

| 段口径 | 副本规则 | 条款 | `R-B` | `R-C` |
|---|---|---:|---:|---:|
| ★ **strict** | **现状** | ★★★ **944** | ★★★ **447 = 47.4%** | ★★★ **159 = 16.8%** |
| strict | 任意名 | **959** | **456 = 47.5%** | **159 = 16.6%** |
| 广义 | 现状 | 983 | 463 = 47.1% | 162 = 16.5% |
| 广义 | 任意名 | 998 | 472 = 47.3% | 162 = 16.2% |

⇒ ★★★ **`strict × 现状` 一格把报告的三个数（944 / 447=47.4% / 159=16.8%）全部精确复现**。
⇒ ★★ 而上一轮我用的是 `广义 × 现状` = **983 / 463 / 162** —— 与 944 **差 39**，我却报成了 945。
★ 那是另一个巧合：上一轮我的去重键是 `' '.join(c.split())`，与 `_u4_clauses` 的原始文本不同，
**两个错误互相抵消成了「差 1」**。

### ★★★ 这一节真正的教训（比数字重要）

> **「差 1」比「差 100」更危险。**

上一轮我看到 945 vs 944，把它记成「去重键的细微差异，**未逐条追究**」并列进了证据边界 ——
那个处理**诚实**，但**代价估价错了**：追究它只需要**再跑一次**，我却把一个
「口径可能错了一整级」的信号，归档成了「无害的小数点」。
⇒ ★★★ **新纪律**：**当自算值与报告值只差 1–2 时，不得归因为「去重/口径的细微差异」，
必须先穷举「段口径 × 副本规则」四格** —— 因为**小的差异最常来自结构性的口径错位，而不是噪声**。

### 更正后的正确数字

| 现状条款 | 945 | **944** |

| 绝对数偏差 | 「偏低约 4.5%（44 条）」 | ★ **偏低 1.6%（15 条）** |

⇒ ★★ **好消息**：`P135-10` §12-1/§12-2 的**结论**（率稳健、绝对数不稳健；率可引用、绝对数须改）
**一字不变，且这次是被正确配方支撑的**。★ 但**幅度**从 4.5% 缩到 1.6%，引用时应改用后者。
