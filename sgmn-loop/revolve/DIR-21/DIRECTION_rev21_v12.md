## 0. ★ 本 rev 的三条澄清（**都是「不改阈值、只钉口径」**）

### 0.1 澄清一：扫描的横轴必须是 **在线步数**，不是文档数

- **问题**：rev 1.1 的 K 扫描按**文档数** ⇒ ⇒ 不同粒度的「每篇步数 m」不同
  ⇒ ⇒ 同一个文档数在 `G_tok`（m=136）与 `G_doc`（m=2）下代表**完全不同的步距**
  ⇒ ⇒ **两条曲线不可比** ⇒ ⇒ 「衰减只认步数」这类判据**根本无法计算**。
- **澄清（不改阈值）**：横轴 = **在线步数 `step`**；读出点 = `step = s` ⇒ 已写文档数
  `D(s) = floor(s / m) + 1` ⇒ ⇒ **同一横轴对所有臂表示同一「年龄」** ✔
  ⇒ ⇒ H21-2 / H21-3 / H21-4 的曲线比较**在步轴上进行** ✔。
- **扫描网格**：`STEP_GRID_FULL = [0,16,32,48,64,96,128,192,256,384,512,768,1024]`（13 点）·
  smoke 用 `[0,16,32,48,64,96,128,192,256]`。
- **为什么上界是 1024 步**：① 解析视界 `1/(ηλ) = 200 步` ⇒ 1024 步 = **5 倍视界** ⇒ 足以看到半衰期；
  ② `G_doc`（m=2）在 1024 步处要写 **513 篇** ⇒ 评测文档数取 **520** ⇒
  ⇒ 语料里的码池（4000 个稀有单 token 词）够用（720 篇 × 2 个码 = 1440 ≪ 4000）✔。

### 0.2 澄清二：**m = 每篇的写规则触发总次数**（目标文档 + 干扰文档）

- 一篇文档的写入 = **目标文档的一次前视** + **干扰文档的一次前视** ⇒ ⇒
  每篇的触发总次数 = `2 × (每篇前视的触发数)`。
- ⇒ ⇒ **m 的取值**：`G_tok` **136** · `G_seg4` **8** · `G_seg4_alt` **8** · `G_tok_rate` **136** · `G_doc` **2**。
- ⇒ ⇒ 由此得到两条**解析预测**（H21-1b / H21-3 的对照）：
  ① **容量峰值** `K* ≈ N_ENTRIES / m` ⇒ 2 / 32 / 32 / 2 / 128 篇 ⇒ ⇒ H21-1b 的比值预期 ≈ **64×**（阈值 8× 保守）；
  ② **每篇累积衰减** = `(ηλ)·m`：`G_tok` = 0.05·0.1·136 = **0.68**；
  `G_seg4` = 0.05·0.1·8 = **0.04**；`G_tok_rate` = 0.05·(0.1/17)·136 = **0.04**（**与 `G_seg4` 相同** ✔）。

### 0.3 澄清三：**读出必须逐条目进行**；配对的 NLL 口径用**目标条目**

- **问题**：粗粒度下**目标条目（码 token）可能根本没被写进去** ⇒ ⇒ 读它等于问一个
  **没写过的答案** ⇒ ⇒ NLL 会**平凡地**变差（那是「答案不在记忆里」，不是「粒度的影响」）
  ⇒ ⇒ 判据会把「任务不可作答」误读成「粒度更差」。
- **澄清（不改阈值）**：
  ① 写规则的触发位置集合 = `{S, 2S, ...} ∩ [1, L−1]` **∪ {L−1}** ⇒ ★ **目标位置 `L−1`（码 token）必写**
  ⇒ ⇒ **每个粒度下任务都可作答** ✔；
  ② 读出**逐条目**进行：条目 `t` = (前缀 `ids[:t]`, 码 `ids[t]`, 真值槽 `count_before + 写入序号`)
  —— **真值槽用精确槽号映射**（沿用 D54 的做法）✔；
  ③ **H21-1 的 NLL 口径 = 目标条目**（每个臂都写它 ⇒ **严格配对** ✔）；
  **容量与保持的口径 = 该臂写下的全部条目**（`n_ret` = 可检索条目数，`R` = 归一化内容保真）✔。
- **附带**：`G_seg4_alt` 改为 **stride = 18**（`{18,36,54}` ∪ `{68}` = 4 次 ⇒ **m 与 `G_seg4` 相同**）
  ⇒ ⇒ 「同一步数、不同调度」的控制臂成立 ✔（若沿用 stride=17 + 段首规则，目标条目不会被写 ⇒ 不可用）。
