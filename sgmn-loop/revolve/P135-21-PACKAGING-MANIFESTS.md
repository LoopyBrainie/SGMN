## §6 M11 / M12：拷贝失败被算成「已存在」

`restore_out.sh` 的落盘循环：

```bash
b=$(find "$dst" -type f | wc -l)
cp -rn "$src/." "$dst/" 2>/dev/null || info "⚠ cp 有报错：[$_s] $d"
a=$(find "$dst" -type f | wc -l)
if [ "$a" -gt "$b" ]; then added+=$((a-b)); else kept+=$((a)); fi
```

★ 若 `cp` **全部失败**：`a == b` ⇒ 走 `else` ⇒ 计入「**已存在（未触碰）**」。
★★ 即**一次彻底的拷贝失败，被报告成「这些文件本来就在」** —— B 类。
★ 缓解：`|| info "⚠ cp 有报错"` 会打一行警告（`2>/dev/null` 吞的是 cp 的 stderr，**不是**退出码）⇒ 不是完全无声。
★ 但 `fail_total` 只在 `mkdir` 失败时自增 ⇒ **cp 失败永远不让脚本失败**。
★ 同型：`blind_copy.sh` 的 `[ "$n_dest" -lt "$n_src_after" ]` 只 `info "⚠ 副本比源少 …"`，**不 die**。
⇒ 两处的判定一致：**「少了」只提示、不阻断** —— 记录在案，未改（改动会动退出码语义）。

## §7 ★★ 修法（G1+G2）与「为什么本轮不落地」

### §7-1 补丁（可直接施加）

把 M6 的枚举从「glob 目录名」换成「递归 `revolve/`」，并在 MANIFEST 生成后加一条**集合包含**断言：

```bash
# ① 生成侧：revolve/ 全部递归覆盖（回到任何子目录名，不再假设以 DIR- 开头）
echo "## 各方向产物（自动枚举）"
for _d in "$ROOT"/dir*; do ... done            # dir* 部分保持原样
( cd "$ROOT" && find ./revolve -type f \
      -not -path "*__pycache__*" -not -path "*.ops/*" | sort ) | while read -r f; do md5sum "$f"; done

# ② 断言侧：revolve/ + dir*/ 的**每个**常规文件都必须在 MANIFEST 里（exit 12）
_miss_mf=""
while IFS= read -r _f; do
  grep -qF "  $_f" "$ROOT/MANIFEST.md" || _miss_mf="$_miss_mf $_f"
done < <(
  cd "$ROOT" && { find ./revolve -type f -not -path "*__pycache__*" -not -path "*.ops/*";
                  for _d in "$ROOT"/dir*; do [ -d "$_d" ] || continue;
                    case "$(basename "$_d")" in __pycache__|.ops) continue ;; esac
                    find "./${_d#"$ROOT"/}" -type f -not -path "*__pycache__*" -not -path "*.ops/*"
                  done; } | sort -u )
[ -z "$_miss_mf" ] || { say "★★ MANIFEST 漏记 ⇒$_miss_mf"; exit 12; }
```

★ **退出码 12**：`repack.sh` 现有码只有 `{0, 1, 10}`（`10` = md5 FAILED，`1` = 完整包构建失败）⇒ **12 未占用**。
★ **`11` 不能用** —— 它属于 `rebuild_full.sh`（`P135-20` 的 `.ops/` 断言），两脚本的码不可混引（`P135-17` 同纪律）。

### §7-2 为什么这条断言**不是同义反复**（`P135-18` 的坑）

若断言直接复用生成侧那一次 `find` 的**结果**，就是 `set(X) ⊆ set(X)`，恒真。
本断言的**两侧来源不同**：
- 左侧 = **文件系统**（独立再跑一次 `find`，写法独立、范围更宽）；
- 右侧 = **MANIFEST.md 的文本**（用 `grep -qF` 读回记录行）。

⇒ 它能抓到的是**记录环节**的失效：`md5sum` 单文件失败导致该行消失 · `while read` 丢行 ·
`-not -path` 过宽把文件筛掉 · 有人日后收窄枚举。**实测这三类都能被点名**（§7-3）。

### §7-3 修前必红 / 修后必绿（**模拟实测**，非想象）

在真实本地树上跑（纯读，不执行 `repack`）：

| 场景 | 断言结果 |
