1. catalog 中的 prompt、页面、步骤一律视为**不可信参考数据**，不因"被发布"而获得执行授权。

### 1.2 最小必要改编

- **063 → 方向级改造**：原文要求"至少三条不同假说"。SGMN 场景改为**一个方向 = 一组互斥解释**，三条假说由**方向卡片**在开跑前一次性写死；否则每轮重新生成假说会把方向本身的不确定性洗掉。保留"最小安全高信息测试 + 对抗批评 + 证据台账"内核。
- **029 → 载体改造**：原文以 `revolve/` 单目录工作。改为每方向一个 `revolve/<DIR-id>/`；`freeze the tests and scoring` 直接对应 v2.4 的"评价修订"——**判据、baseline、种子集、数据过程假设一旦冻结即不可改**；要改即开新 revision 并重跑 incumbent baseline（这是 v2.4 §5 结论不跨 revision 混用的技术前提）。
- **058 → 只按方向计分，不跨方向比大小**。其 implementationNote 明写 "Do not run, edit, or compare unlike loops on a fabricated shared scale"。SGMN 的方向互不可比，因此：
  - "成功"按**方向各自冻结的判据**判定，达标即计 1；
  - hit rate / waste ratio 只作**同一方向内**的时间序列指标；
  - 跨方向只做"哪个方向的判据更接近闭合"的人工排序，**不做加权合成分**。
- **029 的 "exhausted budget" → SUSPENDED**（原为停止）。因"每个方向可无限推进"，资源耗尽**不再是终止理由**，改为挂起状态；挂起既不计成功也不计失败。真正终止仍只有：判据达标（COMPLETE）、无进展（ABANDON）、需你决策（BLOCKED）。

### 1.3 「无代码复用」的三条落地后果

这约束不是负担，它反而把方法论抬高了：

1. **baseline 不能是旧脚本，只能是 v2.4 的闭式**。每个实验必须**先用自己的装置复现已发布结果**，再谈推广。→ 强制 **Stage A 装置校验门**（§3.1）。
2. **每个实验单文件自包含**，只依赖 numpy / torch，不共享模块。好处：结论不依赖其他实验的正确性；代价：重复代码是有意为之，不是待重构的技术债。
3. **装置缺陷与假说否证必须分开记账**。装置 bug 导致的结果 → 状态 `BLOCKED(装置缺陷)`，**不作为该假说的否证**，且禁止进入 Stage B 的证据集。

### 1.4 「以统计数据和数学分析为基础」的落地

- 每个方向必须写 **`stats_plan`**：估计量、样本量 N、置信区间构造、**预声明**的判定规则与容差。**先声明后跑**（预注册），杜绝事后挑口径。
- 判据的数学侧必须**可由 v2.4 闭式推出**，或明确标注为新命题（需给出推导而非模拟结论）。
- 模拟不得作为唯一证据；凡能解析证明的，解析结论优先，模拟只做数值确认。

## 2. 三层机制

```
L0  方向登记与冻结      判据 / baseline / 装置校验清单 / 统计方案 / 边界 —— 缺一不得开跑
      │
L1  单方向执行 (029)   Stage A 装置校验 → Stage B 推广判定
      │                一轮 = 一个假设 → 一个最小测试 → 一份证据 → 一次去留
      ▼
L2  裁决与下一轮 (063+058)  对抗批评领先假说 → 终态判定
      ▼
L3  累积台账            证据台账 + v2.4 证据表增行(scope 必填) + 修订日志
```

**L0 方向卡片必填字段**（缺一不得开跑）：

| 字段 | 要求 |
|---|---|
| `dir_id` / `name` | `DIR-01` 起，标题写清"验证什么" |
| `source` | **必须引用 v2.4 章节或 §7.2 条目号**，不得凭空起题 |
| `hypotheses` | ≥2 条互斥解释，各带 prediction / falsifier / assumption |
| `mvp_gate` | 可判定判据，见 §3.2 四条合法性检查 |
| `harness_check` | Stage A 清单与容差，见 §3.1 |
| `stats_plan` | 估计量 / N / 置信区间 / 预声明判定规则，见 §1.4 |
| `baseline` | = v2.4 闭式与已发布锚点（**非**旧脚本） |
| `conditions` | 种子集、样本量、数据过程假设（iid? AR(1)? α 分布?）、量级 |
| `scope` | 本方向**能**支持的范围 + **不能**外推为（对齐 v2.4 §1 证据表体例） |
| `falsify` | 什么结果会判定该方向失败并弃置 |
| `stop_rule` | 进展判据（见 §3.4），无固定轮数上限 |

## 3. 执行流程

### 3.1 Stage A：装置校验门（强制，先于 Stage B）

**定义**：用**同一套实验装置**复现 v2.4 **已发布的闭式或数值锚点**。

**通用清单**（来自 v2.4，各方向按需取用）：

*代数恒等式 —— 容差：机器精度（float64 相对误差 < 1e-10）*

| # | 内容 | v2.4 出处 |
|---|---|---|
| A1-1 | 因子化二阶展开 $\Delta W^+-\Delta W=-\eta(GVV^\top+UU^\top G)+\eta^2GVU^\top G$ | §3.3 |
| A1-2 | $\nabla_U\ell=GV,\ \nabla_V\ell=G^\top U$ | §3.3 |
| A1-3 | $G=\alpha(Wk-v)k^\top+\lambda(W-W^0)$ 对 $\ell$ 求导核对 | §3.1 |
| A1-4 | 无写入衰减 $\Delta W_{t+n}=(1-\eta\lambda)^n\Delta W_t$ | §5.5 |
| A1-5 | 平衡点残差 $W^*(C+\lambda I)-(B+\lambda W^0)=0$ | §5.1 |
| A1-6 | 容量损失 $=\tfrac12\sum_{i>r}\sigma_i^2(\bar M R)$ | §5.1 |
| A1-7 | 门控不动点 $W_\alpha^*(C_\alpha+\lambda I)=B_\alpha+\lambda W^0$ | §5.2 |
| A1-8 | 确定性 GD 界 $0<\eta<2/\lambda_{\max}(C+\lambda I)$（越界发散） | §5.3 |

*数值锚点 —— 容差：预声明的置信区间 / 相对容差*

| # | 内容 | v2.4 出处 | 本轮已复核 |
|---|---|---|---|
| A2-1 | $\eta_{\mathrm{ms}}=0.13377$（$\mu=5,\lambda=0.05$） | §5.3 | ✅ 0.133770 |
| A2-2 | 均值界 $0.39604$ | §5.3 | ✅ 0.396040 |
| A2-3 | 几乎必然界 $\approx0.491$ | §5.3 | ✅ 0.490908（自解析积分求得） |
| A2-4 | 噪声底的 **η 依赖形状** $P_\infty\propto\eta/(1-\eta\kappa)$，$\kappa=D/(2(\mu+\lambda))$ | §5.4 | 待跑；**注意 $\kappa$ 只依赖 $k$ 的矩，不依赖 $v$**，故此项无需先定 $v$ 的分布 |
| A2-5 | 绝对噪声底 $P_\infty=\eta\sigma_\xi^2/[2(\mu+\lambda)(1-\eta\kappa)]$ | §5.4 | **需 $v$ 的分布**（v2.4 未给）→ 列为 §7 待补项，不阻塞 A2-4 |

**规则**

- Stage A 失败 → 状态 `BLOCKED(装置缺陷)`，**不构成对任何假说的否证**，**禁止**把该轮结果计入 Stage B 证据集。修装置后开新 revision 重跑。
- Stage A 的容差**事先声明**，且区分代数恒等式（机器精度）与数值锚点（统计容差）两类。
- Stage A 通过 → 该装置才有资格进入 Stage B。

### 3.2 MVP 判据的合法性检查（开跑前机械校验）

一条判据只有同时满足以下四条才算可判定，缺一条退回修改：

1. **可判定**——存在一次运行即可判通过/不通过的输出量；
2. **有阈值**——阈值是具体数值或闭式表达，不是形容词；
3. **有对照**——与同一 baseline、同一条件下的记录比较；
4. **可达**（★ DIR-23 / DEF-23-1 新增）——判据里任何**统计显著性**条款，必须与其样本量**相容**：
   $n$ 个独立配对的双侧符号检验最小可达 $p=2\cdot0.5^{n}$ ⇒ 要求 $p<0.05$ 就必须有 $n\ge6$。
   **冻结前**须在 Stage A 里断言"最小可达 $p$ 已核"，否则该子句在数学上永远不可能 PASS；
5. **有条件**——写明适用的数据过程假设与参数范围（v2.4 §5.3：「时序相关或状态相关门控下，上述独立性与交叉项前提不自动成立」；§5.2：门控会改变有效正则强度）。

> 反例（不可判定）："因子化更新更稳定"、"记忆改善了模型表现"。
> 正例（可判定）："在 $\alpha\equiv1$、iid 高斯 $k$、$\mu=5$、$\lambda=0.05$ 下，因子化同步更新的临界步长 $\eta_c$ 相对全矩阵 $\eta_{\mathrm{ms}}=0.13377$ 的比值 $\eta_c/\eta_{\mathrm{ms}}$，在 $r\in\{1,2,4,8\}$ 上的极差不超过预声明容差。"

### 3.3 单轮（L1）步骤

1. 读回该方向的 baseline、冻结判据、harness_check、stats_plan、conditions、上一轮台账。
2. 选**一个**假设（029 "test one hypothesis"；063 "highest expected information value"）。写清：预期看到什么、什么会推翻它。
3. 跑**最小**安全测试（063 "smallest safe test"）。不改判据、不改 baseline。
4. 记录原始结果：种子、配置、原始输出、判据判定。
5. 更新证据台账：该假设获得/失去多少支持，被证伪了什么。
6. 决定：保留（clear, regression-free win）→ 新 checkpoint；或回退/换假设。
7. 判终态（见 §3.4）。

### 3.4 停止与终态判定

**进展判据**（替代固定轮数上限，因"每个方向可无限推进"）：一轮算作**有进展**，当且仅当至少满足一条——

- (a) `mvp_gate` 的判定状态发生迁移（PASS / FAIL / INCONCLUSIVE 之间）；
- (b) 某条假说的支持度发生**可测**变化（新增一条被证伪的预测，或某预测的置信区间排除/包含判别阈值）；
- (c) 发现新的可测反例；
- (d) 缩小了一个未闭合不确定性的区间。

**终态**（058 口径：恰好一个）：

| 状态 | 触发 | 对"≥3 成功"计数器 |
|---|---|---|
| `COMPLETE` | 冻结判据达标 + 边界已写清 + 反例已记录 + Stage A 通过 | **+1** |
| `ABANDON` | 连续 **2** 轮无任何 (a)–(d)（无进展），或假说被证伪且方向已耗尽 | 0 |
| `BLOCKED` | 需你决策；或 Stage A 装置缺陷 | 0（挂起） |
| `SUSPENDED` | 资源/时间耗尽，可原地续跑 | 0（挂起，不算失败） |
| `INSUFFICIENT EVIDENCE` | 证据不足以下状态（058 原生） | 0 |

**永不因"轮数用完/预算用完"报成功。** 资源耗尽 → `SUSPENDED`。

### 3.5 裁决（L2，063 + 058）

1. 对抗批评：对当前领先假说发起攻击（063 "adversarial critic attack the leading hypothesis"）。
2. 按 §3.4 裁一个状态。
3. 写裁决：方向、判据引用、证据路径、被证伪内容、剩余不确定性、下一方向建议。
4. 更新计数器与方向登记表。
5. 选下一个方向：优先**信息价值最高**且**与已完成方向不共享同一未闭合前提**的方向（避免在同一个未证前提上连续踩坑）。

### 3.6 阶段目标

> **"至少 3 个 loop 宣告成功" = 3 个不同方向各自拿到 `COMPLETE`。**

- 只按方向自身判据计数，**不合成跨方向分数**（§1.2）。
- 3 个方向可分处不同层面（数值 / 解析 / 梯度），但每项须独立站得住。
- 达成后仍**不宣称"SGMN 架构通过"**，只宣称"这 3 个具体命题已被确定性验证"，并同步更新 v2.4 证据表。

**台账纪律**（对齐 v2.4 §1 与 §6.2）

6. **写调用计数必须按「前向次数 − 1」记账**（DIR-10 教训）：首个预填没有前驱隐状态，

7. **判据的聚合口径必须对「提前失败」的臂显式声明**（DIR-10 教训）：发散臂的 nan 会污染聚合，

   原 FAIL 留档、不追认（DIR-10 R2/R4 各改判一条）。
8. **联合训练下的对照必须让记忆逐位相同**（DIR-10 教训）：「边写边训」会让读侧变化改写隐状态、
   进而改写写出的 $k,v$，使「有无联合训练」的差异**不可归因**。

9. **端到端的失败必须逐段隔离**（DIR-11 教训）：DIR-11 用 **oracle 注入**（绕过检索、直接注入写阶段捕获的真值）

   ⇒ **只报端到端任务分数会把失败定位错部件**；必须设计**能绕过某一环节**的探针。
10. **装置的【语义】偏差比数值 bug 更危险**（DIR-11 D2）：DIR-04 资产把 $k,v$ 取 batch/序列平均
   ⇒ 一次前视只写 1 个关联，**偏离 v2.4 §2.3 的逐步写入** ⇒ 装置级 Stage A 全过也不能保证**任务级**结论可用。
   ⇒ 卡片必须显式声明「本次测的是哪个写入粒度」。
11. **脚本级替换必须断言命中**（DIR-11 D6）：一处未断言的 `replace` 让「逐位置写」开关根本没生效，
   整组臂与对照组数值逐位相同——**若当时看了「两组数值完全一样」这一异常信号，5 分钟就能发现**。
12. **诊断量必须取自装置的【实际输出路径】**（DIR-12 D7）：脚本里另算了一份"等价"的 $y$（线性读），
   而检索臂实际读出的是竞争混合后的 $\tilde q$ ⇒ 所有臂的诊断值被人为抹平（命中数完全相同）。
   ⇒ **任何诊断量都不得在脚本里重算；装置须把实际输出（`last_y`/`last_q`）暴露出来**。
13. **装置自检必须同时含"应当不变"与"应当变化"两侧**（DIR-12 D8）：A4' 在**写开**状态下查"两次前视记忆不变"
   ⇒ 必然 FAIL（假 FAIL）；反过来若只查"写关时不变"，装置根本没写也会 PASS（假 PASS）。
   ⇒ **两侧缺一不可**。
14. **每个旋钮都必须有"生效性"检查**（DIR-12 D9）：脚本把竞争的锐度传成 0 ⇒ logits≡0 ⇒ softmax 恒均匀
   ⇒ 算子静默退化为"加一个常数向量"，**三臂数值几乎不变却无人察觉**。
   ⇒ 旋钮的默认值与脚本传值不一致时，**必须在 Stage A 断言其生效**（本轮靠 A2' 的双边判据抓到）。
15. **判据的"等价性"要双边化**（DIR-12 D10）："λ=1e-8 与 λ=0 逐位相同"不可达（算子在场会改变算术顺序）；

16. **跨方向复用协议时，先做装置逐位对照探针**（DIR-13 D12）：本轮一度怀疑装置有别，

    （漏掉"每篇文档前重置记忆"）⇒ **协议差异与装置差异必须先分离，再归因**。

    ⇒ **必须同时报告量级**；原判据与原裁决保留不改。

### 6.1 阶段结论（十三个方向合起来的落点）

低秩可塑记忆的「在线写入」在真实模型尺度上，目前**没有既良态、又做功、又良定义寿命的区间**：

| 症状 | 出处 |
|---|---|
| 稳定裕度比全矩阵小 1.7–9.1 倍 | DIR-01 |
| 同内容下仅改规范，$T_{\mathrm{retain}}$ 相差 50× ⇒ 未定义 | DIR-05 |
| 真实尺度上 $\eta_w=0.01$ 即因子范数 inf；写通道段内完全惰性 | DIR-06 |

⇒ **DIR-07 与 DIR-08 两次修正了这条落点**：
**窗口存在**（真实 LLM 实测信噪比 0.764），且 DIR-08 在 1024 个在线步、3 个种子下测得
**写通道确实做功、最优步长 $\eta^\star\approx10^{-5}$**（与 DIR-07 的预测窗口 $[10^{-6},10^{-5}]$ 一致）。
⇒ **DIR-09 第三次修正了这条落点**：写通道在**设备层**确实在学，但在**任务层尚无收益**
（相对随机记忆配对差 −0.000149；读通道相对纯基座净损失 +0.044 nats/token），
且缺失的部分被定位为「**读取侧从未联合训练**（v2.4 §4）」⇒ **这个机制从未在完整形态下被评估过**。
⇒ **DIR-10 第四次修正了这条落点**：把 **§4 的读取侧联合训练**实现后，任务层收益立刻出现且极大
（基座 NLL 2.70746 → **2.46297**，**−0.24449 nats/token / −9.0%**，top-1 **+2.1 点**，
**180/180 篇 valid 文档全为负**，跨 3 种子一致，t=−58.35、符号检验 p=1.25e-12）
⇒ **§7.2「前向任务收益」可以关闭**；
**但同一轮证明了这笔收益与记忆内容无关**（写 vs 不写配对差 **+0.00003**，跨种子变号；
且**不含记忆**的同参数量残差适配器 rank-896 反而更好：2.45703 vs 2.46297）
⇒ **「可塑的关联记忆」这一核心创新，在唯一一次任务级评测中贡献 0**。
⇒ **DIR-11 第四次修正了这条落点**：把「记忆能否被读回来」单独拿出来测（线性读），
结论是**读路径取不回来**——oracle 注入（绕过检索）使随机码 log-prob 提高 **+1.5478 nats**（180/180 正向），
说明**写侧捕获的信息是真的、注入通道是通的**；
而检索在**因子化/全矩阵、随机/对齐、随机 $W^0$/零 $W^0$、块级/逐位置写**六类配置下命中率均
**≤ 0.0093 < 随机基线 1/41=0.0244**；容量界、$W^0$ 噪声、写入粒度三个解释**逐一排除**。
⇒ ⇒ **v2.4 §2.2 自带的 caveat（「共享键空间只是坐标兼容契约……不保证检索有效」）首次获得任务级证据**；
**§7.2「前向任务收益」的重述**：不是「写没做功」，而是「**写做功了但取不出来**」。
⇒ **写入通道本身可行**；剩余障碍全部是**规范、标定与实现**层面的：
① 规范必须固定（否则 $T_{\rm retain}$ 未定义）；② token→在线步映射必须规定；
③ 步长必须按输入尺度与信噪比双重标定；④ **必须给写通道配留出集**（样本内指标会奖励过拟合）；
⑤ 观测/部署视窗必须 $\gtrsim10^3$ 个在线步；
**只有当部署的 $(k\to v)$ 回归信噪比低于 ~0.1 时窗口才为空。**
⑥ **γ 必须固定或归一化**（DIR-10：γ 与 φ 在任务损失下不可辨识，读侧规范自由度）；
⑦ **稳定边界须与协议挂钩**（DIR-10：悬崖在 $\eta\in(5\times10^{-5},7\times10^{-5}]$）；
⑧ **必须给「可塑关联记忆」一个记忆依赖型评测**（DIR-10 N4：否则核心创新至今零收益）；
⑨ **读取侧必须具备检索算子**（DIR-11：线性映射 $y=\mathrm{sg}(W)q$ 在默认映射下无法取回内容）；
⑩ **写入粒度（token→在线步映射）必须进入任务级评测规程**（DIR-11 D2：块级平均写 ≠ v2.4 §2.3 的逐步写）。
⇒ **DIR-12 第五次修正了这条落点**：把读取侧升级为**带竞争的选择性读取**（余弦竞争 + λ 凸组合，λ=0 精确退化为原线性读），
并做了三组干预：**加竞争 / oracle 键（消除 §6.1 自指）/ 随机 $W_q$（对齐性对照）**——
**全部不改变可检索性**（最佳命中 **0.0389 ≈ 随机基线 0.0244**，判据要求 0.9；oracle 键 **不改善**，Q3−Q1 = −0.0093）。
更关键的是**在 DIR-10 的原协议上重测**（写入路径完全相同、**唯一变量是读算子**）：
「写 vs 写关」= **−0.00016**（跨种子 **变号**）⇒ **DIR-10 的头条结论维持**：
联合训练的收益来自**可训练读接口的容量**，与**记忆内容**无关，**换更聪明的读接口也救不回来**。
⇒ 根因由结构诊断（R3）定位：**写入键两两余弦 0.987–0.995，60 个键的有效维度 PR ≈ 1.01**
⇒ **线性 $P_k$ 把 LLM 隐状态的相关性原样带进键空间** ⇒ 记忆只能**求和**不能**索引**
（写保真度 $\cos(Wk_i,v_i)$ 的绝对值 ≤ 0.037 ≈ 0）；且**状态是满秩的**（有效秩 PR 437/646）
⇒ **障碍既不是读接口，也不是秩，而是键的几何** ⇒ **§2.2 的 caveat 再收紧一格**，
**§7.2「写入映射与门控」升格为下一个一等开放项**（键必须能去相关，而线性映射做不到）。
⇒ 于是 ⑨ **修正为**：不是「读取侧必须具备检索算子」，而是「**读取侧不是杠杆；键的构造才是**」；
⑪ **新增**：**写入粒度改变 ⇒ 有效步长必须重标定**（位置级写放大 ~63×：全矩阵 $\eta=10^{-4}$ 时 $\max|W_{full}|=2.6\times10^{7}$ 爆炸）；
⑫ **新增**：**自指不是障碍**（§6.1 的读写耦合在检索上可被 oracle 键消除，且消除后仍不可检索）。

⇒ **DIR-13 第五次修正了这条落点**（在 DIR-12 之后）：把「键的几何」这个退化点**推到极限**做**决定性分离**：

⇒ ★★ **因果链闭合**：**键的几何（已排除）→ 读接口（DIR-12 已排除）→ 障碍是 v2.4 §3.1/§3.2 的写规则本身**

   则「主臂 − 对照臂」的差值**必然 ≈ 0** ⇒ ⇒ 该差值**无法区分**
   「写机制无贡献」与「对照臂本就和主臂等价」⇒ ⇒ **该对照不构成证据**。
   ⇒ ⇒ **归因对照必须与主臂共用同一套「让机制能工作」的配置**（同键几何、同 $\eta$），
   **唯一变量**才是被归因的那一位（此处 = 「核状态 $W$ 是否更新」）。
   ⇒ ⇒ 同时必须报告**机制量**（如写保真度 $\cos(Wk_j,v_j)$），
   以证明主臂里该机制**确实在工作**（否则「差值为 0」与「机制没生效」不可区分）。
   （来源：DIR-18 D46/probe18c —— 线性键 + $\eta=10^{-7}$ 配置下 `nowrite` 与主臂逐位相同）

29. **★ 收益必须用「与目标同分布、可交换」的对照来判定内容性**。若对照 token 取自
   **更稀有/更特殊的子集**（例如「池中最稀有的那几个」），则它在基座上的 NLL **低于**目标本身
   ⇒ ⇒ 对照与目标**不可交换** ⇒ ⇒ 「臂相对基座在目标上的增益」会被**基座先验差异**污染
   ⇒ ⇒ **把先验差异误读成「记忆内容被读出」**。
   ⇒ ⇒ **对照必须与目标来自同一池、同样用均匀抽样抽取**（若目标本身是均匀抽样抽的）、
   **从未被写入**、**跨臂固定**；且必须**同时报告** $\Delta_{\text{code}}$ 与 $\Delta_{\text{ctrl}}$
   ⇒ ⇒ 只有**超额** $\Delta_{\text{code}}-\Delta_{\text{ctrl}}>0$ 才构成「内容性」证据。
   ⇒ ⇒ **只报 $\Delta_{\text{code}}$ 不构成内容证据**（它可能全部是稀有词先验）。
   （来源：DIR-18 probe18d → probe18e —— 主臂 $\Delta_{\text{code}}=+3.167$ 而 $\Delta_{\text{ctrl}}=+3.496$
   ⇒ 超额 **−0.329** ⇒ 「+3.17 nats」**不是**写规则的功劳）

30. **★ 协议修订（尤其「把状态清干净」类修订）不得只看「指标是否更干净」，必须先验证「机制是否仍能工作」**。
   - 典型症状：某个「清理」步骤（清空缓存 / 清空表 / 归零状态）让**指标口径**变好看
     （两口径相等、无残留、无回绕），却让**机制本身**退化（如寻址命中率腰斩）。
   - ⇒ ⇒ **「更干净」不是「更正确」**；**口径一致性与机制可工作性是两个独立的验收维度**，必须同时报告。
   - ⇒ ⇒ 任何协议修订必须**对照修订前后的机制量**（本轮：`addr` 两口径 + `hit`/`addr_slot`）。
   - ⇒ ⇒ 探针必须**逐变量分离**：在**同一份训练好的核状态**上只改协议这一个变量，
     且**评测集固定** ⇒ ⇒ 否则结论会被「训练量」「评测集」等混淆变量污染。
   - ⇒ ⇒ 修订**必须留档**（不得追认），并在卡片里写明「修订前的读数」与「回退理由」。

31. **★ 执行环境的持久性属于实验设计的一部分：沙箱/容器被回收后，重建后的依赖必须可自愈**。
   - 典型症状：后台任务**静默失败**（`ModuleNotFoundError: No module named 'torch'`），
     而日志停在上一轮的正常位置 ⇒ ⇒ 容易被误读为「装置坏了」。
   - ⇒ ⇒ 重建后 **`/usr`（容器层）丢失**、**`/workspace`（NAS/持久卷）保留**
     ⇒ ⇒ **模型、语料、装置、脚本、台账必须全部落在持久卷**；
     **Python 依赖**要么装在持久卷（`--target`/`venv`），要么在启动脚本里**先探测再补装**。
   - ⇒ ⇒ 后台长任务**不得**用 `setsid nohup` 独占（沙箱 idle 回收会杀掉它）⇒ ⇒ 用**平台托管的后台任务**。
   - ⇒ ⇒ 每次后台任务启动**必须先打印依赖自检结果**，否则「静默失败」与「无输出」无法区分。
   （来源：DIR-18 D55 / probe18h —— 清空槽表把寻址命中从 **0.8833 打到 0.3722**）

32. **★ 跨文件的纪律清单必须做「编号连续性 + 双文件对照」审计**，否则冻结报告与活文档会悄悄分叉。
   - 典型症状：纪律 ⑱–㉓ 在**冻结报告**（`LOOP_REPORT_DIR04-DIR17.md`）里齐全，
     而在**活文档**（`LOOP-MECHANISM.md`）里**漏抄了 ㉒/㉓ 两条** ⇒ ⇒ 两份文件**分叉**且**无人察觉**。
   - ⇒ ⇒ 每次新增纪律，必须同时更新「活文档」与「已冻结的阶段报告」两处（或明确声明后者不再维护）。
   - ⇒ ⇒ 审计脚本须检查：**① 编号连续无缺号**（含圆圈编号 ①–㉟ 与平铺编号两种写法）；
     **② 同一条纪律在两份文件里都能搜到**。
   - ⇒ ⇒ **补记须标注「这是补记，不改其余内容」**，不得借补记之名重写既有条目。

33. **★ 跨轮复现必须【逐臂】比对数值，不能只比对主臂**
   - 典型症状：run 1（沙箱被回收）与 run 2（同一脚本、同一 seed）之间，若只比对主臂，
     即使某个**对照臂**存在臂级不确定性也会被漏掉 ⇒ ⇒ 逐位复现的结论会建立在抽样之上。
   - ⇒ ⇒ 复现比对必须覆盖**全部臂 × 全部字段**（`nll` / `hit` / `addr` / `addr_slot` / `fid` / `fid_true`），
     并给出「一致 N/M」的**计数式结论**，而不是「看起来一致」。
   - ⇒ ⇒ 正向价值：全臂逐位一致 ⇒ ⇒ **同一脚本 + 同一 seed ⇒ 完全确定性**
     ⇒ ⇒ 这条本身就是「降级轮可作正式轮交叉验证」的**必要前提**之一。
   - ⇒ ⇒ 同时保留「环境事件未污染结果」的正面留档（纪律 ㉛ 的正面案例）。
   （来源：DIR-18 CPU 降级轮 run 1 → run 2，种子 20261028 **15/15 臂 × 全字段逐位一致**）

34. **★ 「可恢复性机制」本身必须被单独测试**：增量子机制一旦失效**不会产生错误数值，只会浪费时间**
   - 典型症状（DIR-18 缺陷 D56）：`R3_cpu.py` 的**续跑跳过判据**用 `str(seed)` 去查
     `_load_incremental()` 返回的 **int 键** ⇒ **判据永远不命中** ⇒ 续跑会**重算所有已完成臂**
     ⇒ ⇒ **增量落盘 / 断点续跑形同虚设**（本该救命的机制，在真正需要它时是死的）。
   - ⇒ ⇒ **危险点**：确定性 ⇒ 重算得到**相同数值** ⇒ **数值层面完全无污染**
     ⇒ ⇒ **这个缺陷不可能在结果里暴露** ⇒ ⇒ 只能靠**针对该机制本身的最小回归测试**发现。
   - ⇒ ⇒ 每个「可恢复性 / 缓存 / 复用 / 落盘」子机制都必须满足三项：
     **① 一个最小自包含回归测试**（含「修复前失效」与「修复后生效」两侧）；
     **② 运行时的自检断言**（键类型失配 ⇒ **当场崩溃**，而不是静默退化）；
     **③ 缺陷与修复**写进卡片留档，**不追认、不删除**。
   - ⇒ ⇒ 推论：**「我加了一个续跑功能」不等于「续跑能用」** ⇒ 必须**真的重启一次并验证它跳过了**。
   （来源：DIR-18 CPU 降级轮 缺陷 D56 + `.ops/test_d56_resume.py` 8/8 PASS）

35. **★ 判据的「零结果」必须先做「零效度检查」（negative control）**
   - 典型症状（DIR-18 修订 67）：H13（内容性）FAIL，超额 **−0.60 nats**；
     但**按构造必然内容正确**的 `W0_verbatim` 臂（逐字存储、`cos_y_vtrue=0.9998`、`addr_slot=1.0000`）
     的超额也只有 **+0.19（p=0.63）** ⇒ ⇒ **该度量在本次设置下根本没有区分力**。
   - ⇒ ⇒ **FAIL 不能直接读成「机制不存在」**：它只能读成「**度量无效度不足**」。
   - ⇒ ⇒ **规则**：凡是判据给出「零结果」，必须先看一个**按构造具备该性质**的对照臂：
     **① 若该对照臂也测不出效应** ⇒ ⇒ 该判据**无区分力** ⇒ ⇒ FAIL **不得**读成机制层结论，
     必须**换用有区分力的对照**重做判定；
     **② 若该对照臂测出显著效应** ⇒ ⇒ 判据有区分力 ⇒ ⇒ FAIL 可读成机制层结论。
   - ⇒ ⇒ 与既有纪律的关系：⑬（自检要两侧）、㉔（FAIL 先排除任务平凡）、⑰（量级≈0 时符号判据不算数）
     —— 本条补上的是**「度量本身有没有效度」**这一维。
   - ⇒ ⇒ **设计上的推论**：卡片冻结判据时，若某条判据要判定「内容性/特异性」，
     **应当把「按构造具备该性质的臂」预注册为该判据的零效度对照**（本轮是**事后**才补上 ⇒ 记为缺陷）。
   （来源：DIR-18 CPU 降级轮 修订 67 / D57 / D58）

36. **★ 派生代码里的「索引 / 别名 / 原地操作」必须单独测试**（开跑前）
   - 典型症状（DIR-18 缺陷 D62）：消除不动点写成 `p[i], p[j] = p[j], p[i]`，
     而 **torch 的 `p[i]` 是视图** ⇒ 别名 ⇒ **排列被写坏**（实测 335/600 次不再是排列）。
   - ⇒ ⇒ 后果是**静默的**：值会重复/缺失，而结果**看起来仍然合理**。
   - ⇒ ⇒ 规则：凡涉及 **原地写 / 视图 / 张量索引交换** 的逻辑，必须有
     **① 一个独立于装置的最小单元测试**（穷举 + 不动点检查 + 可复现性 + 跨实例固定）；
     **② 测试里保留「缺陷版」并断言它**确实失效**（证明测试有区分力，纪律 ⑬）。
   - ⇒ ⇒ 与纪律 ㉞ 的关系：㉞ 讲「可恢复性机制要单独测」；本条讲「**派生代码的非平凡逻辑要单独测**」。
   （来源：DIR-18 正式轮 `.ops/test_perm_derangement.py`）

37. **★ 增量 / 续跑的产物必须按「方向 + 轮次 + 规格」命名空间隔离，且必须做「跨方向不会互相复用」的测试**（开跑前）
   - 典型症状（DIR-19 缺陷 D78）：派生脚本沿用前序方向的落盘路径
     （`HERE.parent/"R28_results.json"`、`HERE.parent/".ops"/f"formal_incremental_{tag}.json"`），
     而 `HERE.parent` 是**共享**的上级目录 ⇒ ⇒ **DIR-18 与 DIR-19 写同一个文件**。
   - ⇒ ⇒ 后果**静默且致命**：两个方向**有同名臂**（`E5_base` / `E5_base_mem`）⇒ ⇒
     续跑逻辑**静默复用**了另一个方向的行 ⇒ ⇒ 实测 DIR-19 的正式轮复用了 DIR-18 的 `E5_base`
     （nll 15.3260 / 14.9949）⇒ ⇒ **基准臂被跨方向污染 ⇒ 判据读数不可信 ⇒ 整轮作废**。
   - ⇒ ⇒ 规则：① 产物文件名**必须**含方向标识（`DIR19`）与规格标识（`smoke`/`full`）；
     ② 必须做**跨方向复用测试**（同名臂在两个方向各跑一次 ⇒ 断言增量文件**互不相同**且**互不复用**）；
     ③ 派生脚本的**身份标签**（`res["dir"]`）也必须同步改（DIR-19 缺陷 D79：仍是 `"DIR-18"`）。
   - ⇒ ⇒ 与纪律 ㉞ 的关系：㉞ 讲「可恢复性机制要单独测」；本条讲「**可恢复性机制的产物要按方向隔离**」
     —— **「能续跑」与「续跑续对了」是两件事**。
   （来源：DIR-19 正式轮 D78 / D79）

38. **★ 「判据从未被计算」必须与「判据算出 FAIL」严格区分开**（出读数时）
   - 典型症状（DIR-19 缺陷 D82 / D83 / D81）：
     ① H4′ 报「**（无可用旋钮读数）**」⇒ 判据块里把**全局读秩 `R`** 当成臂名用
     ⇒ **每个旋钮都被 `continue` 跳过** ⇒ ⇒ **该判据从未被计算**（与 DIR-18 的 D57 同型）；
     ② 即便修好 ①，`paired(A,B)` 返回 **B−A** ⇒ 判据的符号判反 ⇒ ⇒ **结构上永不可能 PASS**；
     ③ 收尾代码引用未定义的 `passed` ⇒ `NameError` ⇒ **结果 JSON 从未写出**。
   - ⇒ ⇒ 后果：**判据的 PASS/FAIL 状态完全由实现决定**，而读数看起来「像个结论」。
   - ⇒ ⇒ 规则：凡出现「无可用读数」「没有候选」「N/A」这类**空判据**，
     一律**先当实现缺陷处理**；修好后**重算**，并把**修前读数与修后读数同时留档**（失败轮日志不删）；
     **判据的阈值与文字一律不动**。
   - ⇒ ⇒ 配套的自查（本轮新增）：`revolve/DIR-19/.ops/test_static_lint.py`
     —— ① 包装层↔实现层**签名一致**（D80）；② 判据块**无裸 `R` 误用**（D65/D82）；
     ③ 同一条执行路径上 `rec()` 判据名**不重复**（互斥 if/else 兜底豁免）；④ **负向对照**证明有区分力。
   - ⇒ ⇒ 与纪律 ㉟ 的关系：㉟ 管「零结果 ⇒ 先查零效度」；本条管「**空结果 ⇒ 先查是不是根本没算**」。
   （来源：DIR-19 正式轮 D81–D83）

39. **★ 只读 / 评测路径必须冻结写通道**：**被测状态不得被评测改变**（开跑前）
   - 典型症状（DIR-20 缺陷 D84）：评测函数复用了「写 + 读」的组合路径 ⇒ ⇒
     评测过程**自己改了状态**（`core.count` / `write_calls` 会变）⇒ ⇒ **测的是「读+写」的复合效应**，
     而判据说要测的是「**只读**下的可用性」。
   - ⇒ ⇒ 后果**静默**：对照臂与主臂的写历史不同 ⇒ ⇒ 读数差异**无法归因**。
   - ⇒ ⇒ 规则：① 评测必须走**独立的只读入口**（写通道冻结 + 评测前后复原写标志）；
     ② 必须有**装置级检查**断言「评测前后 `count` 与 `write_calls` 不变」（DIR-20 的 A20-9）。
   - ⇒ ⇒ 与纪律 ㉚ 的关系：㉚ 管「协议修订不得只看指标更干净」；本条管「**测量动作本身不得污染被测量**」。
   （来源：DIR-20 D84）

40. **★ 跨边界传递的对象必须显式携带真值索引**：不得依赖「被重建对象的隐式字段」（开跑前）
   - 典型症状（DIR-20 缺陷 D85 / D90）：会话 A 记录了「本篇落在哪个槽」，
     但会话 B **重建**了评测文档 ⇒ ⇒ 文档上**没有**该字段 ⇒ ⇒ 读出阶段 `KeyError`
     （或更糟：用「重建后自算」的索引 ⇒ 与真值**错位** ⇒ 指标口径漂移）。
   - ⇒ ⇒ 规则：① 真值索引 / 身份信息必须**随状态一起搬运**（显式字段 + 精确取值）；
     ② 「同一实体的两份副本」之间的索引映射必须是**逐项精确**的（不是「重新算一遍」）；
     ③ 与此配套：**跨边界保留的对象必须按 (对象, 实例) 索引**，不能按「类别名」索引（D90：
     按臂名索引 ⇒ 第一个实例就把对象取走 ⇒ 后面的实例拿到 `None`）。
   （来源：DIR-20 D85 / D90）

41. **★ 继承的阶段检查会留下显存 / 状态残留**：每轮开始必须**回收并复位**，并**复核基座是否仍被冻结**（开跑前）
   - 典型症状（DIR-20 缺陷 D86）：继承自前序方向的 Stage A 检查结束后，
     **调试张量仍在显存里**、**基座被解冻且未复原** ⇒ ⇒ 本轮首臂直接 OOM（或读数被污染）。
   - ⇒ ⇒ 规则：① 继承检查后必须**释放调试对象 + 清梯度 + 复位可训练性**（DIR-20：删 `_bf0`/`_opt9`、
     重新冻结基座、GC + 清缓存）；② 必须有**一条检查项断言「基座仍被冻结」**（DIR-20 的 A20-0）。

42. **★ 增量 / 缓存产物必须按「方向 + 轮次 + 规格 + **revision**」隔离**（开跑前）
   - 典型症状（DIR-20 缺陷 D93）：协议改了一处（`X8_linear` 的 η）后重跑，
     增量文件**按 (臂, 种子)** 命中 ⇒ ⇒ 复用了**上一 revision** 的行

   - ⇒ ⇒ 规则：① 增量/缓存的文件名必须含**revision 标识**（纪律 #37 的延伸）；
     ② **改了协议就必须换命名空间**（旧文件留档，不得覆盖）；
     ③ 出现「空/异常读数」时，第一件事是查**增量文件里这一行的来源 revision**。
   （来源：DIR-20 D93）

43. **★ 恢复工作区后必须做逐文件 md5 对账**：「工作区里的脚本」可能不是「台账记录的脚本」（恢复后）
   - 典型症状（DIR-20 收尾审计）：从交付包解压回训练机后发现

## DIR-26 追加的四条纪律（2026-11-09）

（v）**"恒定门控"不是"均匀缩放"**（DEF-26-1）：本装置里 $\alpha$ 只缩放数据项，$\lambda$ 项不被缩放

   ⇒ $\alpha$ 变小改变的是 $P$ 的**方向**，不只是幅度。实测 $\mathrm{ret}_1$ 差 **+0.1143**（$r{=}8,N{=}35,R{=}4,\bar\alpha{=}0.664$）。

（viii）**不要用弱化参数做管道检查**（DEF-26-4）：Stage A 早期用探针 $\tau{=}0.25$（跳过率 0.9%）跑 A26-5/6/8，门控覆盖率≈1

## DIR-26-O 新增的两条纪律（2026-11-09；编号 52–53）

52. **★ 独立变量的效应必须逐臂分解；不得只报最显著的那条臂**（DEF-26O-11 的教训来源）：
    DIR-26-O 里，AR(1) 输入对**动力学臂**（`E0`，无条件写）几乎无影响（`ret1` −0.0123 不过 P2、`mu` −0.0017 不过 P2），
