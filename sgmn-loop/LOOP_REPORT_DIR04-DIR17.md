# 第一部分 · 框架与方法

## 1.1 唯一框架来源：v2.4 的结构

本 loop 的每一个方向都必须从 v2.4 §7.2 的具体开放项派生（**不得自造议题**）。为便于对照，下文直接附上 v2.4 的原文锚点。

### 1.1.1 状态对象与逐层数据流（v2.4 §2.1–§2.3）

> **§2.1 符号和状态**
>
> - $l$：Transformer 层索引；$t$：在线事件索引，不与层索引混用。
> - $h_{l,t}$：第 $l$ 层注入前的隐状态；$h_{l,t}^{+}$：注入后的隐状态。
> - $\theta_l$：冻结基座参数；冻结表示不更新参数，不表示删除其对输入的 Jacobian。
> - $W_l^0\in\mathbb{R}^{d_v\times d_k}$：固定的基准关联矩阵，其与具体 LLM 权重的构造关系不在本版敲定。
> - 可塑关联状态为
>   $$W_{l,t}=W_l^0+\Delta W_{l,t},\qquad \Delta W_{l,t}=U_{l,t}V_{l,t}^{\top},$$
>   其中 $U_{l,t}\in\mathbb{R}^{d_v\times r}$、$V_{l,t}\in\mathbb{R}^{d_k\times r}$，故 $\operatorname{rank}(\Delta W_{l,t})\le r$。
> - $\operatorname{sg}(\cdot)$：前向保持原值，反向梯度为零；它不是前向断开，也不消除状态之间的函数依赖。

> **§2.2 基座、读取和注入**（本 loop 最关键、也是最终被证伪的一节）
>
> 先定义读取上下文 $c_{l,t}=\operatorname{sg}(h_{l-1,t})$。为闭合读取上下文与关联矩阵的维度关系，v2.4 将读取器固定为以下最小接口：
> $$q_{l,t}=\mathcal Q_l(c_{l,t};\phi_l^q)\in\mathbb{R}^{d_k},$$
> $$y_{l,t}=\operatorname{sg}(W_{l,t})q_{l,t}\in\mathbb{R}^{d_v},\qquad m_{l,t}=\mathcal O_l(c_{l,t},y_{l,t};\phi_l^o),$$
> $$\boxed{h_{l,t}^{+}=h_{l,t}+\gamma_l m_{l,t}.}$$
>
> …… $q_{l,t}$ 是当前事件的读取查询，$k_{l,t}$ 是写入历史关联的键；二者共享键空间 $\mathbb{R}^{d_k}$，但不要求 $q_{l,t}=k_{l,t}$，也不要求 $\mathcal Q_l=P_{k,l}$。**这里的共享键空间是坐标兼容契约，而非仅要求维度相等；如何通过投影或训练满足该契约仍开放，该契约本身也不保证检索有效。** $y_{l,t}$ 是维度为 $d_v$ 的关联读取结果，$\mathcal O_l$ 将其转化为残差空间输出。**核心读取据此固定为线性关联接口 $y=\operatorname{sg}(W)q$；$\mathcal Q_l,\mathcal O_l$ 的内部结构不指定，更复杂的记忆读取算子不进入本版核心。**

> **§2.3 写入键与目标**
> $$\boxed{k_{l,t}=\operatorname{sg}\!\left(P_{k,l}(h_{l,t-1})\right),\qquad v_{l,t}=\operatorname{sg}\!\left(P_{v,l}(h_{l,t})\right).}$$
>
> …… 这里两者都取注入前隐状态。于是 $k_{l,t}$ 与 $v_{l,t}$ 构成同层相邻在线事件的关联，而不是 $h_{l-1,t}\!\to h_{l,t}$ 的层间关联。

### 1.1.2 写入目标与动力学（v2.4 §3.1–§3.3）

> **§3.1 唯一局部目标**
> $$\ell_{l,t}(W)=\frac{\alpha_{l,t}}{2}\|Wk_{l,t}-v_{l,t}\|^2+\frac{\lambda}{2}\|W-W_l^0\|_F^2,\qquad \lambda>0,$$
> 其中 $\alpha_{l,t}\in[0,1]$ 只门控数据项，并在局部更新中视为 detach 的外生量。其梯度为
> $$G_{l,t}:=\nabla_W\ell_{l,t}=\nabla_{\Delta W}\ell_{l,t}=\alpha_{l,t}(W_{l,t}k_{l,t}-v_{l,t})k_{l,t}^{\top}+\lambda(W_{l,t}-W_l^0).$$
> 该式把"学什么"固定为局部因果关联预测加基准回归，不把最终任务损失隐式并入写入目标。

> **§3.2 全矩阵参考动力学** $W_{l,t+1}=W_{l,t}-\eta G_{l,t}$。
>
> **§3.3 低秩因子动力学**：对 $\Delta W=UV^{\top}$，由链式法则（因子步 + 二阶展开项）。

### 1.1.3 Freeze C：读取梯度、参数所有权与隔离契约（v2.4 §4）

> $$\boxed{\frac{\partial\mathcal L_{\mathrm{task}}}{\partial\gamma_l}=\langle\delta_{l,t}^{+},m_{l,t}\rangle,\qquad \nabla_{\phi_l}\mathcal L_{\mathrm{task}}=\gamma_l\left(\frac{\partial m_{l,t}}{\partial\phi_l}\right)^{\top}\delta_{l,t}^{+}.}$$
>
> …… 读取分支中的 $W_{l,t}$ 被 stop-gradient，因此 $\left.\frac{\partial\mathcal L_{\mathrm{task}}}{\partial W_{l,t}}\right|_{\mathrm{read}}=0$。与此同时，$W_{l,t}$ 的**数值**仍经 $y_{l,t}=\operatorname{sg}(W_{l,t})q_{l,t}$ 参与前向计算。**隔离的目标正是"前向可用、任务梯度不进入写入"，而不是把记忆从计算图中实际移除。**
>
> （§4 参数所有权表）$\theta_l$：任务损失**否** / 局部更新**否**；$\phi_l^q,\phi_l^o,\gamma_l$：任务损失**是** / 局部更新**否**；$U_{l,t},V_{l,t}$：任务损失**否** / 局部更新**是**；$P_{k,l},P_{v,l}$：核心内否 / 否；$\alpha_{l,t}$：核心内否 / 只作为 detach 门控。
>
> …… 还有两个退化点必须保留在架构边界中：
> - $\gamma_l=0$ 时，当前注入对前向输出无影响，且 $\nabla_{\phi_l}\mathcal L_{\mathrm{task}}=0$；
> - **非零梯度、有限梯度和记忆扰动确实改变输出，都不是 stop-gradient 定义本身能够保证的，仍须由 EXP-03 类接口实验验收。**

### 1.1.4 跨层耦合（v2.4 §6.1）

> 梯度隔离只限制反向传播。前向上，第 $j$ 层记忆仍可沿以下路径影响后续状态：
> $$W_{j,t}\longrightarrow y_{j,t}\longrightarrow m_{j,t}\longrightarrow h_{j,t}^{+}\longrightarrow h_{l,t}\ (l>j)\longrightarrow (k_{l,\cdot},v_{l,\cdot})\longrightarrow W_{l,\cdot+1}.$$
> 因此，当前层写入虽然只优化局部目标，其键、目标和有效数据分布仍可能受到前层记忆影响；过去记忆也可能通过时间上下文影响未来写入。$\operatorname{sg}$ 不会消除这些依赖。

### 1.1.5 §7.2 保持开放 —— 本 loop 的方向池

## 2.1 DIR-04 · Freeze C 梯度级接口验收

```python
    def read(self, hs_in, drop_sg=False):
        """c = sg(h_{l-1}^+)；q = Wq c；y = sg(W) q；m = Wo y。逐 token。"""
        self.read_calls += 1
        c = sg(hs_in, drop_sg)                                   # (B,L,d_model)
        cf = c.reshape(-1, c.shape[-1])                          # (N,d_model)
        q = (self.Wq @ cf.T).T                                  # (N,d_k)
        W = (self.W0 + self.U @ self.V.T) if self.use_factorized else self.Wfull
        y = (sg(W, drop_sg) @ q.T).T                             # (N,d_v)
        m = (self.Wo @ y.T).T                                    # (N,d_model)
        self.injection = m.reshape(hs_in.shape)
        return self.injection

    # ------------------------------------------------------------------ 写
    def write(self, hs_in, drop_sg=False):
        """k = sg(P_k h_{l,t-1})；v = sg(P_v h_{l,t})；G = alpha(Wk-v)k^T + lam(W-W^0)；
        同步因子步（或全矩阵参考步）。记忆跨 batch 共享 -> k,v 取 batch 平均。"""
        if self.prev_hs is None or self.no_write:
            return        # 首个时间步无 k_{l,0}（声明条件）；或写入被显式关闭
        self.write_calls += 1
        pf = self.prev_hs.reshape(-1, self.prev_hs.shape[-1])     # (N,d_model)
        hf = hs_in.reshape(-1, hs_in.shape[-1])
        k = (sg(pf @ self.Pk, drop_sg).mean(dim=0)) * self.pk_scale     # (d_k,)
        v = sg(hf @ self.Pv, drop_sg).mean(dim=0)                       # (d_v,)
        W = (self.W0 + self.U @ self.V.T) if self.use_factorized else self.Wfull
        G = self.alpha * torch.outer(W @ k - v, k) + self.lam * (W - self.W0)   # (d_v,d_k)
        # 读取侧注入强度与写门控解耦：alpha 只门控数据项（v2.4 §3.1）
        with torch.no_grad():
            if self.use_factorized:
                self.U.copy_(self.U - self.eta * (G @ self.V))     # 同步：用旧 U、旧 V
                self.V.copy_(self.V - self.eta * (G.T @ self.U))
            else:
                self.Wfull.copy_(self.Wfull - self.eta * G)         # 全矩阵参考：W 本身是可塑状态
        self.steps += 1
```

```python
    def _install(self):
        layers = self._layers()
        for li, mem in self.mems.items():
            layer = layers[li]

            def pre_hook(module, args, kwargs, li=li):
                hs = args[0] if len(args) > 0 else kwargs.get("hidden_states")
                self._hs_in[li] = hs
                return None

            def fwd_hook(module, args, kwargs, output, li=li):
                mem = self.mems[li]
                hs_in = self._hs_in[li]
                hs_out = output[0] if isinstance(output, tuple) else output
                m = mem.read(hs_in, self.drop_sg)          # 读：用 W_t
                hs_out = hs_out + mem.gamma * m             # 注入：h_l^+ = h_l + gamma*m
                mem.write(hs_in, self.drop_sg)              # 写：产生 W_{t+1}
                mem.cache(hs_in)                            # 为下一步准备 h_{l,t}
                if isinstance(output, tuple):
                    return (hs_out,) + tuple(output[1:])
                return hs_out

            self._handles.append(layer.register_forward_pre_hook(pre_hook, with_kwargs=True))
            self._handles.append(layer.register_forward_hook(fwd_hook, with_kwargs=True))
```

## 5.4 ★ §2.2 读取接口的形式完备性分析

#### 5.4.1 v2.4 的接口在**形式上**是完备的

$q=\mathcal Q(c;\phi^q)$、$y=\operatorname{sg}(W)q$、$m=\mathcal O(c,y;\phi^o)$ 三段链条：
- 维度闭合：$c\in\mathbb R^{d_{\rm model}}\to q\in\mathbb R^{d_k}\to y\in\mathbb R^{d_v}\to m\in\mathbb R^{d_{\rm model}}$ ✓；
- 梯度闭合：$\operatorname{sg}$ 截断 $c$ 与 $W$，但**不**截断 $\phi^q,\phi^o,\gamma$ 的参数路径 ✓（D-10 实测）；
- 所有权闭合：§4 的表把 6 类对象的任务/局部更新归属写死，无歧义 ✓。

#### 5.4.2 但它**在能力侧不提供寻址**，而且这不是实现问题

设第 $t$ 次写入使 $Wk_t$ 向 $v_t$ 靠拢。在全矩阵极限下，经过足够多次更新后 $W$ 逼近 v2.4 §5.1 的全矩阵平衡点（岭回归解）

$$W^*=(B+\lambda W^0)(C+\lambda I)^{-1},\qquad B=\mathbb E[vk^\top],\ C=\mathbb E[kk^\top],$$

于是对任意新查询 $q$，

$$W^*q=\sum_t \beta_t(q)\, v_t,\qquad \beta(q)\in\mathbb R^n .$$

★ **关键结构事实**：$y=Wq$ 是**所有历史 $v_t$ 的线性混合**，系数 $\beta$ 由 $q$ 与键 Gram 矩阵决定。**它不是一个「查表返回 $v_i$」的操作。**
- 若键几乎共线（DIR-12 实测：余弦 0.987–0.995、有效槽位 PR ≈ 1.01）⇒ $\beta(q)$ 近乎均匀 ⇒ $Wq\approx\bar v$ ⇒ ★ **记忆只能求和，不能索引**；
- 要让 $\beta$ 有区分力，必须让键 Gram 矩阵条件良好 ⇒ 这正是 DIR-13 的 K4（严格正交，弦 0.0002、有效槽位 245.5）—— **而 K4 的写保真度仍只有 0.0078**。

⇒ ★★ **由此得到本报告最重要的一条形式化结论**：

> **「检索」在 v2.4 的接口里根本不是一个被定义的操作。**
> $y=\operatorname{sg}(W)q$ 只定义了「**用 $q$ 对记忆做一次线性泛函**」；
> 「取回与 $q$ 对应的那一条 $v_t$」需要的是一个**选择算子**（argmax / 竞争 / 内容寻址），
> **而 v2.4 §2.2 明文规定「更复杂的记忆读取算子不进入本版核心」。**
> ⇒ ⇒ 所以 DIR-11…DIR-14 证伪的不是「实现得不好」，而是 **v2.4 选定的核心接口里根本没有检索算子**。

#### 5.4.3 为什么 DIR-15 的内容寻址是**真正的修复**而不是「调参」

DIR-15/16 的做法：**地址不再由 $W$ 承担，而由一个与写侧共享的「原始量」承担** —— 写入时把 $h_{t-1}$ 存进旁表 `sigs`，读取时用**同一个量**去匹配，取出对应条目的键再交给 $W$ 读。

```python
    def _cue_match(self, hs_in):
        """线索匹配：读侧的**地址**与写入时记录的地址比较（余弦），返回 (best_idx, scores)。
        【D29】读侧地址取 `hs_in[0][L-1]`（**最后一位**）——与写侧约定对齐：
        写侧在事实首 token 位置 t 写入时，记的签名是 $h_{t-1}$（**事实首 token 的前一位**）；
        读阶段前缀的最后一位正是「事实首 token 的前一位」⇒ 两侧取同一个量。
        """
        core = self.core
        n = min(core.count, core.N)
        if n == 0:
            return None, None
        L = hs_in.shape[1]
        h_last = hs_in[0, L - 1].detach()                       # 【D29】读侧地址的取位
        if self.addr_mode == "key":
            addr_q = (self.Pk.detach() @ h_last)
            stored = core.keys[:n].detach()
        else:
            addr_q = h_last
            stored = core.sigs[:n]
        sc = stored @ addr_q
        sc = sc / (stored.norm(dim=1) * addr_q.norm()).clamp_min(1e-30)
        return int(torch.argmax(sc).item()), sc
```

⇒ 匹配成功后，$q$ 直接取被选中条目的**键**（`self.core.keys[j].detach()`），
   再由 $W$ 完成「键 → 值」的线性读取 ⇒ ★ **选择算子被显式地、单独地、可验收地加进来了**。

⇒ ★★★ **这正是 v2.4 §2.2 缺失的那一层**，而且加进来的方式完全遵守 v2.4 的其余约束：
- 不改 $W=W^0+UV^\top$ 的状态形式；
- 不改 §3.1 的写目标；
- 不改 §4 的梯度隔离（`keys` 被 `detach()`，见 D21）；
- 只在 §7.2 明列开放的「**$\mathcal Q_l,\mathcal O_l$ 的内部结构、参数共享及查询坐标对齐方式**」这一格里动刀。

⇒ ⇒ **可寻址性契约的正式写法（可验收条款）**：
> 读取命中率的验收条款 = 「在**跨措辞 / 跨上下文 / 跨干扰**三种扰动下，对同一原始量做地址匹配，
> 命中率 ≥ 0.97，且阴性对照（地址取键、v2.4 现状读取）≤ 0.01」——
> 这是 DIR-16 实测（C1 1.0000 / C2 0.9981 / C3 0.9981 / C4 0.9741；C5 0.0019 / C6 0.0037）给出的**可验收数字**。

#### 5.5.1b v2.4 §5.1 的原文（供对照）

> 由 $\nabla_WJ=WC-B+\lambda(W-W^0)=0$，全矩阵平衡点为
> $$\boxed{W^*=(B+\lambda W^0)(C+\lambda I)^{-1}.}$$
> 令
> $$\bar M=W^*-W^0=(B-W^0C)(C+\lambda I)^{-1},\qquad R=(C+\lambda I)^{1/2}.$$
> 由于 $\lambda>0$，$R$ 可逆。忽略与 $\Delta W$ 无关的常数，
> $$J(W^0+\Delta W)=\frac12\|(\Delta W-\bar M)R\|_F^2+\text{const}.$$
> …… **该损失只是局部二次目标的空间容量代价，不能直接换算成语言任务性能损失；$M_r^*$ 是秩约束最优解，也不等于因子化在线动力学必然到达的平衡点。**

⇒ ★ 注意最后一句：**v2.4 自己已经声明「秩约束最优解 ≠ 动力学平衡点」**。DIR-13/14 的负面结果属于**后者**（实际动力学到达的 $W$ 的逐条保真度），与 §5.1 的解析最优解**不矛盾** —— 这正是 §5 的数学纪律在保护 v2.4。

#### 5.5.2 由事实导出的机制假设（**待检验，本 loop 未测**）

★ **假设 H-write（待检验）**：写保真度低**不是**键几何造成的，而是
**(a) 状态秩 $r=8$ 相对同时驻留的关联条数 $n\approx40$ 严重不足**（秩截断必然丢失大部分逐条关联），
与 **(b) 岭回归解把逐条残差平均掉**（回归目标是最小化平均误差，不是逐条命中）。

⇒ 这条假设**可证伪且有明确判据**：
- 若 (a) 为主因 ⇒ 把 $r$ 提高到 $\ge n$（或分块写入、按块释放槽位）应显著提高写保真度；
- 若 (b) 为主因 ⇒ 固定 $r$ 但把 $\lambda\to0$、并让**同一键**重复写入多次（相当于把回归变成赋值）应显著提高写保真度；
- 若两者都不成立 ⇒ 说明 $v_t=\operatorname{sg}(P_v h_t)$ 与 $k_t=\operatorname{sg}(P_k h_{t-1})$ 之间**本身不存在可学的逐条对应**（即 §2.3 的时间因果配对不是「事实-码」的对应）⇒ ★ **那才是真正的根本障碍**。

⇒ ★ 这个假设把 DIR-13 的「决定性分离」再往前推了一步：DIR-13 排除了**键几何**，DIR-14 排除了**记忆结构**，但**还没有排除「状态秩 + 回归目标」这一层**。⇒ 这是下一方向 DIR-18 的第一候选（见 §6.2）。

#### 5.5.3 完备性判定

⇒ ★ **Freeze B 的数学是对的（§3.1/§3.2/§3.3 全部成立且被量化），但它的「语义」是错的**：
它定义的是**「学习一个从上下文到下一状态增量的线性关联模型」**，
而不是**「记住 $n$ 条可分别取回的事实」**。
⇒ 这两件事在 $r\ll n$、值互不相关、键接近共线时**不等价**，而 v2.4 的叙述把两者当成了同一件事。
⇒ ⇒ **v2.4 需要一个新的冻结项：把「关联学习」与「逐条可寻址存储」在规范上分开，并声明本版只做前者。**

## 5.6 ★ §4 训练协议的完备性分析：可训练读接口 ≠ 可塑记忆

#### 5.6.1 实测的归属分解（DIR-10，同一协议同一评测）

#### 5.6.2 这不是 bug，而是 §4 的**内在张力**的形式化

⇒ ⇒ ★★ **因此，在 v2.4 的训练协议下，「前向任务收益」原则上只能来自读接口的形状，不可能来自记忆的内容。**

## 6.2 DIR-18 · 写规则的可寻址性重设计 ★ 最高价值的下一方向

**source**：v2.4 §3.1 / §3.2 / §3.3（**第二次动 Freeze B**）+ §7.2「写入映射与门控」+ §7.2「数值与结构选择」（$r$、槽位数）；DIR-14 的 D-20 与 DIR-13 的 D-19。

③ 若二者都不是 ⇒ $k_t=\operatorname{sg}(P_k h_{t-1})$ 与 $v_t=\operatorname{sg}(P_v h_{t-1})$ 之间**本身不存在可学的逐条对应**。

| 臂 | 写规则 | 检验的机制 |
|---|---|---|

## 6.3 DIR-19 · 可学习地址（$P_k$ 的离线学习）

**source**：v2.4 §4 表：「$P_k,P_v$ —— 核心内否 / 否 —— **视为给定写入映射；固定或离线学习的选择仍开放**」；§7.2「写入映射与门控」。

**要验证的**：DIR-15/16 的「同一性」条件目前依赖**手工约定**（读侧取 `hs_in[0][L-1]`，写侧取 $h_{t-1}$）。★ 这个约定**能对齐靠的是构造，而不是原理** ⇒ 换一种任务构造（不同粒度、多事实、乱序上下文）就可能失效。⇒ 能否让地址本身被**离线学习**，使得「可寻址性」不依赖人工对齐？

**mvp_gate**：用**无标签**的旁任务离线训练一个地址投影 $A_\psi:\mathbb R^{d_{\rm model}}\to\mathbb R^{d_{\rm addr}}$，使「同一位置/同一事实的两次观测」靠近、「不同事实」远离（对比学习），再把 $A_\psi$ 用作地址；**唯一变量 = 地址是否学习**。

**判据草案**：H1 学习地址在 DIR-16 的 C2/C3/C4 三种扰动上**不低于**手写地址（0.9981/0.9981/0.9741）；H2 在**新的构造**（跨粒度、跨位置、多事实）上手写地址**退化**而学习地址不退化（这才是价值所在）；H3 阴性对照（随机地址）命中 ≤ 0.01。

**Stage A 草案**：A1' 冻结基座不变；A2' **离线训练不泄漏到评测**（地址投影的更新与主装置解耦）；A3' 跨方向逐位对照（DIR-16 的 C1 = 1.0000 必须复现）。

**风险**：★ 这是**第一个会把「训练引入装置」的目录**，必须严守 §4 的所有权表（地址投影属于写入映射 ⇒ 属 $P_k$ 一类 ⇒ **核心内否 / 只在离线学**）⇒ 一旦把地址投影放进任务训练，就会触发 §4 末段警告的「任务目标影响未来写入数据」的外层通道 ⇒ **必须先与 §7.2「受保护联合训练」合并考虑**（见 DIR-20）。

## 6.4 DIR-20 · 受保护联合训练的定义与首测

**source**：v2.4 §7.2「持久化与 LLM 协同 → **受保护联合训练**」；§4 表（$P_k,P_v$ 核心内否、$\alpha$ 外生）；§4 末段「若以后让任务损失训练写入投影或写入门控，就会引入"任务目标影响未来写入数据"的外层通道。那将是新的耦合系统，**不能在未重新分析的情况下继续沿用本版的独立局部动力学结论**」。

**要验证的**：① 「受保护」到底保护什么（写侧参数？写侧目标？写侧数据分布？）；② 联合训练下 §5 的平衡点/稳态结论**在什么条件下**还成立。

### A.1 显式键值核 `ExplicitKVCore`（DIR-15 引入，DIR-16/17 沿用）

```python
class ExplicitKVCore:
    """显式键-值分离：N 对 (k_i, v_i)；写轮转追加；读按 softmax(β cos(q,k_i)) 加权。"""

    kind = "explicit_kv"

    def __init__(self, d_k, d_v, alpha, lam, eta, gen, device, n_entries=64, d_model_sig=0):
        self.d_k, self.d_v = d_k, d_v
        self.alpha, self.lam, self.eta = alpha, lam, eta
        self.N = n_entries
        self.keys = torch.zeros(n_entries, d_k, device=device).requires_grad_(True)
        self.vals = torch.zeros(n_entries, d_v, device=device).requires_grad_(True)
        # 【DIR-15 新增】上下文签名旁表：第 i 条关联写入时的上下文签名 h_{t-1}（与键 k 的**同一**输入）。
        # 用途：以「地址（写侧上下文）」而不是「键的线性投影」来匹配查询 ⇒ 内容寻址式读取。
        self.sigs = torch.zeros(n_entries, d_model_sig, device=device)
        self.count = 0
        self.last_delta = 0.0

    def write(self, k, v, sig=None):
        with torch.no_grad():
            i = self.count % self.N
            self.count += 1
            self.last_delta = float((k.norm() ** 2 + v.norm() ** 2) ** 0.5)
            self.keys[i].copy_(k)
            self.vals[i].copy_(v)
            if sig is not None:
                self.sigs[i].copy_(sig)

    def read(self, q, beta=16.0, drop_sg=False):
        # 【D21】键是**写侧量**（§2.3 的 k = sg(P_k h)）⇒ 必须从计算图里摘出，
        #   否则「写侧原地更新 keys」会破坏跨越该前向的反向传播（version counter），
        #   且正常的 (sg) 模式下写侧参数会拿到梯度 ⇒ 违反 Freeze C。
        #   值同理：正常模式 detach，阴性对照 (drop_sg=True) 保留克隆 ⇒ 泄漏可被检出。
        K = self.keys.detach()
        s = (q @ K.T)
        s = s / (q.norm(dim=1, keepdim=True) * K.norm(dim=1).unsqueeze(0)).clamp_min(1e-30)
        a = torch.softmax(beta * s, dim=-1)
        return a @ (self.vals.clone() if drop_sg else self.vals.detach().clone())
```

```python
    def write(self, hs_in, drop_sg=False):
        """位置级写（v2.4 §2.3/§3.1/§3.2 的逐步语义）：t=1..L-1 逐位置写入。"""
        if self.no_write:
            return
        if hs_in.shape[0] != 1 or not self.perpos:
            raise RuntimeError("DIR-14 装置只实现位置级写（B=1）")
        L = hs_in.shape[1]
        if L < 2:
            return
        with torch.no_grad():
            for t in range(1, L):
                k = sg(hs_in[0, t - 1].reshape(1, -1) @ self.Pk, drop_sg).mean(dim=0)
                if self.key_mode == "sparse":
                    thr = k.abs().topk(self.key_topk).values[-1]
                    k = k * (k.abs() >= thr).to(k.dtype)
                k = k * self.pk_scale
                v = sg(hs_in[0, t].reshape(1, -1) @ self.Pv, drop_sg).mean(dim=0)
                self.keys_written.append(k.detach().clone())
                self.vals_written.append(v.detach().clone())
                sig = hs_in[0, t - 1].detach()                    # 【DIR-15】上下文签名（键的同一输入）
                if hasattr(self.core, "sigs"):
                    self.core.write(k, v, sig=sig)
                else:
                    self.core.write(k, v)
                self.write_calls += 1
                self.steps += 1
```
