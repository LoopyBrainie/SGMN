## 1. 本方向的问题（主假说）

> **主假说 H**：v2.4 §7.2 的「跨会话状态语义」可以被定义为一个**可测量的边界**：
> **(a)** 记忆的**状态**（核状态 + 地址表 + 读出映射）可以跨会话搬运，并在**全新加载的模型实例**上继续产生任务收益；
> **(b)** 跨会话后的收益**仍由记忆内容驱动**（内容特异），而**不是**「搬来一个更强的模型」；
> **(c)** 跨会话的收益折损**有界**，且**可事先声明**；
> **(d)** 跨会话的可用性**依赖具体的机制成分**（哪些状态必须搬运），**不是**「搬一切就行」。

### 1.1 三条会被判据直接推翻的可能

- **H 的不可能版**：状态**不可**跨会话搬运（模型实例一换，记忆即失效）⇒ H 被证伪为「跨会话语义不可行」。
- **H 的平凡版**：跨会话的收益**不来自**本会话写入的信息（随便搬一个状态都有收益）⇒ H 被证伪为「搬的是模型，不是记忆」。
- **H 的非内容版**：跨会话后**内容不再驱动输出**（收益来自通用能力或稀有词先验）⇒ H 被证伪为「跨会话记忆」名不副实。

## 2. ★ 装置与协议（本方向的核心）

### 2.1 「跨会话」的确切定义（**唯一**差别）

| | 同会话（DIR-15…DIR-19） | **跨会话（本方向）** |
|---|---|---|
| 模型实例 | 训练与评测**同一个** `model` 对象 | ★ 会话 B **重新 `from_pretrained` 加载**（⇒ **隐状态历史清零**） |
| 记忆状态 | 进程内 `snapshot_all` / `restore_all` | ★ **`export_state()` → 磁盘字节流 → `import_state()`** |
| 评测时的写阶段 | 评测前 `write_both`（协议的一部分） | ★ **不写**（会话已结束，记忆是**冻结**的）⇒ ⇒ **只读** |

⇒ ⇒ ★ **唯一**变量是「模型实例是否被重建 + 状态是否经由磁盘搬运」⇒ ⇒ 其它一切口径（任务、指标、写配置）**逐字沿用 DIR-19**。

### 2.2 两段式协议

```
【会话 A】(seed = 文档种子)
  1. 建装置（写配置 = 该臂的 key_mode；η=1e-1；mem_kind = hebbian_full 或 explicit_kv）
  2. 对 **N 篇**文档做写阶段 + 读侧训练（Wo/γ；Adam(lr=1e-3)）—— 与 DIR-19 的 N1_frozen_base 同口径
     ★ 这 N 篇**包含**会话 B 将要评测的 E 篇（否则 B 无从评测）
  3. export_state(...) → torch.save 到 .ops/state/{arm}_{seed}.pt
     ⇒ 记录：**文件 md5** + **内容指纹** `state_fingerprint()`
  4. 释放装置、释放模型

【会话 B】(★ 全新模型实例)
  5. model = from_pretrained(...)   ← ★ **重建** ⇒ 隐状态历史清零
  6. 建装置 → import_state(state, strict=True)
  7. ★ **只读**评测：**不写、不训练** ⇒ 直接读出并算 NLL / hit / addr_slot / fid …
```

### 2.3 ★ 为什么「键尺度归一」在跨会话下**可能**特别重要（可检验的机制假说）

读侧的寻址用 **上下文签名**与存储的 `keys` 做匹配 ⇒ ⇒ 会话 B 的 `hidden state` 与会话 A 的**分布不同**
⇒ ⇒ 若键的范数随实例/上下文漂移 ⇒ ⇒ 匹配会失准 ⇒ ⇒ **逐写归一化到固定范数（Freeze B 待补条款）**
⇒ ⇒ **应当让跨会话的匹配对尺度不敏感** ⇒ ⇒ ⇒ **H4″ 正是检验这一点的关键判据**。

## 4. ★ 冻结判据（**7 条**，阈值与文字**一字不改**）

| 编号 | 判据 | 阈值 | 备注 |
|---|---|---|---|
| **H1″** | **跨会话可用**：会话 B 导入状态后，相对**不导入状态**有显著收益 | Δ(Δnll) > **0.5 nats**，p < 0.05，**三种子同向** | 参照臂 = `X11_newinst_noexport`（★ 同一「新实例」，唯一差别是**有没有状态**） |
| **H2″** | **★ 内容特异（记忆内）**：`X1_full_state` 显著优于 `X4_content_wrong` | Δ(Δnll) > **0.5 nats**，p < 0.05，三种子同向 | 两臂**只差「值」**（地址不动）⇒ ⇒ 天然无零效度问题 |
| **H3″** | **★ 跨会话折损有界**：`X1_full_state` 相对 `X10_same_session` 的收益折损 ≤ **事先声明的界** | 界 = **1.0 nats** | ★ 直接给出「跨会话要付多少代价」的可写条款 |
| **H4″** | **★ 键尺度归一 ⇒ 跨会话寻址稳定**：归一化配置（`ortho`/`renorm`）的跨会话收益**显著高于**原尺度（`linear`） | Δ(Δnll) > **0.5 nats**，p < 0.05，三种子同向 | ★ 直接检验 Freeze B 条款在**跨会话**下的后果 |
| **H5″** | **★ 会话归属**：`X1_full_state` 显著优于 `X5_wrong_session` | Δ(Δnll) > **0.5 nats**，p < 0.05，三种子同向 | ⇒ ⇒ 收益归因于**本会话写入的信息** |
| **H6″** | **★ 零效度门槛**：`X6_verbatim`（按构造内容正确）的跨会话收益**显著 > 0** | Δ(Δnll) > **0.5 nats**，p < 0.05 | ⇒ ⇒ 度量有区分力 |
| **H7″** | **状态成分的必要性**：**至少一个**成分缺失（`X2_no_readmap` / `X3_no_addr`）会**显著降低**跨会话收益 | 至少一条：Δ(Δnll) > **0.5 nats**（缺失臂相对主臂**更差**） | ⇒ ⇒ 「跨会话要搬哪些东西」的可写条款 |

### 4.1 ★ 证伪条件（写死在卡片里）

- **H1″ FAIL** ⇒ 「状态**不可**跨会话搬运」⇒ ⇒ v2.4 §7.2 的「跨会话状态语义」子项应写成「**不可行**」。
- **H2″ FAIL** ⇒ 跨会话后**内容不再驱动输出** ⇒ ⇒ 该子项降级为「跨会话的通用能力提升」，**不是记忆**。
- **H5″ FAIL** ⇒ 收益**不来自**本会话写入的信息 ⇒ ⇒ 「搬的是模型，不是记忆」⇒ ⇒ 该子项不成立。
- **H4″ FAIL** ⇒ 键尺度归一对跨会话**没有**额外作用 ⇒ ⇒ **不得**把 Freeze B 的「键必须逐写归一化」**扩展**到跨会话语义。
- **H3″ FAIL** ⇒ 跨会话的折损**超过事先声明的界** ⇒ ⇒ 「跨会话」在任务层**不可接受** ⇒ ⇒ 该子项只能写成「有代价」。
